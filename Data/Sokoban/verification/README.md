# 推箱子候选关卡验证

2026-10-28，在固定的 Boxoban `unfiltered/test/000.txt` 源数据上进行了离线搜索和逐格重放。此目录是设计阶段的内容准备材料，不是 Unity 生产规则实现，也不是已经发布或完成真人难度评级的关卡集。

## 已获得的证据

- 1,000 个源关卡通过结构校验：源 ID 为 0..999，10×10、一个人物、四箱四目标、合法字符、外圈封闭。
- 按源顺序尝试源 ID 0..103，共 104 关；其中 100 关找到完整解法并通过独立逐格合法移动重放。
- 源 ID **21、46、65、78** 达到本次每关 1.5 秒的时间预算，记录为 `budget_exceeded`，没有将它们判定为无解。
- 已保存候选的完整走法长度为 15..125 步，推动数为 4..22；这些数值只描述本次见证解，不代表全局最短步数或真人难度。
- 本次完整搜索运行约 25.157 秒；重新搜索的时间及入选集合可能因机器负载发生变化，已保存见证的逐格重放结果应保持确定。
- 重放额外检查了空解法、非法方向字符及撞边界走法，均被拒绝。

## 复现

在仓库根目录运行：

```bash
# 快速、确定地重放已经保存的全部见证，同时核对原始文件哈希及全部源关卡结构。
python3 Data/Sokoban/verification/verify_boxoban.py --replay-only

# 重新从源顺序搜索并覆盖本目录的候选和报告。
python3 Data/Sokoban/verification/verify_boxoban.py --count 100 --max-states 35000 --max-seconds 1.5
```

搜索采用箱子推动状态的广度优先遍历，并将同一箱子布局下玩家的可达区域归一化；反向拉箱可达性仅用于剔除确定的静态死格。每条推动边同时保存人物走至推动位置的合法路径。另一个独立的二维逐格函数从源地图重新执行完整走法，检查越界、撞墙、连续推两箱以及最终四箱全部到位；该函数不调用搜索的邻接、可达性或状态更新工具。

## 交付边界

这 100 关可以作为后续正式关卡集的**已证明可解候选池**，尚未确定教学顺序、章节与难度。源 ID 104..999 没有在本次运行中搜索。4 个超预算关卡仍保留在完整源档，不删除或改写。

后续将候选导入 Unity 时，必须再使用真实 C# 生产规则重放同一批见证；Python 的通过不能代替该检查。Unity 渲染、动画、触摸、生命周期、存档与 Android 真机均不在本次验证范围内。
