# 数字华容道玩法与接入

数字华容道是当前源码大厅中的第十三款离线游戏，稳定标识为 `sliding-puzzle`。玩家利用一个空格移动数字，将棋盘按从左到右、从上到下的顺序还原，空格最终留在右下角。页面提供「自由拼图」与「解锁闯关」，默认自由模式为 4×4。

本文说明现行源码的规则、UI 和存档契约。本轮实际检查、原稿对比和 Android 运行证据见[验证记录](verification-sliding-puzzle.md)。

## 模式与固定内容

| 模式 | 内容与续局 |
| --- | --- |
| 自由拼图 | 可选 3×3、4×4、5×5，三个尺寸各保存一局。切尺寸或切模式保留原局；「重玩这题」恢复原初局，「换一题」仅替换当前尺寸的题目。 |
| 解锁闯关 | 三章各六题，共 18 题。第一章 3×3，第二章 4×4，第三章 5×5。首次只有第一题解锁，完成当前题才解锁下一题；完成整章后可进入下一章。已通关题可以重玩。 |

闯关只保留一个活动对局。切去自由模式再返回可继续该局；进入另一道已解锁题会替换原闯关对局，已完成进度及纪录保留。选关页按章节展示已完成数量，题卡区分「开始挑战」「继续挑战」「已通关」与「未解锁」，大厅展示真实的已完成题数。

题库由 `SlidingPuzzleCatalog` 嵌入固定数组，题号稳定，`ContentVersion` 为 `1`。第一题初局为：

```text
1  2  3
4  ·  5
7  8  6
```

依次移动数字 5、6 即完成，最优为两步。第一章六题的最优步数为 **2、4、6、8、12、16**，由测试中的独立 BFS 遍历 181,440 个可解 3 阶局面证明。4／5 阶的十二题保存了可重放的合法解法，仅据此保证可解，不声称见证长度就是最优步数。

自由题使用自定义确定性 PRNG，从完成局面进行合法交换，再排除完成状态；相同尺寸与 seed 生成相同初局。运行时给新题选择 seed，存档直接保存初始排列，因此续局不依赖再次生成。打乱次数不用于标注难度，也不提供运行时自动求解。

## 移动、计步与练习

点击与空格上下左右相邻的数字，或按住该数字向空格方向滑动，都会只交换这一块数字与空格。斜向、不相邻、跨行边界、空格及无效输入不移动，也不计步；没有整行推动或数字合并。已经位于正确位置的数字仍然可以移动，棋盘中的数字块使用一致样式。

每次合法移动增加一步。撤回将盘面恢复为上一次移动之前的状态，同时再增加一步，并将整局标记为「练习」；即使之后回到初始盘面，练习标记也保留。连续撤回受当前历史长度限制，不能撤回到初始局面之前。重玩或换题才会清零本局步数、用时与练习标记。

完成排列后立即停止接受移动和撤回，完成动画后展示结果。闯关结果提供下一关；最后一题提供返回选关。自由模式提供再来一局，也可以关闭结果查看已完成棋盘。结果文案依据真实完成状态，不把完成一次自动称作打破纪录。

练习局完成闯关仍然解锁后续题目，但不会写入个人最佳纪录。普通胜局按自由尺寸或闯关题号分别维护两个真实成绩元组：

| 指标 | 比较规则 |
| --- | --- |
| 最少步数 | 先比较步数，步数相同再比较用时；保存该次成绩的完整 `(步数, 用时)`。 |
| 最快用时 | 先比较用时，用时相同再比较步数；同样保存该次完整成绩。 |

两个元组可以来自不同胜局，不把一次的最少步数与另一次的最短时间拼成不存在的成绩。保存、切换模式或恢复已完成局面不会重复结算。

## 计时、暂停与页面

首次有效移动之前显示 `00:00`，进入页面、查看规则或点击无效数字均不启动计时。之后仅在当前对局处于前台、未被弹窗或宿主界面阻挡且尚未完成时累计时间。打开玩法说明、设置、重开确认，返回选关、离开游戏、切后台或失焦都会暂停；恢复可交互状态后继续，不补算离线时间。页面在每次前后台回调重新建立单调时钟基准，排除 Android 恢复首帧可能携带的后台间隔。移动后撤回到初始盘面仍属于已经开始的对局。

页面沿用合集的纸色背景、绿色层次、公共字体和 Home／Book／Settings 导航。自由与闯关共用模式切换条；游戏页以两张信息卡显示用时和步数，下方是完整棋盘与撤回、重开操作。使用过撤回时步数标题显示「练习」。玩法弹窗显示当前尺寸的目标排列，清楚说明空格目标与单块移动规则。

页面与手势层在弹窗、切页、切后台、尺寸重排时取消未提交的按压，并将动画收敛到规则已经提交的盘面。点击和滑动共用一次 pointer-up 提交，避免一次手势重复移动；多指与取消手势不提交操作。

游戏没有倒计时失败或目标步数限制。为避免操作历史和存档无界增长，每局累计移动与撤回合计最多 **100,000 次**；达到时保留全部当前移动历史，停止继续操作，页面明确提示「操作记录已达安全上限，请重玩或换一题」。存储用时另有 315,576,000 秒的数值饱和保护，约十年，不触发胜负。

## 模块归属

| 模块 | 职责 |
| --- | --- |
| `Core/SlidingPuzzle/SlidingPuzzleGame` | 棋盘、可解性校验、相邻交换、计步、撤回和终局；对外数组采用防御复制。 |
| `SlidingPuzzleGenerator` / `SlidingPuzzleCatalog` | 自由题生成与固定内容，独立于 Unity 呈现。 |
| `SlidingPuzzleSession` | 本局用时、活动／前台／阻挡门禁、结果是否已经记账。 |
| `SlidingPuzzleProfile` | 三个自由槽、一个闯关槽、当前选择、连续完成进度及两类纪录。 |
| `SlidingPuzzlePage` / `SlidingPuzzlePointer` / `SlidingPuzzleBoardView` | 页面、弹窗、输入仲裁、棋盘绘制和可取消动画；不另行计算规则。 |
| `SlidingPuzzleSaveCodec` / `SlidingPuzzleSaveStore` | 严格数据边界、文件读写、备份和恢复。 |
| `AppController` | 第十三张大厅卡片、路由、公共设置和应用生命周期分发。 |

规则代码位于 `Assets/Scripts/Core/SlidingPuzzle/`，会话、存档和页面代码位于 `Assets/Scripts/Runtime/SlidingPuzzle/`。声音和触感通过宿主委托使用共用设置，不引入新的网络或服务依赖。

## 独立存档

保存位置为 `Application.persistentDataPath/sliding-puzzle-v1.json`，对应备份与临时文件为 `.bak`、`.tmp`。根协议固定为 `schemaVersion: 1`、`saveKind: "sliding-puzzle"`、`contentVersion: "1"`，不修改其他游戏或公共设置的协议，也不导入其他游戏存档。

根数据保存选中模式、自由尺寸、章节、三个自由槽、一个闯关槽、连续已完成题号和各尺寸／题目的纪录。每个存在的槽保存初始盘面、当前盘面、当前未撤回的 tile-value 历史、总步数、撤回次数、用时和结果记账标记；不保存触点、动画进度或临时弹窗。

`History` 表示当前盘面仍保留的移动轨迹，撤回会移除其末项并增加 `UndoCount`。固定关系为：

```text
Moves = History.Length + 2 × UndoCount
Assisted = UndoCount > 0
```

恢复时从 `InitialCells` 逐条重放 `History`，严格校验每一步相邻交换、不能在胜利后继续、重放结果必须等于 `Cells`。闯关初局必须与对应固定题一致；完成题号必须为从零开始的连续前缀。胜利标记由盘面推导，存档中的结果记账必须与其一致；普通胜局必须已经被纪录包含，练习胜局可以没有纪录。

编码和解码都执行完整校验。缺失、未知或重复字段，显式 null（允许为空的槽及纪录项除外）、错误 token 类型、非有限数、非法排列、不可解棋盘、假历史、未来版本与不一致纪录均被拒绝，不静默补成合法状态。文件最大 2 MiB，JSON 深度最大 12，四槽均受每局 100,000 次操作边界约束；不会截断历史来满足长度限制。

有效操作、模式／尺寸／题目切换、进入弹窗、后台及离开时保存，已开始的进行局另定期尝试写盘。写入先将临时文件刷盘，再原子替换主档；只有通过校验的旧主档才会成为备份。读取优先主档，再尝试有效备份；损坏文件归档保留。保存失败保留当前内存对局，页面显示未保存提示，后续保存成功后清除。

## 检查与构建入口

从当前工作树根目录执行：

```bash
scripts/test-sliding-puzzle.sh
scripts/test-sliding-puzzle-persistence.sh
```

这两个入口以 C# 7.3 编译生产源码，在 .NET 10 运行规则、题库、会话和存档检查；持久化使用实际 Newtonsoft.Json 13.0.2 与真实临时目录。覆盖相邻交换、奇偶可解性、撤回计步、终局、快照防御复制、非法历史、全题解法重放、第一章 BFS、计时门禁、连续解锁、双纪录元组、四槽最长历史、严格 JSON 及备份恢复。

Unity UI 与独立 Android 包另有入口，需在同一工作树中串行执行：

```bash
scripts/test-sliding-puzzle-ui.sh
scripts/build-sliding-puzzle-validation.sh
```

UI 入口运行生产 UGUI 检查并输出 `artifacts/validation/sliding-puzzle-ui/report.txt`；构建入口读取当前工程版本，生成 `artifacts/builds/XanaduYonder-<版本>-sliding-puzzle-validation.apk`。独立包标识为 `com.duanyao.xanaduyonder.slidingpuzzletest`，用于隔离正式应用及其数据。这些入口应分别记录实际执行结果；独立 C# 测试不覆盖 Unity 触摸分发、真实安全区、图形、IL2CPP、Android 文件系统及设备生命周期。
