# 成语接龙学习机制与选词算法

本文是成语接龙学习机制的统一说明，涵盖词库、输入规则、APP 回复、提示、生词复习、个人熟悉词和本地保存。内容对应 2026-10-30 的多来源保留与全部合法词可选契约，代码入口与复核命令见文末。

玩法完全离线，不调用大模型。目标是让 APP 多说用户能理解、还能接下去的词，偶尔带用户复习生词，同时避免每次都选同一个最高分词。当前先保留全部合法候选，再按 95% 优先分支与 5% 其他合法词探索分支选择；优先分支内部按普通/到期复习 80%/20% 分池，最后池内加权随机。普通后继为零不排除候选。参数是产品启发式，不代表词频、掌握程度的科学测量或间隔重复记忆模型。

## 玩法与数据基础

人机对战和双人本地对战各支持同字、同音两种规则，共四个独立续玩槽位。人机开局选择机器先开始或人先开始；双人选择左方或右方先开始。双方共用本局已用词集合，一局内不能重复，历史消息、提示与随机状态分别保存。

| 规则 | 实际判定 |
| --- | --- |
| 输入格式 | 只去除首尾空白，必须恰好四个汉字 Unicode 码点，且正文精确命中当前可玩词库；不做模糊纠错或简繁自动替换。 |
| 同字接龙 | 上个成语的末字等于下个成语的首字。 |
| 同音接龙 | 使用各来源可解析的成对首尾音节，忽略声调；保留 ü/u、平翘舌和前后鼻音区别。每回合只释放与上一步尾音匹配的读音对的尾音，不跨对组合、不猜多音字。 |
| 合法输入 | 在完整词库中、符合字或音规则、本局未用即可；不要求属于常用词或还有普通后继。 |
| 无效输入 | 不追加历史，不增加学习次数，不消耗随机状态。 |

当前四汉字目录含 **45,776** 个词，公共常用表保持 **1,534** 个；版本由随包 manifest 记录。两套固定源按正文归并为 49,676 个唯一词，但所有 80,534 条源记录分别保留。读音和释义差异不排除四字词，各来源原文分别展示，不选择权威主释义，不由大模型补写内容。没有可解析读音的词仍可用于同字；同音提交明确说明读音不可用，包括用户开局首词。

公共常用表从 431 扩充到 1,534 词，是编辑策划的优先范围，不是权威词频表。未列为 Common 的合法词仍可参加探索或全库回退。具体数据、音对和来源字段见[数据说明](idiom-data.md)，策划标准及静态覆盖见[常用词审计](idiom-common-vocabulary.md)。

## 词的三种来源

| 集合 | 来源与用途 |
| --- | --- |
| C：公共常用词 | 随包发布的人工策划表，所有设备一致；完整词库的子集。 |
| F：个人熟悉词 | 用户在人机对战中独立合法说过的词，或明确点“我记住了”的词；只保存在本机。 |
| N：生词本 | 用户主动加入的词，带离线释义；表示希望继续学习，优先于 C/F 的推荐身份。 |

普通推荐范围为 `(C ∪ F) − N`，复习范围为 N。公共标签与个人学习记录不互相覆盖。F 中的词加入 N 后暂停熟悉推荐；只移出 N 不新增熟悉证据，已有的 F 证据可以恢复作用。“我记住了”会移出 N 并明确加入 F，不伪造独立回忆次数。

用户输入始终使用全部 45,776 个四汉字词校验，不因推荐表中没有这个词而拒绝。双人对战共用生词本和个人资料，因此既有 F/N 会影响双人提示；双方输入均不自动积累机主的 F，也不累计独立或辅助使用次数。手动“我记住了”仍是用户主动维护资料的入口。

## APP 如何选词

1. 从首字/全部可用首音索引取得符合当前规则的词，排除本局双方已用词。所有剩余合法词始终保有正选择概率；没有可解析音对的词仅不参加同音模式。
2. 计算候选的未用普通后继数，排除已用词和候选自身，同音按本回合匹配到的音对计算。后继数只用于轻微加权，为零也保留候选。
3. 普通词进入普通池；N 中距上次 APP 正式说出满 86,400 秒的词进入到期复习池，尚未被 APP 说出的生词立即到期。两池组成优先范围。其他合法词进入探索池，包括尚未到期的生词。
4. 优先范围与探索池都有候选时，以 95% 进入优先分支、5% 进入探索分支；任一为空时另一类获 100%。优先分支内部普通/到期复习两池都非空时按 80%/20% 选池，只有一池则使用该池。
5. 在选中的池内按正权重随机抽取。不会只保留最高分，近期降权和冷却都不能让合法候选永久失去资格。全库没有合法词才按无词可接结算。

例如“一望无际”的同字后继即使全都不在 Common，仍会进入其他合法候选；优先范围为空时使用它们继续。若当前另有普通或到期复习回复，这些非优先词仍有 5% 分支的选择机会。同音模式则使用来源中可解析的 `ji` 首音对。

机器开局使用相同策略，尚无前词时从该模式全部合法目录选择。冷却与近期记录跨字/音两个人机对局共享。没有用户名、联网服务或跨设备同步。

```mermaid
flowchart TD
    A[机器开局或用户合法提交] --> K{全库仍有未用合法词}
    K -->|否| L[按无词可接或词库用尽结算]
    K -->|是| B[分出普通及到期复习 与 其他合法词]
    B --> C{优先与其他都非空}
    C -->|是| D[95% 优先分支 5% 探索分支]
    C -->|否| E[使用唯一非空范围]
    D -->|优先| F[普通和复习都非空按80%与20%选池]
    D -->|探索| I[所选池内按正权重随机抽取]
    E -->|只有优先| F
    E -->|只有其他| I
    F --> I
    I --> J[记录历史 APP展示时间及近期记录]
```

策略只观察下一步普通可接性，不搜索整条最长接龙，也不保证永远可接。最多计数三个普通后继用于权重，生词或其他合法后继不增加这个普通后继分数，但不会因此被过滤。

### 权重公式与抽样示例

设 `k = min(未用普通后继数量, 3)`，k 可以为 0。

- 普通常用及其他合法词的基础权重：100。
- 个人熟悉基础权重：`120 + 5 × min(独立使用次数, 6)`，上限 150；同时属于公共和熟悉时采用熟悉权重，不叠加。
- 后继倍率：`(100 + 10 × k) / 100`，即 1.0、1.1、1.2、1.3；只温和偏向较好接的词。
- 最近 10 条 APP 正式输出（含开局）出现过：权重乘 0.25；跨局生效，仍有正概率。
- 复习基础权重：`100 + 3 × d + 2 × max(0, 6 − min(独立使用次数, 6))`，其中 `d = max(0, min(等待完整天数, 7))`。等待时间从上次 APP 展示计算；未展示时从加入 N 计算，设备时间回退时 d 最低为 0。再乘后继倍率与近期降权。

实现先计算整数 `W = 基础权重 × (100 + 10 × k)`；近期出现则执行整数 `W / 4`。省略的公共除数 100 不改变相对权重，所有合法候选的权重仍大于零。

例如同一普通池有三个候选，均有两个普通后继：

| 候选情况 | 整数权重 | 该池内的近似抽中概率 |
| --- | ---: | ---: |
| 仅公共常用，近期未出现 | 100 × 120 = 12,000 | 39.22% |
| 个人熟悉，独立说过两次，近期未出现 | 130 × 120 = 15,600 | 50.98% |
| 仅公共常用，最近十条 APP 消息出现过 | 100 × 120 ÷ 4 = 3,000 | 9.80% |

抽样将各权重累加，生成随机值后定位其落入的权重区间。第二项权重最高，也没有必选权；若普通池和复习池同时存在，上表概率还要乘优先分支内普通池的约80%；若另有探索候选，还要乘进入优先分支的约95%。只有复习池非空且没有其他合法候选时，复习比例才是100%。

实现使用 `xorshift32` 伪随机数和取模完成选池、选词，因此这里的百分比是目标比例或近似概率，并非无偏抽样的精确统计承诺。20% 不是每五回合必有一次，也不保证连续两局一定不同。等待时间仅调节权重，不承诺每日固定复习计划；设备时钟向前变化可能提前到期，向后变化只会延后到期。

### 随机性与恢复的一致性

- 候选按稳定 ID 顺序索引，固定词库、对局、个人资料、时间和随机状态时，结果可复现；不是预先为每个成语绑定唯一后继。
- 新对局从 UTC 时钟与系统运行计时生成种子；种子不保证绝不碰撞，随机选择也允许在不同对局恰好相同。
- APP 与提示各有一个随机状态，生成提示只推进提示状态。保存与恢复保留两者，退出重进不会额外重抽已有回复或当前提示。
- 提示可能让之后的用户输入被记为辅助输入，继而影响熟悉词资料；“随机流分离”只保证提示不直接消耗 APP 的随机数，不意味着提示对之后的学习和推荐绝无影响。

### 自动复习的时间边界

生词未被 APP 正式说出过时，无需等待加入生词本满一天。已经说出过则满足 `当前 UTC 秒 − 上次 APP 展示 UTC 秒 ≥ 86400` 才进入优先分支的自动复习池，恰好 24 小时到期；未到期时仍可通过其他合法词分支被选中。

记录覆盖所有 APP 正式输出：一个词即使先作为普通词被 APP 说出，随后才加入生词本，也沿用那次展示时间。移出再加入不清空展示历史；重新加入的时间只在没有 APP 展示记录时作为等待天数的计算起点。提示和查看释义不会重置冷却，用户主动查阅和合法输入始终不受冷却限制。

## 提示与“独立输入”的定义

每次提示前两项优先从普通池抽取；第三项优先生词，其他合法候选存在时有 5% 机会探索其他词。其余空位先从普通/生词合并池补足，再从其他全库合法词补足。最多三个且不重复，不占用本局已用词，不自动发送。普通后继为零不排除提示；用户主动提示生词不受自动复习冷却限制。全库确无候选或生成失败时不增加次数。

提示免费，每名人类玩家每局最多使用三组新提示；本地双人左右各自三次。第三组展示后仍可以选词填入并提交，对局继续；额度用完后主按钮变为“认输”，不会因为提示次数用尽自动结束。当前回合已有提示保持缓存，恢复和重复查看不重新随机、不增加次数。对局允许第三次提示后的后续输入以及双人合计六次历史提示。认输是明确的结束动作，用户也可从菜单主动结束本轮。

“独立输入”指在人机对战中合法提交，且该词没有在**当前等待用户输入的回合**被展示为提示或成功打开释义。整组提示都算展示，不局限于点选填入的那一项；从生词本打开释义也算。辅助状态随存档保存，退出再进入不能消除来源。跨回合不追溯辅助来源。

| 事件 | 学习结果 |
| --- | --- |
| 人机独立提交，词不在 N | 累计独立使用，第一次即可进入 F。 |
| 人机独立提交，词在 N | 累计独立回忆，仍留在 N，不自动认定记住。 |
| 人机辅助后提交 | 正常计分，记辅助使用，不新增独立使用或 F。 |
| APP 说出 N | 记录再次见到与展示时间，不自动移出 N 或加入 F。 |
| 双人本地提交 | 只更新对局，不积累机主的个人熟悉词。 |
| 用户点“我记住了” | 明确移出 N、加入 F。 |
| 用户点“移出生词本” | 仅取消生词标记，不生成掌握证据。 |

只有通过格式、词库、去重、接龙规则校验的提交才产生使用记录。即使有效输入随后使 APP 无法继续，该输入本身仍计入学习。辅助来源以词 ID 标记：同回合看了甲词的释义，并不会让未展示过的乙词也算辅助；成功提交后清除当前辅助集合，下一回合重新判断。

人机合法提交先更新个人资料，再选择当次 APP 回复，因此新的熟悉证据立即生效；刚提交的词仍受本局去重约束，APP 不能马上把它复述回来。独立说对一个仍在 N 的词，只增加回忆次数，不自动毕业；当前也没有随时间遗忘、达到次数自动毕业或根据错误输入扣除熟悉状态的机制。

APP 说出的词已进入本局去重集合，用户不能在本局再说一次。因此本版本是生词再遇见机制，不是要求用户立即回忆同词的测验。

## 结算与学习页面

| 情况 | Core 状态与页面行为 |
| --- | --- |
| 优先范围为空，但全库尚可接 | 从其他合法词中选择，继续本轮；不因推荐范围用尽结束。 |
| 全词库没有未用合法后继 | 依轮到的一方记录 `AppNoMoves` 或 `PlayerNoMoves`；双人模式中 App 枚举代表左方。 |
| 全词库全部用完 | `DictionaryExhausted`，优先于某方无词可接。 |
| 当前人类玩家三次提示用完 | 第三组仍可用于提交，对局保持进行中；主按钮显示“认输”。 |
| 当前人类玩家认输 | `Surrendered = 7`，记录当前方认输并展示小结。 |
| 用户主动结束 | `EndedByPlayer`，保留历史供回顾。 |

对话页左右消息可点开释义；右上角本子图标进入生词本二级列表。释义弹窗按来源分别展示原拼音、词义、可用典故、出处和例句，长内容可滚动，支持点击周围阴影关闭。未加入的词显示“加入生词本”；已加入的词提供“我记住了”与“移出生词本”两个不同动作。前者明确新增熟悉身份，后者只取消生词标记。

小结显示本轮完成数量，双人另有双方数量，以鼓励和回顾为主，提供“再来一局”“生词本”“回看本轮”。已经生成的提示和历史不因之后编辑生词本而改写。

## 状态所有权与保存

Core 纯 C# 接收共享 `IdiomLearningProfile` 与 UTC 秒时钟，不依赖 Unity 或磁盘。生产页面显式注入时钟，独立测试可注入固定时间。四个可续玩对局共享同一个 profile；个人学习变化影响下一次尚未生成的选择，不重写已生成的回复、提示及结算。

Presentation 成功展示释义后调用 `RecordDefinitionViewed`；有效提交与 APP 输出的学习变更在 Core 动作内执行一次。普通 Save 只复制快照，不重放事件，所以重复保存不会重复计数。

`Application.persistentDataPath/idiom-learning-v1.json` 使用 `schemaVersion = 1`、`gameId = idiom-learning`，将四组对局与学习状态一起原子保存，文件上限为 64 MiB。

| 保存内容 | 字段与用途 |
| --- | --- |
| 四组续玩 | 人机同字、人机同音、双人同字、双人同音；各含历史、先手、结束原因、提示、草稿与纪录。 |
| 随机与辅助来源 | 每局 `randomState`、`hintRandomState`、当前 `assistedEntryIds`，恢复后延续选择与辅助判定。 |
| F/N 身份 | `familiarIds`、`notebookIds`，两者允许同时有记录，但 N 优先。 |
| 学习次数 | `uses` 中的独立与辅助使用次数；辅助次数仅记录，不用于提升熟悉权重。 |
| 再遇见记录 | `appExposures` 保存每词最近一次 APP 正式展示时间；`recentAppIds` 保存最近十条 APP 消息，包含机器开局，跨局降权。 |
| 生词加入时间与释义 | `notebookAdded` 与 `notebook` 保存一致的身份和加入时间；生词本另保存加入时词条、原拼音、全部来源资料的完整文本、内容身份 ID 与词库版本；不截断来源。 |
| 历史终态依据 | `endSelectionContext` 等旧字段仅用于已有历史终态校验，不作为新局因推荐范围用尽结束的依据。 |

编码前验证、写入临时文件、持久刷盘后替换主文件，并保留可用备份。写失败时保留上一份完整文件；普通游戏动作维持内存进度并显示保存错误，可重试。生词本编辑写失败时同时回滚内存的生词本与共享 profile，避免半成功。备份恢复沿用本游戏的文件保护机制，不影响其他小游戏。

本次按用户要求不做旧存档迁移；历史 `idiom-v1.json` 与 `idiom-notebook-v1.json` 不读取、不覆盖。新协议校验类型、范围、唯一性、词条身份与 Notebook/Profile 一致性，并要求存档目录版本与当前词库一致。主文件缺失或损坏时尝试备份；主文件版本不兼容则直接保护原文件，不尝试备份。版本不兼容或没有可用备份时等待用户确认归档重建，不能静默清空资料。

新局不再产生 `RecommendationExhausted` 或 `HintLimit`；旧枚举只用于只读恢复历史，不能让新局第三次提示自动结束。恢复验证允许第三次提示后继续和双人各三次提示，并从完整历史按成对读音重建本回合可用尾音。词库版本变化仍受现有保护，不为旧档自动迁移或清空。

## 当前限制与调参原则

公共常用范围的覆盖有限，其他合法词因此可能被选中；用户可随时查看资料或收进生词本。静态覆盖审计分别报告普通回复、其他合法回复和全库无解，不把“普通回复后仍有普通词”误称为可接龙资格。统计不模拟完整对局或95%/5%抽样概率，具体口径见[常用词审计](idiom-common-vocabulary.md)。

当前没有词频模型、服务端用户画像、自动掌握分级、错误遗忘曲线或每日复习任务。后续调整先观察短局比例、普通后继覆盖及复习重复情况，再改变公共词表或少量参数；这些是评估方向，当前没有自动采集上报。调整分支概率和权重时仍须保持每个合法候选可选。

修改选词、学习或存储语义时，应同步更新本文件对应公式、事件表和边界测试；修改公共词表时还需重新导出资源与覆盖审计，并处理目录版本变化对存档的影响。
