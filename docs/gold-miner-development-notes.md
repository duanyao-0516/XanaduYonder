# 黄金矿工开发记录与约定

记录日期：2026-10-28。用于后续维护，区分已解决问题、实现约定与验收边界。

## 1. 开发隔离

- 在独立 Git worktree 开发，明确当前分支与交付目标，避免污染其他任务。
- Unity 构建目录、Android 测试包名、存档目录和设备操作均应隔离。
- 多 agent 并行时按文件划分职责；Unity、构建和设备操作由主 agent 统一协调。
- 不覆盖用户原安装包或存档；需要覆盖时先明确范围并保留备份。

## 2. 设计还原与视觉验收

- 全屏黄金矿工以已确认的设计预览为准，不强行套用大厅配色。
- 背景、圆角、文字、图标、按钮、留白和页面状态都属于还原范围。
- 坐标正确、握点重合、测试通过不能证明视觉自然；必须实际查看渲染结果。
- 同时看放大近景和实际显示尺寸，避免只在大图中发现问题或只在小图中掩盖问题。
- 分开记录素材预览、Unity 渲染、Android 真机验证，不能用其中一种替代另一种。

## 3. 矿工与收线动画

- 原拆分手臂素材带有闭合袖口，刚性拼接后出现断臂和悬空手；仅调整骨骼点不能根治。
- 使用包含矿工、完整手臂、握柄和绞盘的六帧整体图，避免零件之间的连接缝。
- 头部、脚底、机器轴心和出绳位置保持稳定，机器不能整座在屏幕平面内旋转。
- P1 橙色、P2 青色沿用同一角色和材质；P2 镜像完整画面，不改变游戏世界坐标。
- 六帧属于卡通分帧动画，手柄相位并非严格等速圆周，不宣称连续机械动画。
- 播放进度由真实绳长减少量及实际回收速度驱动，不能仅靠渲染帧数或墙钟时间。
- 暂停、首帧、视图重建和恢复需要处理长度基线；两个玩家的动画状态独立。

## 4. 绳子、抓钩与载荷

- 每帧以实测短绳末端作为 sprite pivot，归一坐标与导入尺寸解耦。
- 短绳连接固定世界原点，再接会转角的主绳；主绳和抓钩的朝向保持一致。
- 抓钩和九种载荷使用完整抓持组合图；统一吊环显示尺寸，不再运行时拼接物体。
- 携钻鼹鼠由前爪抱住钻石，移动和被抓状态都保持完整形象，不能悬浮或背钻。
- 绘图锚点校验只证明声明的数据一致，仍须实看手部连接、抓持位置和出绳衔接。
- 放大近景曾看到竖直短绳与斜主绳交点的硬折角；后续精修时关注端部外观。

## 5. 平衡性与旧档兼容

- 区分空钩、轻物、大金块和重石头的回收时间，让重量真正影响一局的决策。
- 黄金矿工按累计钱包判定过关；商店消费会减少带入下一关的资金。
- 不能只看单关目标或成功见证判断难度，还需测量连续挑战、购物和不购物路径。
- 新挑战采用新目标曲线；旧挑战直至结束沿用旧曲线，本关与重试也保留已接受目标。
- 原迁移曾让旧第九关 15150 钱包进入目标 30400 的第十关，缺口超过整场矿物收入上限。
- 修复应保持挑战曲线连续，不能靠补钱、偷偷改目标或降低验证要求掩盖问题。
- 旧记录没有独立规则版本，保留历史合法成绩；存档目标仍只接受明确的旧、新曲线值。
- 固定策略模拟不是人类胜率；熟练玩家积累盈余仍可能提前达标，应如实说明。

## 6. 素材、构建与交付

- 保留生成原图、提示词、来源、尺寸和 SHA-256；透明性检查实际 alpha，不能只看 RGB 预览。
- 素材按版本使用独立严格清单；校验路径、数量、身份、哈希、切片、pivot 和压缩格式。
- 同一动画图集各帧必须等尺寸；全部来源、目标及既有 GUID 预检完成后再写入。
- Android 使用明确的 ETC2 RGBA8、尺寸上限和无 mip 配置，保留源 PNG 原字节。
- 发布从干净构建副本和独立 Library 产出，关注 APK ZIP 有效内容及异常间隙，避免复用污染产物。
- 交付记录构建来源、包名、版本、哈希、验证范围与未验证项；不把编译成功写成真机体验通过。
