# 连连看 UI 设计示例

本目录是 **浏览器设计原型，演示进度，不保存**。它没有接入 Unity，没有完整连连看规则引擎、真实倒计时、六槽活动局、成绩或持久化；不联网对战，不请求远程图片，也不会读写生产存档。时间、续局和完成结果是明确的评审夹具，不代表用户实际进度。

设计依据为最新主线的 [推箱子开发复盘与小游戏 UI 参考规范](../../sokoban-development-guide.md) 和 [推箱子原型](../sokoban/README.md)。**设计阶段记录**：当时只新增本目录，没有修改生产 `Assets/`、游戏逻辑和既有原型。后续已完成 Unity 实现，当前生产实现与各层验证状态见[连连看验证记录](../../verification-link-match.md)；本原型仍仅用于演示。

## 打开与切换

在仓库根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，打开 [原型入口](http://127.0.0.1:8765/docs/prototypes/link-match/)。页面使用本地素材与项目已入库的 Noto Sans CJK 字体，不依赖 CDN。

外层评审控件可切换大厅卡片、选关、轻松对局、挑战对局、挑战超时、暂停、重开确认、本关完成、最后一关完成、保存失败与素材板；另有 388×784 / 360×640 安全内容尺寸、首次 / 续局样例，以及第 01–03 关选择。控件不属于正式游戏 UI。

点击「三页概览」把大厅、选关和挑战对局并排显示。三张内容仍分别按 **388×784 CSS px** 渲染，再整体等比缩放到浏览器可用空间；概览缩放不改变真实设计尺寸，也不作为物理触控尺寸证明。

## 页面与样例状态

- **大厅**：仅演示新卡及已有大厅头部。保留当前大厅文案、左品牌 / 右 Settings、608×350 卡片比例和底部「开始 / 继续游戏 →」按钮，编号为 13。卡片按钮先到连连看选关页；本原型不复制其余 12 款游戏。
- **选关**：轻松 / 挑战两个页签，三张关卡卡片显示编号、牌数、图案种数和网格。点击卡片直接开始或继续，无重复「进入」按钮。全部关卡开放，不暗示解锁关系。
- **最近活动局**：`profile=resume` 仅预置“轻松第 02 关、36 张待配、00:32”的单一演示局，入口卡明确写轻松；它可越过当前挑战页签直接继续这局。其他模式 / 关卡槽位没有伪造续局。`profile=new` 没有演示活动局，首卡会跟随当前模式开始第 01 关。
- **正式游戏**：导航、标题、单行信息、淡 `#EBEEE2` 圆角棋盘、提示 / 洗牌 / 暂停集中操作区。Home 回大厅；点击关卡名回选关；Book 显示简短规则；Settings 为示例共用声音 / 触感开关，既不播音也不振动。
- **棋盘**：三关分别为 4×6 / 24 张 / 6 种、6×6 / 36 张 / 9 种、6×8 / 48 张 / 12 种。每种水果恰好 4 张。没有 6×10 棋盘。固定排列仅验证牌数和图案计数，未宣称全部局面可解，也不是生产关卡。
- **选中与连线**：默认两张草莓位于左列第 2、5 行，线从左侧外圈绕行，恰好两次转弯，不经过其他水果。点任意水果仅预览单选反馈；「提示」恢复这条合法示例路径。「洗牌」在两个固定排列之间切换，不是生产随机重排或可解性保证。
- **模式数值**：轻松不限时、道具显示无限。挑战展示每关初始 90 / 120 / 150 秒，3 次提示、2 次手动洗牌；时间不会流逝，道具次数不会扣减。这些数值均待真实试玩调参。
- **暂停 / 帮助 / 设置**：弹层出现时，全部棋盘水果与路径隐藏，底层内容 `inert`。暂停的 × 或 Escape 回选关并保留内存夹具；只有「继续游戏」直接恢复棋盘。游戏中关闭帮助或设置（×、Escape、「明白了」或「完成」）先回暂停，需明确点击「继续游戏」；从选关、大厅或素材板打开时则正常关闭并留在原页。重开确认的 Escape 仍回暂停。原型没有需要恢复的真实计时器。
- **重新开始本关**：暂停弹层在「继续游戏 / 返回选关」下方增加小号文字入口。确认弹层显示「重新开始这一关？」及「将替换这一关的当前进度。其他模式和关卡不受影响。」；「保留当前进度」或 Escape 回到暂停，保留当前演示状态。「重新开始」只重置当前内存夹具的选中、路径、洗牌排列、续局时间样例和保存失败标识，保持当前模式与关卡；轻松显示 `00:00`，挑战显示本关初始时间，时间仍不推进。原型未实现六槽存储，外层首次 / 续局样例和选关页预置的轻松第 02 关样例不被改写。
- **完成**：页外切换到固定完成结果，不由点击水果触发。第 01 关完成后，若轻松第 02 关已有样例局，主按钮为「继续下一关」；否则为「下一关」。第 03 关只说明该关完成，提供「再玩这一关 / 返回选关」，不声称前两关已完成。
- **挑战超时**：`timeout` 状态自动使用挑战模式，倒计时固定为 `00:00`，弹层明确显示「时间到 / 本关未完成」，隐藏全部底层水果和路径，阻止底层输入；只有「重试本关 / 返回选关」，没有续命、下一关或关闭后继续旧局的出口。重试恢复本关初始时间样例，不实际启动计时器。
- **保存失败**：持续提示“进度尚未保存，请暂时保留本页”，重试样例继续保持失败。不会短暂 toast 后静默消失，也不会声称保存成功。

## 尺寸约束

棋盘统一保留最少 12 CSS px 外围通道，示例线路距网格左边 8 px。实际点击区域是互不重叠的方形 slot，牌面向内缩 2 px；没有覆盖相邻格的透明扩大热区。

`slot = min((棋盘区域宽 − 24) / 列数, (棋盘区域高 − 24) / 行数)`。小于 680 px 高度时压缩导航、标题与工具区间距，保留 48 px 操作按钮；保存错误条独立占位。CSS px 不等于所有 Android 设备的物理 dp，最终还需真实宿主验证。

## 工作拆分与验证边界

本次工作按“读取主线规范 → 固定素材来源 → 入口 / 游戏 / 状态原型 → 静态核查 → 浏览器复核”执行。

**开发阶段状态补全（2026-10-28）**：研究方案已要求重开，但最初原型漏了入口；本次补齐暂停入口、重开确认及 `restart` 评审状态，对应 Unity 重开交互已实现。本次仅同步四个原型文件，已批准的入口、棋盘、素材与页面布局沿用原样；新增交互只操作演示夹具，不表示浏览器已有真实计时或存档。此次补全执行 JavaScript 语法和小范围状态逻辑检查；此前截图未包含重开弹层。

**弹层退出语义修正（2026-10-28）**：最初演示将 ×、Escape 与继续共用关闭逻辑，会直接露出棋盘，与方案“恢复必须明确点继续”不一致。现同步防止停表看题的退出语义：暂停关闭回选关，游戏内帮助 / 设置关闭回暂停，明确点击「继续游戏」才恢复棋盘。此修正只改变关闭路由，不改视觉、布局或底层夹具；本原型仍无真实计时或生产存档读写。

- `index.html`：评审入口、共享外壳、三个主页面、素材板与弹层容器。
- `style.css`：合集风格、安全内容尺寸、棋盘与短屏适配、宽屏概览。
- `prototype.js`：演示状态、导航、固定棋盘排列、合法路径和状态切换；不包含生产规则与存档。
- `assets/`：原始水果、MIT 原文、固定版本与哈希。

已执行静态检查：JavaScript 语法、Git 空白错误；12 张 PNG 的签名 / CRC / 尺寸 / SHA-256；六种棋盘夹具的总数、图案种数、每种 4 张与外圈端点一致性；本地资源引用存在性。没有建立针对原型实现细节的长期测试套件。

浏览器复核已观察到：360×640 的第 03 关正常 slot 约 **51.33 CSS px**；保存失败状态 slot 约 **48.25 CSS px**；棋盘与操作区保持在安全内容内，48 张本地原图加载成功。

已实际点击核对：新玩家选择挑战第 03 关后显示 48 张 / 02:30；续局入口恢复轻松第 02 关 / 00:32；暂停隐藏棋盘且底层 `inert`，继续后恢复；第 03 关完成不显示下一关；保存重试后错误持续；挑战超时显示 00:00 并遮盘，重试本关回到挑战第 03 关 / 02:30。这些结果仅验证演示导航与状态，不代表真实游戏逻辑。
