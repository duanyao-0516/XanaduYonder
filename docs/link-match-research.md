## 3. 玩法调研

### 3.1 经典规则

选择不同位置的两张同图牌，若存在仅水平/垂直、最多两次直角转弯的空通路，则同时消除。允许直线、L 形、Z/U 形；不允许斜连或穿过其他牌。玩家只点两张牌，系统计算并展示路径。这是 KShisen 官方规则的核心。麻将花牌/季节牌的特殊互配规则与本项目水果主题无关。[KDE 官方规则](https://docs.kde.org/trunk_kf6/en/kshisen/kshisen/rules_and_tips.html)

路径可以走已消除空位，也可以绕棋盘外圈；外圈仍受两拐弯限制，不是边缘任意互连，也不是左右边界传送。[DKM 官方帮助](https://dkmgames.com/Shisen/ShisenHelp.htm)

首版采用静态单层棋盘，消除后保留空位，没有落子、重力、旋转或卡槽。这与旸了个旸的叠层遮挡、七槽三消属于不同规则模型。

### 3.2 代表性取舍

| 参考 | 已查证特点 | 本项目取舍 |
| --- | --- | --- |
| KShisen | 可选可解开局；可选重力与滑动；错误消除顺序仍可能使可解局卡住 | 以静态规则为基准，单独处理可解性与死局 |
| Famobi Onet Connect Classic | 官方商店介绍为每关 5 分钟，提供提示和洗牌 | 证明限时是一个常见变体；不直接照搬 5 分钟 |
| Nikakudori / Street Mahjong | 时间不影响玩法，可按自己的节奏消除 | 轻松模式不设超时失败 |
| DKM Shisen | 提示表示当前可配，不承诺全程可解；手机版因空间缩减牌数 | 提示文案不称“最佳解”；手机尺寸优先 |

来源：[KDE 配置](https://docs.kde.org/trunk_kf6/en/kshisen/kshisen/configuration.html)、[Famobi 官方商店介绍](https://play.google.com/store/apps/details?id=com.famobi.onetconnectclassic)、[Nikakudori 官方玩法](https://www.nikakudori.com/)、[DKM 官方帮助](https://dkmgames.com/Shisen/ShisenHelp.htm)。重力/滑动是改变规则的变体，不能仅当作动画加上去。

### 3.3 三种“可解”不能混用

**同图数量为偶数、当前存在可消一对、全局存在完整消除序列，是三个不同保证。** 例如满盘 `A B / B A` 虽然两种牌各两张，却不能按两拐弯规则开局消除。该反例是按上述规则推导。

建议开局与洗牌都产生可重放的完整解法见证，并通过生产规则重放校验；随机摆若干对子不算可解生成。局中每次有效消除后扫描当前可消组合，没有组合且仍有牌则自动救场。不能将搜索超时判为已证明无解。

自动重排保留剩余牌的种类与数量，优先保留空位分布，清除旧选中态，并产出可验证的新解法。生成需有有界重试与确定性兜底，不允许无限随机洗到碰巧可走。初局可解仍不保证任意玩家顺序都能清盘；提示只保证当前合法。

## 4. 首版双模式及选关

### 4.1 关卡目录

首版推荐每种模式 3 个关卡入口，全部开放，使用编号和实际牌数，不虚构主题章节。每次新开同一关生成新局，关卡代表稳定的规则档位；稳定 `levelId` 与展示编号分开。教学从 Book 进入，展示直连、一拐弯、两拐弯、外圈及阻挡，不计入普通关记录。

| 展示关卡 | 棋盘（列×行） | 图案种类 | 轻松 | 挑战初始时间建议 |
| --- | --- | --- | --- | --- |
| 01 | 4×6，24 张 | 6 种，各 4 张 | 不限时 | 90 秒 |
| 02 | 6×6，36 张 | 9 种，各 4 张 | 不限时 | 120 秒 |
| 03 | 6×8，48 张 | 12 种，各 4 张 | 不限时 | 150 秒 |

90/120/150 秒是待试玩校准的设计参数，不是连连看标准或已经验证的难度。配对可见度、图案分布和外圈利用也影响难度；不能只按牌数或求解耗时声称“真人简单/困难”。

### 4.2 两种模式

| 项目 | 轻松 | 挑战 |
| --- | --- | --- |
| 胜利 | 清空棋盘 | 倒计时归零前清空棋盘 |
| 时间 | 正向记录有效游玩耗时，无超时失败 | 倒计时；准备完毕、首次露牌且可操作时起表 |
| 提示 | 不限次数 | 每局 3 次 |
| 主动洗牌 | 不限次数 | 每局 2 次 |
| 无可消组合 | 免费自动重排 | 免费自动重排；系统重排期间停表，不扣道具 |
| 辅助耗时 | 正常记录 | 提示显示、主动洗牌及普通消除反馈继续计时，不额外扣秒 |
| 记录 | 通关次数、单局耗时、辅助使用情况 | 最佳完成耗时与同一局辅助情况；按模式和关卡分开 |
| 失败 | 不因无路或时间失败 | 超时后重试或返回选关，不用广告续命 |

首版不叠加生命、体力、签到、联网排行、复杂连击积分或奖励广告。可以有短促成功反馈，但连击不改变本版胜负或计时。

### 4.3 选择、继续与返回

- 从大厅进入选关页。新玩家默认轻松第一关，只显示预览；点开始后才创建活动局。
- 选关页上方显示最近一个未完成活动槽的模式、关卡、剩余牌及继续按钮；继续直接恢复该局，不要求重复选择。所有活动槽都已结束时显示开始，不能把终局包装成继续。
- 推荐按 `模式×关卡` 保留 6 个独立槽位，参考数独按难度隔离续局的产品语义。切模式、浏览其他关卡不覆盖正在进行的局。
- 选好模式后，点击关卡卡片直接开始或继续该槽；已有活动局的卡片标明“继续”，避免再嵌套一个重复的进入按钮。重开已有局是单独动作，并确认会替换该槽。
- 对局中的关卡入口返回选关；Home 始终回合集大厅。系统返回优先关闭弹窗，其次对局回选关，再从选关回大厅。
- 普通关通关可进入下一关；目标槽已有未完成局时显示“继续下一关”，不能静默覆盖，另行重开仍需确认。03 完成后显示“再玩本关 / 返回选关”，不出现不存在的 04。
- 从后台恢复仍停留当前局，先显示暂停遮罩，点继续再露牌和计时，不重新走选关流程。

### 4.4 点击与暂停边界

第一张选中后描边；再点自身取消；点不同图案改选新牌；同图但无路时给短反馈并保留第二张为当前选择。非法配对不扣生命或额外秒数。成功展示实际有效路径，路径选择稳定地优先少转弯、再短距离。

暂停、设置、帮助、退出确认和系统后台都停止两个模式的有效游玩时钟，并用不透明面板遮住整个棋盘，防止停表看题。恢复必须明确点继续。系统自动洗牌同样暂停但不消耗配额，重排完成后恢复。

以第二张有效点击提交时的剩余时间判定：剩余时间大于 0 且消除最后一对即获胜；归零时不再接受提交。先确定并保存终局，再播动画，不能因为消除动画跨过截止时刻把胜利改成失败。

## 5. 小区域还是独立游戏页

| 方案 | 判断 |
| --- | --- |
| 大厅卡片里直接玩 | 不推荐。固定卡片还承担标题、预览和入口，容不下清晰棋盘与外圈；纵向滚动和点选也需要额外仲裁 |
| 独立页但保留很大的标题、说明和小方形棋盘 | 空间利用差；限制可用行数，与最新“主体优先”规范不符 |
| 独立竖屏页，棋盘占导航和工具之间的可用空间 | **推荐。** 保持 App 风格与已有返回/设置习惯，能完整观察全盘及外围路线 |

Android 官方建议交互目标至少约 48×48 dp；8 列在 360 dp 宽度中，仅目标自身就需要 384 dp，尚未计入边距。因此先用最多 6 列，并在较短屏验证最大 8 行。CSS px、Unity 设计单位与 Android dp 并不相等，原型几何通过不等于设备触控通过。[Android 官方触控尺寸建议](https://support.google.com/accessibility/android/answer/7101858?hl=en)

棋盘用淡底 `#EBEEE2`、奶油白小牌和轻阴影；图案保留彩色，连接线和选中态用深绿。外圈至少留出看得清的路径通道。全盘静态可见，不要求玩家拖动或缩放才能寻找配对。若更窄设备无法满足目标尺寸，应减少开局内容或明确适配策略，不能默默重排进行中棋盘的邻接关系。

## 6. 素材确认

### 6.1 首选：Fluent 3D 水果

首发图案：**草莓、红苹果、橘子、柠檬、香蕉、西瓜、葡萄、樱桃、桃子、梨、菠萝、牛油果**。

选择理由是统一圆润体积感、清楚的轮廓和足够的色彩差异；与纸色/深绿外壳相配，又与现有三消描边牌区分。避免同局放红苹果/绿苹果这样主要靠颜色区分的近似图。全部固定使用 3D PNG，不混用 Color SVG、系统 emoji 字符或不同厂商风格。

[Microsoft 官方仓库](https://github.com/microsoft/fluentui-emoji)提供对应 PNG；本次核查候选 3D 图为 256×256。[官方 MIT 许可](https://github.com/microsoft/fluentui-emoji/blob/main/LICENSE)允许使用、修改和分发，需保留 Microsoft 版权及完整许可。原型保留原始文件，正式入包只选择所需图案，不拉入整个素材库。

原图以固定版本、来源 URL、SHA-256 和稳定图案 ID 记录在 [原型素材清单](prototypes/link-match/assets/manifest.json)，原始许可随目录保存。牌底、选中边框、阴影及连线由 UI 绘制，避免把各种状态烘焙进图案。正式游戏离线加载资源，研究原型的下载过程不成为运行时依赖。

### 6.2 候选对照

| 素材 | 风格与代价 | 结论 |
| --- | --- | --- |
| Fluent 3D | 圆润水果、光照统一、现成透明 PNG；MIT 需保留许可 | 首选 |
| Kenney Animal Pack Remastered | 统一动物头像，30 种动物×8 风格；CC0；更偏儿童卡通 | 可作为第二主题，需全套选同一种风格 |
| OpenMoji | 描边平涂，适合花园手账；CC BY-SA 4.0，需要署名及相应许可处理 | 可用但不是本版首选 |
| Kenney Food Kit | 200 个 3D 食物/厨房模型，CC0；官方主要定位为模型包 | 不把未核实的渲染图当成现成 2D 牌面 |

来源：[Kenney 动物包](https://kenney.nl/assets/animal-pack-remastered)、[作者发布详情](https://opengameart.org/content/animal-pack-redux)、[OpenMoji 官方资源及许可](https://github.com/hfg-gmuend/openmoji)、[Kenney Food Kit](https://kenney.nl/assets/food-kit)。

最新主线已有大西瓜水果，但来自另一来源、只有 11 级且尺寸与风格不统一；其授权和物理合成用途见[大西瓜素材记录](watermelon-assets.md)。本次选择独立 Fluent 集合是视觉与识别度取舍，不改动大西瓜素材、等级和 GUID。

## 7. 后续实现边界

| 责任 | 建议归属 |
| --- | --- |
| 牌阵、合法连接、两牌消除、终局 | `Core/LinkMatch/LinkMatchGame`，不引用 Unity |
| 完整路径、当前合法对子、可重放生成 | 独立 PathFinder / Generator，与提示及消除共用同一判定 |
| 有效游玩时间、输入门禁、当前尝试 | LinkMatchSession |
| 六个槽位、关卡记录、最近选择 | LinkMatchProfile；预览不属于活动尝试 |
| 入口、棋盘、连线、暂停及弹窗 | `Runtime/LinkMatch`，使用共享 UiFactory / UiIcon / GameFeedback |
| 严格 JSON 校验及文件事务 | 独立 `link-match-v1.json`，不修改其他游戏 schema |
| 大厅、共用设置、路由和前后台 | AppController 最小接入 |

保存契约至少包含 schema/gameId、模式、稳定 levelId、内容版本、行列、图案 ID 列表、剩余/已用时间、道具次数、随机状态、终局与已计数标记。外部输入先按真实 Newtonsoft token 校验，再恢复模型；偶数牌量不能单独证明存档状态合法。图案资源映射与 ID 分开，避免替换图片导致存档变成另一种牌。

独立临时文件与原子替换，只有合法主档可以成为备份；写入失败保留内存局并持续提示。返回、失焦、后台及有效动作按模型保存；计时还需要周期检查点，后台时冻结而非按墙钟追扣。强杀后可恢复到最近成功检查点，不宣称逐毫秒无损。

正式页显示本游戏存档错误及公共设置保存错误，其他游戏的错误留到大厅汇总。若扩大棋盘时隐藏全局 footer，页内承接 `SetHostSaveWarning`；成功重试分别清除对应错误，不让一次成功掩盖另一项仍失败的保存。

一次指针只允许一个提交入口；滑出、多指、取消、弹窗、布局变化和后台取消未提交动作。动画不拥有计分和终局，恢复时第一张选择、提示闪烁和连线作为瞬态清空。

不复用 SheepGame 的七槽三消逻辑，不继承 SokobanPage，不为了连连看把所有游戏重构到新框架。宿主接入需覆盖 Build/Enter/Leave、Save/Suspend/Back、终局恢复、前后台和保存错误路由；从 Zuma/Dino 横屏回来再进入的恢复链也属于验收范围。

### 后续实现必须覆盖

1. 规则：0/1/2 拐弯、超过两拐弯拒绝、外圈、阻挡、相邻、同一格、不同图、所有方向和边缘。
2. 内容：多随机种子解法重放；区分仅成对/当前可走/整盘可解；残局洗牌保持数量、图案和约定空位；生成失败有界结束。
3. 会话：挑战起表、暂停遮盘、提示/主动洗牌计时、自动救场停表、截止瞬间最后一对、终局幂等。
4. 存档：六槽独立、只浏览不产生续局、损坏主备、null/错误类型/未知 ID/非法计时、写失败与恢复、其他游戏文件不变。
5. UI：两模式选关、首次和继续、普通与末关完成、超时、暂停、公共与本游戏保存错误；短屏最大盘与相邻触点；实际外圈线不被裁切。
6. 宿主：Home/Book/Settings 语义、硬件返回、横屏游戏返回后的页面、应用前后台；同状态同可用尺寸对照原型和生产 UGUI。
7. 设备：真实 Android dp、触点取消、多指、音效触感、连续点击、后台恢复及性能；分别记录构建、安装、启动和已执行交互。

本轮交付的是可审阅的首版方案与 UI 示例；时间预算、辅助配额和图案在小尺寸下的最终辨识度仍须通过真实试玩确认。
