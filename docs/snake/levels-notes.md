# 贪吃蛇障碍闯关：12 关配置草案

这份资料是调研阶段的原创关卡数据，尚未接入游戏。地图由本次方案直接构造，没有搬用其他游戏的地图、素材或关卡布局。`draft: true` 表示速度、目标和教学顺序仍需原型试玩验证；不能把静态检查通过解释为游戏体验已经验收。

配置文件：[`levels-v1.draft.json`](levels-v1.draft.json)。检查工具：[`validate_levels.py`](validate_levels.py)。两者只描述和检查障碍闯关；经典无限挑战使用独立模式配置，不把本文件的食物目标套用到无限挑战。

## 固定规则与字段

- `schemaVersion: 1` 只表示数据形状与字段契约；`rulesVersion: "snake-rules-v1-draft"` 表示待确认的玩法规则版本；`packVersion: "snake-levels-v1-draft-20261028"` 标识这一份完整关卡包。地图坐标、速度或目标的任意改动都必须更换 `packVersion`，即使 schema 和玩法规则没有变化；同一天的下一次修改也必须使用不同的新值。三种版本均独立于关卡 ID，后续调速不应改变 `snake-01` 至 `snake-12` 的稳定 ID。
- `defaults.columns = 20`、`defaults.rows = 24`，共 480 格。左上角为 `[0, 0]`；x 向右、y 向下。所有坐标均为整数且从 0 开始。
- `initialSnake` 按头到尾排列：`[[6,20],[5,20],[4,20],[3,20]]`，初始方向为 `right`。前三步落点 `[7,20]`、`[8,20]`、`[9,20]` 全部保留为空格。
- `tickMs` 是相邻两次逻辑移动之间的毫秒数。每关速度固定，关内吃食物不加速；数字越小越快。暂停、恢复、重开和展示动画不得悄悄改变该值。
- `targetFood` 为本关累计吃到的食物数，开局从 0 计数；每份食物只增长 1 格。目标从 8 递增到 30，均严格小于该关的剩余增长容量。
- `boundary: "wrap"` 表示四边对接：右出左入、左出右入、下出上入、上出下入；`"solid"` 表示碰外边界失败。进入关卡前必须明确展示本关边界规则。
- `obstacles` 是整关固定、开局就可见的坐标数组。没有随机生墙、限时变墙、隐藏障碍或食物触发的地形变化。障碍不占初始蛇身和前三步落点。
- `chapter` 依次为 `01-basics`（基础操作）、`02-islands`（孤岛绕行）、`03-dividers`（隔断换道）、`04-corridors`（回廊规划），每章 3 关。

## 满盘胜利与目标通关

共享规则应使用：

```text
freeCells = 20 * 24 - obstacleCount
snakeLength = 当前蛇头和蛇身的总格数
growthCapacity = freeCells - 4
```

一次合法移动及食物增长完成后，若 `snakeLength == freeCells`，应先进入满盘胜利终局，随后不再尝试生成食物。否则，本关累计食物达到 `targetFood` 时进入目标通关，也不再生成食物。只有尚未终局且吃到了食物的情况，才从未被蛇身和障碍占用的格子中生成下一份食物。满盘判断必须位于“寻找空格”之前，避免空候选集合或无限重试。

本草案各关 `targetFood < growthCapacity`，正常游玩会在满盘之前达到关卡目标。这是有意区分短局闯关与经典无限挑战；不能用“目标通关成功”代替“满盘胜利已经验证”。满盘顺序还需要在共享规则实现后，用无障碍盘、含障碍盘和只剩一个食物空格的状态测试单独覆盖。当前数据没有实现终局、食物生成、存档或游戏逻辑。

## 已执行的静态验证

运行命令（从仓库根目录执行）：

```sh
python3 docs/snake/validate_levels.py --self-test
```

脚本只使用 Python 3.9+ 标准库，不修改数据，不导入 Unity 项目，也不创建缓存文件。也可以将其他候选 JSON 文件路径作为位置参数传入，但该脚本目前刻意只接受本版 20×24、12 关和已确定初始状态的 schema；它不是通用地图编辑器。

校验包括：

1. 顶层、默认值和每关字段结构完整，拒绝缺失或未知字段；验证整数类型及范围，明确拒绝把布尔值当作整数。固定 schema 和规则版本必须匹配；`packVersion` 必须为非空字符串并等于当前关卡包版本，发布新包时需同步更新校验器的允许值。
2. 关卡 ID 唯一且排序稳定，章序正确，名称非空且不重复，速度和目标变化符合本草案范围。
3. 蛇身与障碍坐标均不越界、不重复；初始蛇为连续 4 格且顺序正确，障碍不覆盖蛇身；初始向右前三步安全。
4. 可用格与增长容量按障碍数计算；目标严格小于增长容量。
5. 按每关 `wrap` / `solid` 拓扑，对所有非障碍格做连通性遍历；初始蛇的格子参与静态地形图，不被当作永久障碍。
6. 每个非障碍格的静态度数至少为 2；所有空格至少属于一个完全开放的 2×2 方块；图中没有移除一个格就会断开的割点。这些补充检查用于筛除明显的单格走廊和瓶颈。
7. 内置 23 个反例检查，覆盖布尔整数字段、未知字段、空值、`packVersion` 缺失/空白/类型错误/未知值、蛇身重复或不连续、ID 重复、速度类型、边界枚举、障碍重复或越界、初始碰撞、安全步被挡、地形断开、静态死角、单格走廊、单格瓶颈及目标耗尽增长容量；另检查四向 wrap、solid 不穿越和第 4 关的障碍落点样例。

## 尚未验证的界限

静态连通、无度数 1 的死角、2×2 覆盖和无单格割点，都不能证明长蛇在任意身体形状、任意随机食物序列下都有解，也不能证明存在可执行的满盘路线。已经增长的蛇身会成为动态障碍；一次错误转向仍可能把自己围住。这里没有求解 Hamilton 路线，没有模拟自动玩家，也没有给出必胜保证。

仍需在获准实现原型之后验证：真实转向与输入缓冲、尾格碰撞规则、四向穿越后的障碍和自碰撞、随机食物公平性、吃到目标与满盘同帧的优先级、暂停及恢复、失败后重开、关卡解锁及存档兼容、低帧率下的逻辑步进，以及触屏设备可读性和操作容错。220–140 ms 和 8–30 份食物均为待试玩的初始值；实际通关率、时长、难度递增与手感尚无测量结果。
