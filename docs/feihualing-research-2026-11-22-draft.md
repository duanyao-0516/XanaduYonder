## 三项开局配置

大厅进入飞花令，选人数、目标和玩法，再确认题卡。首次建议默认 **单机 · 学习 · 单字令「月」**。题卡展示令题、条件和一句规则说明，有多张合格题卡时可点「换一题」。成功开始时锁定本局配置。首页记住上次配置，有相应进度时优先提供「继续」，选择新局且会覆盖本槽旧进度时先确认。

| 人数 | 学习 | 竞技 |
| --- | --- | --- |
| 单机 | 不限时自由回忆，可主动请本地陪练接一句，可看提示与原诗。 | 无陪练的个人限时挑战，建议 60 秒内答出 5 个不同的有效句组。 |
| 同机双人 | 左方、右方不限时轮流答，随时看提示与原诗，独立和辅助作答分开统计，合计作为合作成果。 | 同一题交替作答，准备好后每回合建议 30 秒，最多三小局，先获得两胜的一方获胜。 |

四种玩法均可选上表任一组合。人数控制行动方和交接，目标控制计时、提示和成绩，玩法控制题卡及合法句集合。组合共用一个对局规则模块与页面布局。

在开局的目标选项下直接解释差别。选「学习」显示「不限时 · 可看提示和原诗」，有单机陪练或双人合作时补充相应说明。选「竞技」显示「单机 60 秒答 5 句」或「双人每回合 30 秒 · 最多三小局」，并说明原诗在赛后回顾，局内独立作答。作答页继续用学习的独立/辅助统计和帮助按钮、竞技的计时和进度／比分区分目标。

## 四种令题

| 玩法 | 开局题卡与作答条件 | 样例 |
| --- | --- | --- |
| 单字令 | 一局固定一字，答案含该字，任意字位。 | 「月」→ 海上生明月 |
| 字位令 | 每题固定令字和句长（五言或七言）。首次按第 1 位起，提交有效句后移至下一位，最末位后回到第 1 位。题卡和回合条都显示当前字位。 | 五言「月」→ 第 1 位「月出惊山鸟」，第 2 位「明月松间照」。 |
| 双字令 | 同一个可判题句同时含两个不同的指定字，顺序不限。 | 「风＋雨」→ 夜来风雨声 |
| 主题令 | 每条有效句关联经过审核的句级主题标签，并附能解释归类的依据。 | 「思乡」→ 低头思故乡。句中直接写出思念故乡。 |

单字和字位可参考中国儿童中心所区分的简化玩法和字位玩法。双字是《诗词大会》采用过的进阶形式，具体采用同句、顺序不限为本 App 规则。央视也有数字与动物的组合主题。[中国儿童中心规则](https://www.ccc.org.cn/art/2025/4/20/art_517_229453.html) · [央视第四季介绍](https://news.cctv.com/2019/02/05/ARTIsYBqAZHzSyn08OoupeRW190205.shtml) · [花与月节目片段](https://tv.cctv.com/2024/05/18/VIDEmCG1rHL8R5X08Y9Wrryd240518.shtml) · [数字与动物节目片段](https://tv.cctv.com/2021/03/20/VIDEbX1NWl8fZ9OwkOngT7Ta210320.shtml)

### 题卡的开放条件

- 题卡按规范化的有效答案**重复组**统计，兼顾常见答案覆盖与来源分布。字面条件满足但作品或异文尚未审核的资料继续留在开发期审计清单。
- 单机竞技开局前验证至少有 5 组互不重复的合法答案，可覆盖实际要求的字位序列。双人题卡验证双方轮次和两种先手顺序，按预期完整回合数核对容量，出题门槛以内容审计和试玩结果确定。
- 字位用「计划轮次/字位 → 可用重复组」二分匹配，验证存在一条互不重复的解序列。各字位的计数同时非零仍可能重叠，开放时用独立验算或重放路径核对。玩家自由选择有效句，提交后重新检查下一步，陪练优先选不会耗掉下一位唯一答案的候选。
- 当前题卡的完整合法集合或字位用尽，进入中性结算，最后一个合法答案仍计入。双人本小局记平，单机竞技未到目标时标记题库用尽并给换题入口，保持竞技纪录不受影响。常见提示池用尽时，保留可继续使用的完整判题集合。

### 共用判题

一次提交一个由编辑按采用版本校订的诗词分句。唐宋诗通常以现代标点所标的分句或可靠的诗行边界作为依据，常见五言、七言以五个或七个汉字的一分句为单位，正文在该处印逗号或句号均可。宋词的长短句按词牌格律和语意核定，顿号、领字后的停顿可能位于分句内部。分句表保留这些内部位置，具体标点、省略或字形写法以每个分句登记的等价输入为准。

| 输入 | 判题方式 |
| --- | --- |
| 「床前明月光」或「床前明月光，」 | 都识别为同一分句，符合单字令「月」，同局只能计一次。 |
| 「床前明月光，疑是地上霜。」 | 识别为相邻两句，提示「一次输入一句」，保留输入供修改。 |
| 「床前明月光疑是地上霜」 | 本地分句表可明确识别成相邻两句时，给同样的分句提示。 |
| 双字分处同诗不同分句 | 需要重答，同一分句内同时出现两个指定字才通过。 |

判题先定位编辑登记的单个分句与允许写法，保留分句边界，识别多句时提示拆分。宋词的审核内标点按分句记录做等价处理。随后校验令题，按接受写法的实际字面检查令字；字位令只接受指定句长，按汉字 Unicode 码点计位。单双字和主题可匹配经审核的长短句。句组负责共享去重，采用版本的正文用来展示。

有效提交记录当前方、使用的句、出处、重复组、辅助状态及用时，随即更新分数、字位与回合。双方使用同一个已答集合。不同标点、繁简或异文命中同一重复组时只计一次，同一首诗的不同分句可分别得分。学习与竞技各自统计符合规则的答句，陪练发言单独标记。

| 情况 | 作答区反馈 |
| --- | --- |
| 空输入或可确定同时输入多句 | 「请输入一句完整诗词」或「一次输入一句」，保留草稿。 |
| 文本命中且令字、字位或双字不符 | 说明实际题目条件，例如「月要出现在第 2 字」。 |
| 主题未匹配审核收录 | 「这句未收录为『思乡』题的答案」，保留本地诗句的合法出处。 |
| 重复组已用 | 「这句本轮已答过」，可定位到历史行。 |
| 文本未命中 | 「本地诗库未收录，无法确认」，允许修改后继续。 |

错误输入保留原文和当前回合，竞技倒计时继续。只有有效答句会写入答题历史并更新成绩或推进回合。判题依据随包版本，局内结算区分「无可用答案」与「玩家仍可答但已超时」。

### 主题从句库生成

1. 为每个主题维护明确口径和正反例。以「思乡」为例，句子应表达对故乡的思念，或能由该句的字面与上下文解释明确的怀乡之意。
2. 先用上游作品标签及能检索的词语生成待审候选，再逐句读正文和上下文。李白《静夜思》的「低头思故乡」直接写思念故乡，可入选。「谁家玉笛暗飞声」里的「家」表示哪一家，单凭这一句和这个字不进入思乡判题集合。
3. 审核通过后记录主题 ID、采用版本的句子 ID、出处定位、依据和审核版本。上游的作品级标签用于找候选，歧义或证据不足的句子留在审计清单。学习提示和赛后回顾可以展示归类依据。
4. App 使用随包的主题 ID 到审核句子 ID 的确定性映射判题。主题证据指向原句，去重仍使用句组，只有经过审核的等价写法继承对应主题。整个过程在本地查询现成索引。当前交互稿使用少量样例，正式主题标注集将在内容整理阶段生成。

## 学习和竞技的具体规则

### 学习

- 单机默认自由作答。「陪练接一句」在本地择一条常见、合法且未用的句子，推进字位和已用集合，计为陪练发言。普通提交后可继续作答。陪练候选优先常见诗句，降低同篇和近期重复出现的机会，角色没有可用候选时提示「暂时没有陪练句」。
- 同机双人轮流答，成功提交后收起键盘，显示下一方的交接页，点击「准备好了」进入作答。双方各自的有效数等于独立数加辅助数，并展示合计。结束学习进入回顾。
- 学习无时间限制，可多次求助，同一回合反复打开显示同一批候选。提示最多显示 3 个当前可用的句子。展示成功后，这些候选的重复组进入本局共享辅助集合。已展示未使用的候选仍可作答，也可在后来明确换一批提示时排除已曝光组。没有新候选时保留当前回合。
- 提示弹窗每个候选都提供「展开原诗」和「填入输入框」。原诗默认折叠，点开后在原候选下用同一弹窗展示篇名、作者、正文和对应句，主题令同时显示归类依据。一次只展开一个候选，点别条自动折叠前一条，展开后仍可折叠或选择填入。长正文在弹窗内滚动。退出弹窗保留草稿，主动填入才替换草稿，发送仍由玩家确认。
- 学习可点历史气泡查看采用版本的原诗全文。展开原诗时，只把实际展示的可判题句组加入共享辅助集合，尚未展开的内容保持原状态。关闭或折叠不清空辅助标记，也不刷新本回合候选或改变草稿。提示或原诗公开后，单机或任一方提交已曝光的句组均计辅助，换人和恢复都保留该标记。已提交的成绩按提交当时判定。
- 用户主动结束或本题用尽后显示回顾。学习记录可查看有效句、独立/辅助数量及诗词出处，按人数和玩法保留。双人统计按本局左右方显示。

### 竞技

- 单机建议采用固定题目的 **60 秒 / 5 句** 个人挑战。点击开赛或倒数结束后开始计时，界面显示剩余时间和有效进度。到达目标则保存完成用时，超时则展示有效句数。成绩按题卡、计时、目标、规则和词库版本可比的配置存档，完成纪录以用时较短者为佳。
- 同机双人采用 **30 秒 / 回合，至多 3 小局**。开局明确谁先答，每小局交换先手。有效发送结束本回合，下一方点「准备好了」后开始自己的 30 秒。交接、局间结算与暂停都停止计时。整场沿用选定题卡，每小局独立维护已用答案。
- 当题卡仍有未用有效句时，当前方超时或主动「接不上」判对方赢该小局。题库耗尽的小局记平，占用一小局名额。先获得 2 胜立即结算，最多 3 小局结束后按小局胜场比较，同胜场为平局。对局内一直显示左右小局比分和当前方。
- 局内关闭提示、陪练和原诗全文。回顾界面统一开放出处和原诗。主动退出整场时可选择保存进度返回，或确认结束竞技，后者标为中止，保留已发生事实供回顾。
- 竞赛创纪录、更新小局结果、进入交接与结算等操作单次提交，恢复后复用已持久化结果。计时使用前台单调时钟，保存当前阶段与剩余时间。真正后台或用户主动暂停时隐藏题卡和输入，在明确点击「继续」后恢复倒计时。输入法弹出、错误通知以及确认「接不上」前的等待正常计时。与期限重合时，以规则层收到提交的时刻和固定边界判定，避免重复结算。

### 图标与界面

飞花令共用一个圆角方形「诗」印记，使用低饱和朱砂色细描边和居中的「诗」字。大厅浅绿游戏卡用 64–72 UI px 大标，交互稿按 64 px。游戏顶栏在居中「飞花令」标题旁使用 24 UI px 小标。两处保留相同笔画和字形，字号与描边按实际显示尺寸调节。印记用项目现有的圆角控件及中文字体绘制，无需打包独立图标资源或字体。

大厅是浅色界面，采用 `UiFactory` 的纸面色 `#F6F4EC`。飞花令交互稿也固定为浅色，使用米白底、白色内容面和浅色控件。`#276653` 用于小图标、描边等局部强调。诗句历史采用白色与浅绿气泡，左右位置和文字标明当前方。沿用合集的无衬线界面字体、圆角按钮和导航布局，声音与触感在共用设置中切换。[公共界面配色](../Assets/Scripts/Runtime/UiFactory.cs) · [成语接龙布局参考](../Assets/Scripts/Runtime/Idiom/Presentation/IdiomPage.Layout.cs)

比分、令题和按钮位置在状态切换时保持稳定。作答区以「发送」确认输入，中文输入法候选确认、失焦及返回键用于各自的键盘交互。短屏、长屏和大字号均要验证题卡、输入栏、倒计时、历史和弹窗可阅读。

## 离线诗库与包体预算

上游优先使用 `chinese-poetry` 的唐诗、宋诗、宋词。在 2–3 万首作品中兼顾常见选集、各题卡覆盖及题目间多样性。用《唐诗三百首》《宋词三百首》作为常见子集整理起点，陪练、提示优先用这个子集，判题覆盖经校订的整份随包诗库。运行期可查篇名或词牌、作者、原诗和有许可且已核实的解释。发布前保留出处、固定版本和许可记录。MIT 文件对应仓库授权声明，现代译文、注释等内容逐类核对再纳入。[上游仓库](https://github.com/chinese-poetry/chinese-poetry) · [LICENSE](https://github.com/chinese-poetry/chinese-poetry/blob/master/LICENSE) · [《唐诗三百首》](https://github.com/chinese-poetry/chinese-poetry/blob/master/%E5%85%A8%E5%94%90%E8%AF%97/%E5%94%90%E8%AF%97%E4%B8%89%E7%99%BE%E9%A6%96.json) · [《宋词三百首》](https://github.com/chinese-poetry/chinese-poetry/blob/master/%E5%AE%8B%E8%AF%8D/%E5%AE%8B%E8%AF%8D%E4%B8%89%E7%99%BE%E9%A6%96.json)

上游有繁简异体和正文错误，亦可能将多个句子放在一个 `paragraphs` 元素里，部分选集只有作品级标签。在开发期校订分句与正文，审核具体异文，标记需隔离的错误或歧义。主题令直接映射审核过的句组和归类依据。随包产物记录作品 ID、句 ID、重复组、索引与来源，生成过程固定输入版本和校验摘要，可重复导出和审计。[唐宋诗数据说明](https://raw.githubusercontent.com/chinese-poetry/chinese-poetry/master/%E5%85%A8%E5%94%90%E8%AF%97/README.md) · [宋词结构](https://raw.githubusercontent.com/chinese-poetry/chinese-poetry/master/%E5%AE%8B%E8%AF%8D/README.md)

正文只存一份，每个答题句以作品内的位置引用正文。规范化别名映射到句组。单字使用字符倒排，字位用句位置过滤，双字取两个倒排集合的交集，主题使用紧凑的标签索引。小题卡索引附可用组数量和审核标记，数据按需加载，原诗详情分片。开发期获取数据，普通构建使用已生成的本地资源。App 安装包自带可用全量，更新通过安装新版本交付。

**12 MB 包体目标采用十进制，即约 12,000,000 字节的正式 ARM64 APK 增量。** 调研对上游固定提交 `b8594f81` 抽取了 12,878 首作品，粗切 124,890 个候选片段。作品、句位置和字符索引分别 gzip 压缩后约 1,535,903、43,240、944,421 字节，合计 2.52 MB。候选片段数量是抽样数据，最终可用句数以清洗和人工审核为准。[固定上游文件树](https://api.github.com/repos/chinese-poetry/chinese-poetry/git/trees/b8594f81a89752241442f2ce267d6f66f96704ee?recursive=1)

按 2–3 万首精选、复用现有字体及音效、额外计入繁简异文、句级主题标注和代码/界面资源估算，**正式 APK 增量为 6–12 MB**。v0.9.8 正式发布附件的文件大小为 233,816,837 字节，若以此作演算参照则约 239.8–245.8 MB。此处标明下载包大小。安装占用、冷启动、峰值内存和最终 APK 增量在正式接入时分别实测。[v0.9.8 Android 正式发布](https://github.com/duanyao-0516/XanaduYonder/releases/tag/v0.9.8)

在同一主线基线上用同版本 Unity、ARM64、IL2CPP、构建选项和打包流程分别生成两份 APK，记录精确字节差和内容拆分。包体增加接近预算时先检查重复正文、被打进包的原始文件、冗余索引和重复资源，再按题卡覆盖调整精选范围并保留 2–3 万首目标。安装之后所有玩法、首次进入和资料查看均须通过飞行模式验收，并核对最终 Android manifest。

## 技术接入和存档

| 位置建议 | 责任 |
| --- | --- |
| `Assets/Scripts/Core/Feihualing/` | 诗句和重复组、有效句集合、令题、动作和回合、计时边界、提示、陪练与结算，生成可持久化快照。 |
| `Assets/Scripts/Runtime/Feihualing/` | Unity 页面、详情与回顾、资源加载、输入桥接、存档与生命周期。 |
| `Assets/Resources/Feihualing/` | 随包索引、原诗详情、版本和许可。 |
| `Data/Feihualing/` 与导入脚本 | 固定来源、校订及主题人工标记、版本清单与可复现导出。 |
| `Tests/Feihualing/` 等 | 生产规则、持久化、数据契约和 Unity 交互回归。 |

现有研究基线的 `AppController` 把输入法前台例外绑定 `Page.Idiom`。接入时将键盘可见且游戏仍在前台的共性限定在共享输入桥接，飞花令自己的状态拥有作答、暂停与恢复权限。进入、离开和销毁成对管理 UI、输入监听与异步加载。按下 Home、后台切换和原生输入法抢焦应分别判断。

建议使用独立 `feihualing-v1.json`，以「人数 × 目标 × 玩法」作为续局槽位，最多 16 份独立活跃局，当前题卡包含在该槽快照中。保存活动方、阶段、已用组、提交记录、草稿、词库/规则版本、提示与曝光组、陪练状态、剩余时间和比分。竞技纪录另按可比较的完整配置区分，书写数据落盘时与它依赖的结算状态同事务提交。新局只覆盖所选槽位。对局信息有效性包含题卡、作品引用、阶段、计数和计时范围的一致性。

存档先写同目录临时文件、flush，再原子替换。仅校验通过的主档可更新备份。坏档、资源缺失、旧版本 ID 无法映射时原文件留存，显示恢复或重新开始的明确选择。规则正确生效但写入失败时保留内存对局与草稿，显示未保存和重试，重试持久化同一快照。对局版本变化应借稳定 ID 和明确迁移规则处理，成绩按其历史版本保存。

## 接入验收

1. **数据**。固定版本可复现导出、2–3 万首精选有效去重、每作品/句/重复组/别名关联合法、繁简和异文审批、句级主题正反例和审核理由、题卡和字位路径有独立验证、字体覆盖及包体统计。
2. **规则**。16 种组合都有开始、正确提交、错误重试、终局和恢复的用例。重点验证独立五七言分句、等价句末标点、整联或多句拼接的拆分提示、可含内标点的宋词长短句、跨方去重、字位推进、同句双字、主题判定、公开曝光跨回合统计、陪练和提示用尽，以及题库实际耗尽的中性结算。
3. **竞技和持久化**。用可控时钟验证交接后才计时、暂停或后台后恢复、截止边界、连点提交、双方交换先手、三小局及中性平局，成绩写入与恢复幂等。验证 16 槽、主备损坏、写盘失败、词库升级以及强杀恢复。
4. **交互和离线**。检查大厅大印记与标题旁小印记的字形、识别性和样式一致性，验证真实中文输入法、长短屏、安全区、键盘返回、弹窗和焦点。验证当处展开候选原诗、单项展开、折叠、填入和关闭后保留草稿，辅助标记与实际呈现一致。飞行模式下新安装首次进入、提示、陪练、竞技回顾和续局。检查 Android 正式 APK 的网络权限和资源集成，做同配置包体对照。回归大厅和原有游戏的接入及存档。

当前完成调研、样本压缩测量和可点击交互稿。交互稿使用少量示例诗句，在浏览器中验证了 16 种组合的开局和首次提交，以及提示、原诗、辅助标记、换人、暂停续局和小局结算等路径。正式库筛选、持久化实现、Unity/Android 构建及真机验收属于产品实现阶段。
