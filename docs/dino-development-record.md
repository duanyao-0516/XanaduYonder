# Dino 开发记录：规则、问题与维护规范

日期：2026-10-28。本文件把 Dino 从方案讨论、手机适配、实机反馈到 Chromium 规则对齐和主线交付的经验整理为后续开发入口。**现行规则以本文和生产源码为准；早期设计中的反应窗口限速、四倍高速和额外恢复间距已经被替换。** 每轮测试、APK 指纹与设备操作见[验证记录](verification-dino.md)，不能把旧构建的结果当成后来版本的验收证明。

## 1. 最终产品约定与方案演进

Dino 是源码大厅第九款离线游戏，稳定标识为 `dino`。名称统一为 **Dino**，页面沿用 2048、跳一跳的字体、颜色、图标和排版体系。进入后先选择横屏或竖屏；两种方向共用核心规则，按实际可见宽度调整初速，共用速度相关的障碍间距公式，分别保存最高纪录。

| 开发阶段 | 经验与最终决定 |
| --- | --- |
| 经典像素方案 | 保留原版角色、仙人掌、翼龙和地平线的辨识度，手机上提供跳跃、下蹲和暂停 |
| 横竖屏选择 | 窄视野天然缩短观察时间；提供横屏选择，按实际跑道宽度计算规则，不按手机型号或屏幕方向写两套游戏 |
| UI 多轮反馈 | 先复用已有游戏的规范，再安排分数、紧凑跑道和下方触区；不能把 PC 小画布放在屏幕顶部就算完成手机适配 |
| 加速试验 | 曾采用自定义加速、反应窗口约束和四倍高速；用户随后决定整体对齐 Chrome，这些实验参数不再生效 |
| 原版规则对齐 | 固定版本源码、单位换算、逐帧取整和事件顺序一起移植，不能只抄 `speed` 与 `acceleration` |
| 白边与碰撞 | 夜间真正反色原图 RGB；采用官方细分碰撞框并加连续扫掠，撞停时画面停在首次接触位置 |
| 地面与连跳 | 地面改用与仙人掌一致的取整行程；输入层统一实现持续按住后的落地续跳 |
| 入口闪屏 | 删除 Dino 的临时调整页，并修复合入主线后 Zuma 的画面交接、旧输入和跨游戏方向抢占问题 |

保留的产品差异包括：手机方向选择与双纪录、触屏持续按住连跳、每 30 秒有效运行时间切换昼夜、节日帽及农历生日横幅。没有接入慢速／音频辅助模式、特殊收集模式或联网服务，也不承诺和所有浏览器刷新率下的 Chrome 逐帧相同。

## 3. 模块责任与状态所有权

| 层 | 负责 | 不应承担 |
| --- | --- | --- |
| `Core/Dino` | 固定步、运动、障碍生成、碰撞、行程、得分和随机状态 | Unity UI、设备日期、系统方向、磁盘和声音 |
| `DinoPage` | 页面状态、方向流程、输入命令、暂停恢复、记录保存时机与宿主回调 | 复制另一套跳跃或障碍算法 |
| `DinoViewport` / `DinoPageLayout` | 安全区、世界与设计单位换算、跑道和触区布局 | 根据 UI 喜好直接修改碰撞框 |
| `DinoTrackView` / `DinoCelebrationHat` | 像素场景、地面、昼夜、帽子和碰撞终态的显示 | 推进模型、生成障碍或改变分数 |
| `DinoActionOwners` / `DinoTouchControl` / `DinoRunClock` | 动作所有权、取消、固定步与倒数 | 将后台时间补进游戏 |
| `DinoSaveData` / `Codec` / `Store` | 严格协议、合法备份和原子写入 | 读取或覆盖别的游戏存档 |
| `AppController` | 大厅路由、共享设置、宿主生命周期和跨页面交接 | 让未激活游戏持续控制当前屏幕方向 |

`DinoTraversal` 是编辑器／测试诊断工具。生产生成器不读取其规划结果，也不据此筛选障碍。模拟玩家通过一组种子只能证明该组回放，不能证明任意随机长序列自动通关。

## 4. 速度与视野：必须同时写清单位和更新顺序

参考源码的 `speed` 是每个 60 Hz 参考帧的原图逻辑像素数。模型用 `SpriteScale = 1.35` 换成世界单位，页面再按 1.2 换成设计单位。短边采用 720 设计单位基准；实际设备像素不能直接代入规则公式。

普通模式初速：原图视野宽度 `W < 600` 时为 `min(6, 6 × W / 600 × 1.2)`，否则为 6。每个有效固定步加 0.001，严格封顶 13。世界速度为 `speed × 60 × 1.35`。

| 典型跑道 | 标称初速（世界单位/s） | 地面／仙人掌实际初速 | 最高速度 | 到顶所需有效运行时间 |
| --- | ---: | ---: | ---: | ---: |
| 竖屏 656 设计单位宽 | 393.6 | 324 | 1053 | 8141 步，约 135.68 秒 |
| 宽横屏，原图视野至少 600 | 486 | 486 | 1053 | 7000 步，约 116.67 秒 |

竖屏换算为约 546.667 世界单位、404.938 原图单位。以上是当前布局的公式结果，不代表所有窗口尺寸都相同。暂停、倒数和后台不计入加速时间。

标称速度与植物的实际速度不同，是因为原版障碍每帧移动取整：`floor(speed + speedOffset) × 1.35`。地面与仙人掌的偏移为 0；翼龙保留 ±0.8 的原版差速。低速阶段会出现离散速度台阶，不能直接拿计分距离当作地面位移。

源码的加速增量按有效更新回调次数累加，并未乘 `deltaTime`。在理想 120 次回调/s 下，到顶时间可能接近 60 次的一半；这解释了只凭不同设备“感觉加速快慢”反复改参数的不可靠性。本项目明确固定 60 Hz，保证 30／60／120 Hz 显示驱动下规则一致，最高值也不沿用源码可能略超出一个增量的行为。官方依据见[配置研究](dino-chromium-config.md)；该研究后半的“当前实现”对照表记录的是当时 `bd7acb6`，不是本次交付的现行参数。

障碍最小间距为 `round(整组原图宽度 × speed + 类型 minGap × 0.6)`，最大值为最小值的 1.5 倍再取整，最后在闭区间随机取整数。仙人掌 `minGap=120`、翼龙 150；同类型最多连续两组，仙人掌最多三株。小／大仙人掌组合分别从速度 4／7 开放，翼龙从 8.5 开放；开局超过 3 秒后生成障碍。移动端翼龙只生成两档高度。横竖屏共用这些规则，没有额外的反应窗口限速、0.25 秒恢复间隔或按运行秒数解锁的障碍阶段。

## 5. 跳跃、输入和暂停不是一件事

`DinoMotion` 保留原版左上原点语义：站立顶点 y=93；起跳速度 `-10-speed/10`，先将速度四舍五入累加到位置，再加重力 0.6。达到最小上升高度后松开才允许截短上升至 -5；最高高度参数 30 是绝对 y 门槛，不是“最多跳 30 像素”。空中下蹲先进入 speed-drop 状态，位移倍率为 3。更新顺序、取整、门槛和事件时机与常量同样重要。

页面维护 Jump、Duck 各一个 owner。跳跃按钮、跑道、空格和 ↑ 共用 Jump；其他手指不能抢占或排队。只有当前 owner 的松开、滑出或取消才能释放动作，跳跃释放不能顺带释放另一根手指的下蹲。

核心 `Jump()` 始终是一次命令。页面在持续按住时每个固定步尝试起跳，落地后第一个可跳步接续，且只有接受起跳才播放声音。空中短按后松开不排队；空中开始持续按住可以落地续跳；下蹲优先。Chrome 桌面原本依赖系统重复 keydown，手机触屏连跳是本项目为一致操作补充的行为。

暂停、帮助、设置、失焦、导航和重建时先保留本局运动状态，再清理物理输入 owner。继续前倒数三秒，不恢复旧手指的连跳。当前跳跃轨迹可保留，继承的蹲姿按明确规则解除，不能通过伪造 pointerUp 改写暂停前的运动。单帧超过 100 ms 时暂停，不突然补算积压时间。

## 6. 白边、碰撞和地面滑动的根因

| 反馈 | 根因 | 现行修复与回归重点 |
| --- | --- | --- |
| 夜间角色／植物周围有白圈 | 原图存在不透明白色描边；只乘颜色不能把它变成夜色 | 每个 view 生成 RGB 反色纹理，Alpha 不变；83→172、255→0。白天回原图，帽子保持彩色；退出释放派生纹理 |
| 看起来未碰到就结束 | 大矩形、组合障碍错误拼框及碰撞后显示位置会放大观感差异 | 官方各边内缩 1 像素外框加细分矩形；组合仙人掌延展中框并平移右框，不平铺单株框 |
| 高速跨帧碰撞／撞停错位 | 离散终点判定与最终整帧渲染位置不一致 | 连续扫掠结合外框门限，取所有障碍最早接触比例；角色和场景在同一比例停下；仅碰边不算重叠 |
| 地面比植物滑得快 | 地面使用未取整的计分距离，植物逐帧向下取整 | 独立累计 `GroundDistance`，和仙人掌使用相同位移及碰撞比例；计分与天空仍保留各自语义 |
| 角色浮在地平线上 | 仅按可见图像底边对齐忽略原图地面关系 | 使用完整平地／小丘片段，地平线与脚部下方交叠约 8～9 原图像素；小丘不参与碰撞 |

UGUI 圆角裁剪会缓存派生 stencil 材质，昼夜使用各自稳定材质，不能只修改基础材质后假定遮罩内已更新。派生纹理采用 Point/Clamp，上传后可释放 CPU 副本，销毁 view 时清理自有资源。

官方细分框仍是轮廓近似，不能宣传逐像素碰撞。回归应包含擦边、组合植物、不同高度翼龙、空中下落、落地边界、下蹲撞停和部分帧地面位置；单张角色截图不能证明判定正确。碰撞后的分数沿用已完成固定步行程，不为渲染插值再加分。

## 7. UI 和页面交接规范

竖屏跑道为 656×320 设计单位，横屏两侧各留 32；文本／导航沿用 56 单位边距。跑道用紧凑圆角矩形，内部白天纯白、夜晚纯黑，外部沿用 APP 纸色。不能为主题统一把游戏内部也染成 APP 颜色。

方向选择卡带屏幕示意、独立纪录标签和加粗换行数值，开始按钮靠近下方拇指操作区。竖屏为小下蹲／大跳跃与加粗暂停；横屏暂停视觉中心和两侧操作按钮对齐。玩法入口用顶部图标和暂停菜单，移除底部重复说明；更换方向放在暂停／结算中。帮助弹窗主按钮到底边为 32。短窗口要真实检查滚动与可达性，不把内容压成重叠布局。

返回层级是游戏页 → 方向选择 → 大厅，进行局先确认结束。方向偏好只在成功进入准备页后保存。进入 Dino 直接显示正式方向卡；真实转向时冻结模拟和旧输入、保留当前页，实际方向与安全区稳定两帧后同一次交接显示新页。三秒超时才进入可重试错误状态，系统返回可取消。

合并主线后同时发现 Zuma 两类交接问题，形成以下共同规范：

- **显示交接与方向请求分开。** 新页面完整可见后通过 `PresentationReady` 交出旧画面；退出也在竖屏准备完成后交回大厅。提前隐藏宿主、提前销毁旧 Canvas 都会产生空白间隙。
- **保留画面必须同时冻结输入。** 仅关闭 `GraphicRaycaster` 不足以阻止键盘 Submit/Move 或缓存的 pointerUp/click。禁用标准 Selectable 及自定义按压组件，清理选择和按压；保留期间禁用颜色过渡，避免按钮突然变灰。
- **仅当前页面拥有方向。** 未激活 Zuma 的焦点恢复回调不能强制竖屏，否则会破坏横屏 Dino。重复返回、过期回调、取消和退出必须有状态／token 保护。
- **真实加载与装饰性临时页分清。** 成语词库的异步加载和分批解析仍在正式页内提供进度；此次没有删除实际加载逻辑、冷启动标识或正常模式选择页。

Editor 不能可靠模拟原生 `Screen.orientation` 的读写结果。方向自动化应注入请求边界，断言谁发出了什么命令；是否真正转向仍需 Android 检查。OPPO 本轮拒绝录屏写文件，因此验证记录只报告实际操作、截图和 Unity 对象交接，不宣称测量了每一个显示帧。

## 8. 昼夜、节日和不可等到当天才测的 UI

每 30 秒有效奔跑时间切换一次昼夜，过渡 0.8 秒；暂停、倒数、结束冻结，重开回白天。这是已确认的产品规则，不是 Chromium 按里程触发夜间的原公式。

| 日期 | 帽子／横幅 |
| --- | --- |
| 公历 1/1、5/1、10/1–7 | 红金节庆帽 |
| 农历正月初一至初七、五月初五、八月十五 | 红金节庆帽 |
| 公历 10/31、12/25 | 万圣紫帽、圣诞红帽 |
| 农历四月十五、五月十六 | 生日派对帽，方向选择页显示「生日快乐」 |

离线使用设备本地日期，在每次从大厅进入时采样；重开和窗口重排保持本次装饰。生日优先，其次万圣／圣诞，再到普通节日；农历闰月不重复触发，日历支持范围外仍可计算公历节日。这是固定庆祝日期，不是每年法定放假／调休表。帽子不影响碰撞、跳跃、速度与纪录。

使用可控日期和真实生产 UGUI 渲染覆盖四类帽子的白天／黑夜；另以生日帽验证跑／跳／蹲／结束的共享姿态跟随逻辑，并检查生日入口及窄窗口，没有逐一截图验收所有帽子、姿态和昼夜的完整组合。2026 年两个生日样例为 5 月 31 日和 6 月 30 日。验证不修改手机系统日期，也不在生产页面留调试按钮。截图及其受控数据说明见[UI 预览记录](dino-ui-preview.md)。

## 9. 存档与数据保护

独立文件为 `Application.persistentDataPath/dino-v1.json`，schema 1，`gameId=dino`；横／竖屏最高分是非负 64 位整数的十进制字符串，方向为 `portrait` 或 `landscape`。当前局仅保存在同进程内存中，主动退出或进程重启不恢复上一局。公共声音／触感不复制到该文件。

Codec 拒绝缺失、null、错误 token、负数、溢出、重复键、额外字段和未知版本；限制 4 KiB、深度 4。主档不可用时读取合法 `.bak`，均不可用则提供零纪录和竖屏默认值，并区分需要提示的损坏／读取失败。写入先 `.tmp`、flush、原子替换；只有合法主档才更新备份，损坏主档不能污染最后一份可恢复数据。

新纪录每秒最多写一次，碰撞、暂停和离开立即补写；写入失败仍可游玩并显示未保存提示。没有生命周期回调的强杀可能丢失最近约一秒纪录。规则曾调整，但不擅自清空既有最高分，也不宣称新旧分数具有相同难度含义。

## 10. 工作树、构建和设备规范

开发工作树为 `chrome-dino/XanaduYonder`，分支为 `p/duanyao.0516/feature/chrome-dino`。脚本从自身位置解析项目根目录，不能切换到主 checkout 或借用其他游戏的 Library、构建目录和待提交文件。

```bash
# 从当前工作树构建独立测试包
```
