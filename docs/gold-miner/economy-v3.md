# 黄金矿工 v3：累计目标调整与验证

日期：2026-10-28。范围：累计资金目标、旧档兼容、离线见证和经济测量。保留累计钱包判定及商店扣款；没有修改矿物价值、数量、碰撞、回收速度、商店价格或增益。完整原始输出由 `scripts/test-gold-miner-balance.sh` 重建到 `artifacts/validation/gold-miner/balance.json`；本次稳定摘要见 [economy-v3-measurement.json](economy-v3-measurement.json)。这些是固定模拟策略的数据，不是人类胜率。

## 1. 问题与采用的曲线

结算比较的是 `Cash >= Target`，商店花费从 Cash 扣除，下一关继承剩余 Cash。旧目标增长低于正常连续采矿收入；真实 v2 手机存档在第二关结束已有 3680，进入第三关的旧目标只有 2550，开局便能过关。旧见证搜索一旦满足最低收入就停止出钩并等到结算，因此 `endTick=3600` 只表示见证运行到了截止时间，不能证明玩家必须认真挖满 60 秒。

新挑战的第三关目标为 5100。已有旧挑战整条流程保留旧曲线：真实 3680 钱包从旧第二关成功页进入第三关时，仍使用 2550；只有重新开始挑战才使用新曲线。这样既不改变已经接受的目标，也不会让旧挑战在后期因累计资金基线突变而进入必败关卡。

## 2. 旧档与事务边界

- `rulesVersion` 升到 3，`schemaVersion=1`、目录格式及 `gold-miner-v1.json` 文件名不变。Runtime Codec 无新增字段。
- 完整校验 v1/v2 后，Session 只在自己的副本把根版本升为 3；双槽、金额、道具、剩余时间、在途物、随机流、命令/事务序号和检查点不变。正常写盘保留原字节 `.bak`。
- v1/v2 的 current target 必须属于旧曲线。v3 的 current target 只能是同模式同关卡明确的旧或新目标；2551 等任意金额仍拒绝。
- 检查点不新增重复 target 字段。重试由 Session 把已有 current target 显式传给 `CreateState`；进入下一关时根据当前目标所属的旧/新曲线继承同一条曲线，只有新挑战默认使用新曲线。根 rulesVersion 仍为 3，两个模式槽位可以分别保留旧挑战或新挑战。
- 历史记录没有单独的规则版本，最低合法总收入继续按旧曲线验证；当前关卡的成功/失败仍严格按自己保存的目标判定。不会因新门槛抹掉原本合法的成绩。

持续测试包含五份既有 v1 真机快照和两份新增 v2 真机快照：`v2-solo-won-coop-failed.json`、`v2-solo-loaded.json`。新增夹具分别原样来自 `artifacts/gold-miner-refinement-20261028/device/after-selection.json` 与 `emulator/migrated-before-play.json`。测试逐字段证明升级只改 rulesVersion，并覆盖 Running/Failed 重试保留旧目标、旧 Won→Shop→第三关 3680/2550、该关重试和新挑战 0/1200。另对 v1/v2/v3 载体、单人/合作、全部九种跨关边界共 54 个组合验证旧曲线、商店消费、增益、重载、重试与历史记录；新 v3 挑战继续使用新目标。

独立复核曾复现：合法 v2 单人第九关以 15150 过关，若下一关直接换成新目标 30400，就需再获得 15250；实际第十关即使瞬间清场且所有袋子均为 500，收入最多只有 8680。`RequiredIncome` 证明的是同一条新曲线相邻关卡的差额，不能证明旧资金基线切换新曲线。修复因此保留整条旧挑战曲线，不增加资金、不修改商店和矿图；该第九至十关边界包含在上述回归中。

## 3. 240 图重新证明

`Tests/GoldMinerLevels/RefreshWitnesses.cs` 的 `--refresh-witnesses` 在既有矿图上搜索真实输入，不重新生成坐标。240 张图的 ID、pattern、variantSeed、实体、坐标、类型、袋子保底和初始方向均与 v2 逐字段相同，换图数为 0。

330 次有界策略尝试找到全部 240 份成功输入，单图最多尝试 23 次；本次未用到备用 beam 搜索。每份输入必须经过生产 `GoldMinerPlanner.ReplayWitness`，验证实际碰撞、回收、入账、截止输入及 Session 成功结算，才写入分片和 SHA-256 目录。搜索记录明确标记 `existing-geometry-reproof`，没有把重放时间记成原始生成时间。

## 4. 测量方法和实际限制

持久工具位于 `Tests/GoldMinerBalance`，运行生产 Core，测试层只选择输入：coarse 每 300ms 判断一次，角度误差 ±4°，响应概率 70%；focused 每 100ms，±2°，95%。瞄准当前可能抓到的价值至少 100 的物件，没有未来路径优化。每图每策略五个固定种子，共 2400 局；无道具、袋子保底。2400 个收入结果与修改前控制组逐项一致，说明收入变化没有混入本次目标调整。
