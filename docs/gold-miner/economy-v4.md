# 黄金矿工 v4 数值与兼容

2026-11-08。本次调整原生 Unity 黄金矿工；独立 ClassicGoldMiner H5 不改。实现依据本仓经典源码和现有原生 Core，不将自动策略成功率解释为人类胜率。

## 参考与保留边界

经典 solo 的 `game.js:5817-5835,6112-6202` 和 duo 的 `game-data.mjs:1-41` 提供矿值、商店与增益参考。两种经典游戏并不共用全部规则：solo 商品独立随机出现、部分价格随关卡扩张且允许欠款；duo 每次随机三类、检查余额。原生继续累计钱包判定、购物扣款、不可欠款、10 关、每关 60 秒和倒计时结束后完成已发射动作。

原生矿物面值采用经典共有比例：小/中/大金为 50/100/500，小/大石为 11/20，钻石 600，普通/携钻鼹鼠为 2/602。旧 profile 保留 100/250/500、20/50、600、30/630。

福袋仍只给 100/250/500：普通概率 60%/30%/10%，幸运草 20%/40%/40%，期望值分别 185/320。保留一次选图抽值、重试不重抽及独立 bagRng。力量使带载回收速度 ×1.5，石头书 ×3，钻石油给钻石及携钻鼹鼠 +300；四种增益只影响下一关且重试保留。未移植经典福袋的临时力量/炸药分支。

物理数值保持现状：60 Hz，摆角 ±80°，摆速 π/3 rad/s，伸出 7.2、空回 5、带载基础速度 2.4 世界单位/s；带载除以对应重量。各物件重量、半径、动物速度、地图数量和实体坐标未变。初始每玩家 1 炸药、个人上限 9 不变。

## 旧档与验证

规则版本升至 4，schemaVersion 和文件路径保持 1。v4 槽位新增必需的 balanceProfile。旧 v1/v2 完整校验后推导 legacy；旧 v3 按该槽既有目标推导 legacy/native。新版本拒绝缺失、未知、与目标不匹配的 profile，也拒绝旧版本夹带新字段/新目标。迁移不得改写余额、已收物件账本、商店原价、购买分配、在途钩或检查点；每个旧 run 一直到结束都保留旧矿值、旧货架价格及所属目标曲线。新开局才进入 classic。两槽可以使用不同 profile。

已执行纯 .NET 验证：Core 53 组；Persistence 32 组（真实 v1/v2 夹具、旧 v3 两模式逐关续关/重试/收获、严格字段与真实文件 IO）；Catalog 22 组（2000 固定种子选图）；Levels 9600 检查（240 张原图真实 Core 见证、30 组完整生成重现对）；Campaign 1137 检查（两模式各 10 关、不购物主线和首店全货购买后的失败/重试分支、78 次落盘事务、8 次重载）；Input 54；Assets 595。

见证刷新命令为 `scripts/test-gold-miner-levels.sh --refresh-witnesses`，只更新 witness、rulesVersion 和内容哈希；实体位置、类型、数量、variantSeed 未变。全量验证命令为 `scripts/test-gold-miner{,-persistence,-catalog,-levels,-campaign,-balance,-input,-assets}.sh`。机器报告位于 `artifacts/validation/gold-miner/`，其中 balance.json 记录固定误差策略的逐图收入和三 profile 的购买/不购买连续挑战；这些策略不代表玩家胜率。

规则阶段证据与后续集成验证分别记录，完整 Unity/设备范围见[本轮说明](../gameplay-polish.md)。没有重新绘制地图或改变抓钩物理；没有修改 ClassicGoldMiner H5 的数值或存档。
