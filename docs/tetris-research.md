## 原始玩法调研（2026-10-28）

本节保留方案形成时的资料、建议和模式比较；实际首版范围及参数以随后“首版现行规则”和工程契约为准。

### 基础循环与乐趣

七种四格方块 I、O、T、J、L、S、Z 依次下落。玩家移动和旋转它们，填满横行后消除，上方堆积随之下落；堆积过高导致结束。判断空间、保持平整、避免空洞、为长条保留位置构成持续决策，逐渐加速增加后期压力。[Tetris 官方介绍](https://play.tetris.com/about)

采用现代常见的 **10 列 × 20 行可见棋盘**。顶部生成区另由规则模型管理，不能因为活动方块经过最上排就立即判负。[Tetris Effect 官方站发布的社区入门指南](https://tetriseffect.game/beginners-community-guide/)

核心循环为：生成 → 移动/旋转/下落 → 触地调整 → 锁定 → 同时清除满行 → 更新分数与速度 → 生成下一块。无消行时仍正常进入下一块，不能给空洞自动补齐，也不做连通区域三消。

### 影响手感的规则

| 机制 | 含义 | 本项目建议 |
| --- | --- | --- |
| 七袋随机 | 七种方块各一个组成一袋，洗牌后逐个取出，再开启下一袋 | 采用；缓解长时间等不到某种块的挫败。不是任意连续七块都各不相同 |
| 双向旋转 | 顺时针和逆时针分别转 90° | 均支持，避免只能靠连点三次代替一次逆转 |
| SRS 与踢墙 | 原地旋转受阻时，按旋转状态尝试规定的位置偏移 | 采用成熟的旋转方式，I 与其他块的偏移规则分别定义；禁止临时写成「撞墙就平移一格」 |
| Next | 看后续方块以安排落点 | 显示未来 3 块；3 是本项目的信息密度选择 |
| Hold | 暂存一块，已有暂存块时交换 | 当前活动块落锁前最多使用一次；用完置灰，下块再恢复 |
| Ghost | 预览当前块直接落下的位置 | 默认显示清晰轮廓，与已落定块区分；从同一碰撞结果派生 |
| 软降 | 按住时加速，触地后仍有短暂调整机会 | 独立向下按钮，松开恢复当前等级的自然速度 |
| 硬降 | 立即落到最低合法位置并锁定 | 独立「立即落下」按钮，触发一次，不长按连发 |
| 锁定延迟 | 触地后留出少量移动和旋转时间 | 候选 0.5 秒，并限制可重置次数，避免无限拖延 |

七袋的含义由 [Enhance 官方活动说明](https://www.tetriseffect.game/tournaments-events/tetris-40th-community-showcases/)明确解释。Next 与 Hold 的用途、暂存一块及不可连续重复交换见 [Nintendo 发布的玩法说明](https://www.nintendo.com/jp/topics/article/e8b69d6f-4951-4328-8da9-fb4c42d37fb1)。SRS 的概念见上述 Tetris Effect 社区指南；该页面并非完整官方技术规范，没有给出可直接照抄的完整踢墙表。

### 分数与进阶玩法

官方手机版本的普通消行基础分为：单行 100、双行 300、三行 500、四行 800，再乘当前等级。该版本还有 T-spin、Mini、全清和 Back-to-Back 奖励；例如 T-spin 单/双/三行基础分为 800/1200/1600，符合条件的连续高价值消行可获得额外 50%。这是该作品公开计分规则，并非所有历史版本的统一公式。[手机官方计分说明](https://playstudios.helpshift.com/hc/en/16-tetris-mobile/faq/2437-scoring-in-tetris/?l=en&p=web)

需要分清三个概念：

- **T-spin** 是把 T 形块旋转嵌入特定受限空间，不能仅按「这一块转过」奖励。完整实现还涉及最后有效动作、角点、Mini 和踢墙例外。
- **Combo** 是连续落块都消行，无消行的落块结束连击。
- **Back-to-Back** 连接四行消除等特定高价值消行，中间的无消行落块不等于普通消行，不能简单套用 Combo 状态。

首版建议使用清楚的普通消行分和等级倍率，软降每实际下降一格加 1、硬降每实际下降一格加 2，后两项为本项目拟定奖励。T-spin 技巧在旋转系统中仍可使用，但首版不设额外 T-spin、Mini、Combo、Back-to-Back 或全清计分，帮助页明确说明。这样可以先验证休闲节奏和手机操作；如后续增加进阶计分，应完整定义判定与叠加顺序，并升级规则版本和纪录口径，不能悄悄改变同一排行榜的含义。

### 模式取舍

| 模式 | 玩家目标 | 与本 APP 的匹配 |
| --- | --- | --- |
| 温和加速的无尽模式 | 尽量多消行、提高个人纪录，随时暂停续局 | **首版推荐**；新手容易开始，熟悉后仍有挑战 |
| 40 行竞速 | 尽快消除 40 行，比用时 | 适合熟练玩家，后续再加，纪录独立 |
| 3 分钟冲分 | 固定时间内获取高分 | 短局明确，但会持续施加时间压力，后续再加 |
| 无重力练习 | 主动放块、学习组合 | 改变主要节奏，不纳入首版常驻模式 |

40 行 Sprint、3 分钟 Ultra、150 行 Marathon 和无尽变体在 Tetris Effect 中有对应模式，不能据此认为每个版本都必须采用相同终点。[模式资料](https://tetriseffect.game/beginners-community-guide/)

## 首版现行规则

以下对应规则版本 1 的当前实现，不宣称完整符合官方 Guideline；真实触控和难度仍需设备试玩校准。完整几何、随机和终局约束见[Core 规则说明](../Assets/Scripts/Core/Tetris/README.md)。

| 项目 | 当前契约 |
| --- | --- |
| 开始等级 | 1 |
| 升级条件 | 每累计消除 10 行升级一次；一次多行照实际行数累加 |
| 棋盘与出生 | 10 列 × 22 行，其中 0、1 为隐藏行；坐标向下递增，所有块在 4×4 局部框的 `(3,0)` 原点、旋转 0 出生 |
| 旋转 | 双向 90° SRS，I 与 JLSTZ 使用各自完整五候选偏移；O 几何不变，不消耗锁定重置；不支持 180° 旋转 |
| 随机与预览 | xorshift32、Fisher–Yates 七袋和拒绝采样；Next 固定 3 块，保存未取出的袋顺序和 RNG；每个活动块最多 Hold 一次，已有 Hold 交换不消耗 Next |
| 自然下落 | 60 Hz 下每格 `round(60 × max(0.2, 0.85^(等级−1)))` tick，半 tick 向上取整；第 1 级 60 tick，第 11 级起 12 tick |
| 软降与硬降 | 软降独立每 3 tick 下降一格并清零自然重力计时，实际下降每格加 1；松开清零软降计时。硬降每格加 2，立即锁定 |
| 普通计分 | 单/双/三/四行 100/300/500/800 × 消行前等级；不加算 T-spin、Mini、Combo、B2B、全清分；计数到上限后饱和，不回绕 |
| 锁定 | 首次触地后 30 tick；此后成功横移或非 O 旋转最多重置 15 次，第 15 次可以重置、第 16 次不能延长；失败操作不重置，硬降立即锁定 |
| 防拖延 | 重置预算随当前方块保留，离地或到达更低行不补满。首次触地后锁定倒计时在离地时仍推进；允许的有效重置可重新计满 0.5 秒。到期若仍在空中，只记录到期状态，不悬空锁定；下次接地立即锁定，接地到期后不再接收移动或旋转 |
| 加速时机 | 当前落块结算按消行前等级计算，结算后更新等级并用于下一块，避免跨等级一次消行出现两种倍率 |
| 终局 | 生成或 Hold 换入位置无法放置即失败；落锁先处理消行，再检查顶部残留，允许本次消行解除堆顶危险 |
| 顶部规则 | 消行后隐藏两行仍有锁定格即结束，不再抽下一块；被挡出生保留显式防御检查。当前合法活局不保留隐藏锁定格，因此不能把被挡出生的验证夹具称为可达的正常玩法路径 |
| 反馈 | 锁定与 Hold 使用短音效，消行使用合并反馈并按公共触感开关反馈；终局使用失败反馈。消行闪光只读结果，不延迟模型提交 |
| 新手引导 | 准备态显示简短提示与开始按钮；Book 提供操作、计分与续局说明，无强制教程 |

速度、锁定和连按时序应作为同一规则版本管理。不要在设置里同时暴露大量速度滑杆，让新手先配置才能开始。

## 页面方案与当前布局

原始方案比较如下，已选择最后一项独立竖屏页：

| 方案 | 优点 | 实际限制 | 结论 |
| --- | --- | --- | --- |
| 大厅卡片内直接玩 | 入口极短，小游戏感觉明显 | 卡高 350 设计单位，还要容纳标题/纪录/按钮；10×20 棋盘很小。滚动、长按移动、暂停的手势归属冲突，离屏仍在下落也不合理 | 卡片只用于展示和进入 |
| 独立页内小棋盘 | 可以套用大标题、大成绩卡和居中小区域 | 若只给棋盘约 600×600 设计空间，正方格棋盘最多约 300×600，宽度空置且侧边信息挤；上方装饰与下方说明占了实际游玩空间 | 可以实现，但不是首选 |
| 独立竖屏完整游戏页 | 棋盘获得主要高度，Hold/Next 与触控有稳定位置，暂停语义清楚 | 需要按长短屏重新分配区域 | **推荐** |

这里的完整游戏页是 APP 内的独立页面，仍保留合集导航和安全区。首版不增加横屏、缩放、棋盘拖动或「普通/专注」切换。10×20 棋盘即使占主要高度也不会占满横向宽度，剩余空间正好放 Hold 和 Next。

### 独立竖屏页

按当前规范设计两个安全内容样本：**388×784 CSS px** 和 **388×688 CSS px**。这两组是浏览器预览尺寸，不包含模拟状态栏、手机外框和手势栏，也不直接等同于 Android dp。

原始原型常规屏棋盘为 **237×474 CSS px**，短屏为 **194×388 CSS px**，均为完整 200 格。当前 `TetrisLayout` 按实际安全区宽度相对 388 的比例计算：棋盘区顶部 144、底部操作区高 104、距底 12、棋盘至操作间隔 16；先预留侧栏宽度 112 和棋盘内边距 24，再取宽高约束较小的格边长。有错误提示时另外预留 26 高度。数值均随比例缩放，不是 Android dp。

生产主操作按钮两行各高 48 基准单位；Hold 可见盒仍宽 40，实际点击区扩为 48×68，导航热区也与可见图标分开计算。UGUI 命中、最小设计尺寸和设备物理触控大小仍是不同验收项。

1. 顶部沿用 Home、Book、Settings 的顺序与图形；紧凑显示「俄罗斯方块」。
2. 一行显示本局分数、行数和等级，暂停在该行或相邻的明确位置。最高纪录主要留在大厅及暂停/结算面板，不再常驻第二张大成绩卡。
3. 中央完整 10×20 棋盘，淡色圆角容器 `#EBEEE2` 与适量内边距；左右分别为 Hold 和 Next 3。彩色方块使用低饱和但可辨的色相，轮廓和 Ghost 区分清晰。
4. 棋盘下方集中方向、旋转、软降；「立即落下」占独立一行，与软降分开。Hold 预览框可点击并表现可用/已使用状态。
5. 短屏先压缩留白、缩小棋盘，不改变格子宽高比、不压缩操作热区到不可用。布局公式为 `cell = min(可用棋盘宽 / 10, 可用棋盘高 / 20)`；不足时还需缩减侧栏间距，而不是让棋盘伸出屏幕。

可点击区域应以实际设备密度检查。Android 官方建议触控目标至少 48×48 dp，不能把 48 CSS px 或 48 Unity 单位直接当成达标；相邻热区不得重叠争抢。[Android 触控目标说明](https://support.google.com/accessibility/android/answer/7101858?hl=en)

## 手机输入和页面状态

原始调研中，手机官方版本把横滑用于移动、两侧点按用于双向旋转，下滑/向下拖动分别用于硬降/软降，上滑 Hold。[官方手机操作](https://playstudios.helpshift.com/hc/en/16-tetris-mobile/faq/2953-tetris-controls/?l=en&p=web) 本项目首版采用明确按键，不实现棋盘滑动手势。

| 输入 | 当前契约 |
| --- | --- |
| 左右 | 按下排入一次移动，按住后重复；延迟 180 ms、重复间隔 60 ms，在 60 Hz 步上消费，实际触发时刻量化到规则步 |
| 两方向同时按住 | 后按方向优先，释放它后恢复仍按住方向；同一时刻相冲突则不横移，必须由单一输入仲裁器决定 |
| 旋转 | 顺/逆时针各一次；按住不连续旋转 |
| 软降 | 按住每 3 tick 加速一格；松开或取消停止加速，规则的软降计时在下个规则步清零 |
| 硬降与 Hold | 有效按下只排入一次，待整帧触点归并后消费；滑出、取消或第三指可撤销未消费指令，不通过普通 onClick 再补发 |
| 多指 | 最多两根触点，按动作分别记录 owner，单触点只拥有一种动作。支持横移+软降、横移+旋转/硬降，也支持同时持有左/右再仲裁方向。第三触点介入取消本轮未提交输入，全部松开后再获取；丢失或取消触点不能窃取所有权 |
| 落锁与换块 | 指令绑定活动块身份；硬降或 Hold 改变身份后丢弃旧块剩余离散指令。软降需松开后重新按下才作用于新块；可保留真实横移按住状态，但新块重新等待 180 ms 才连移，不继承旧块的重复计时余额 |
| 弹窗与后台 | 清除全部真实触点、按键及待消费指令；重新获得焦点后不补发旧动作 |

所有游戏动作进入同一仲裁器，未消费命令绑定活动块身份。真实 UGUI 射线决定可开始的控件；滑入按钮不能开启动作，方向和硬降热区不覆盖整个棋盘。编辑器键盘为左右/下方向键、Z/X 双向旋转、空格硬降、C 暂存；真实触摸存在时抑制合成鼠标路径。鼠标与键盘也使用同一最多两 owner 的规则。

| 状态 | 玩家可见行为 |
| --- | --- |
| 新玩家 | 从卡片进入准备态，明确点击开始后才产生活动局 |
| 进行中 | 分数与棋盘实时更新；暂停始终可达 |
| 主动暂停 / 帮助 / 设置 | 冻结重力、锁定和计时；关闭帮助或设置后仍暂停 |
| 切后台 / 失焦 | 保存完整局面并暂停；回到前台显示继续，不自动下落 |
| 继续 | 点击继续后短倒计时，期间不推进规则；可再次暂停 |
| 返回大厅再进入 | 一键找到同一局，进入暂停续局态，无需重选模式 |
| 游戏结束 | 显示本局分数、行数和最高纪录；再来一局或回大厅 |
| 无存档 | 显示准备态，浏览过程不制造活动局 |
| 主档损坏、备份合法 | 恢复备份并提示玩家，继续前仍暂停 |
| 主备份均损坏 | 保留文件并提示，用户明确重置后先归档再新开 |
| 未来版本或读取失败 | 保护原文件，提供返回/重试；不能伪装成新玩家覆盖进度 |
| 写盘失败 | 局面继续保留在内存，明确显示未保存；成功重试后才清除提示 |

暂停和倒计时属于项目体验选择，不把手机官方未公开的后台恢复行为作为依据。无尽模式没有最终关卡或通关界面，不为对齐其他游戏制造不存在的下一关。

## 当前工程接入

接入沿用既有页面、会话、固定步和保存契约，没有新增通用游戏框架。Dino 的 60 Hz、欢乐球球的固定步推进和输入清理可作实现参考；Dino 只存纪录，俄罗斯方块使用自己的完整续局协议。

| 层 | 俄罗斯方块负责的内容 |
| --- | --- |
| `Core/Tetris` | 唯一棋盘与活动块、七袋/RNG、旋转与碰撞、锁定/消行/分数/等级、固定步推进、深复制快照 |
| `TetrisSession` | 准备/运行/暂停/三秒倒计时/结束、是否已开始、固定步累积、revision 和命令消费 |
| `TetrisInput` / `TetrisTouchInput` | 纯输入归并与 owner、重复和换块清理 / Unity 触摸、鼠标、键盘与射线适配 |
| `TetrisPage` | 公共能力注入、前台门禁、暂停继续、保存检查点和状态投影 |
| `TetrisLayout` / `TetrisView` / `TetrisBoardView` | 纯布局、导航/成绩/Next/Hold/覆盖层、固定格/活动块/Ghost 与消行闪光，不另算消行和胜负 |
| `TetrisSaveCodec/Store` | 独立 `tetris-v1.json`，严格校验、原子替换、合法备份和错误提示 |
| `AppController` | 新卡、枚举和路由、页面构造/离开、公共设置、暂停/保存/状态分发 |

`TetrisSession.Advance` 在运行态消费离散命令，再按 1/60 秒累积推进输入重复与模型。单帧间隔超过 0.25 秒直接暂停并清空输入；暂停和继续倒计时不推进重力、锁定、得分或有效时长，后台时长不补跑。规则结果先提交，消行闪光只读结果，没有依赖动画回调才能完成的消行阶段。恢复已开始局使用三秒倒计时；首局点击开始直接运行。

`AppController` 已接入新卡、枚举、延迟构造、进入其他游戏时 Leave、回大厅、共享设置/帮助、后台/失焦、退出保存及错误状态分发。进入 Tetris 先离开黄金矿工并恢复宿主框，再按普通竖屏页构造。大厅使用 `AddLobbyCard(..., cardCount++, ...)`，页脚和内容高度按卡片数计算。

构造发生在首次进入时，构造与进入均采用宿主 `SafeDesignFrame.WidthOnly=true` 按宽度适配；返回大厅恢复其默认策略。`TetrisLayout` 用实际可用高度计算主体，不修改其他游戏的全局尺寸。页面隐藏原宿主底部状态栏，通过 `SetHostSaveWarning` 显示公共设置保存失败。离页、帮助/设置、后台/失焦、尺寸变化和禁用均暂停并取消输入；再次进入或回前台不自动续玩。

### 保存完整对局

根协议为 schema 1、`gameId=tetris`，固定字段包含 `game`、`bestScore` 与 `resultRecorded`。`game: null` 明确表示未开始；页面可构造内存预览，但仅在开始后保存非空游戏，因此无须另存 `HasStarted`。非空游戏保存规则版本 1、220 个已锁定格、活动块类型/方向/坐标、Next 队列、七袋剩余顺序与 RNG、Hold/是否可用、分数/行数、`gravityTicks`、`softDropTicks`、`lockTicks`、`lockResets`、`lockStarted`、`gameOver`、`elapsedTicks` 与 `pieceSerial`。等级由行数派生，不重复存储。

编码器使用严格 JSON 语法及 Newtonsoft token 校验，拒绝缺失/未知/重复字段、错误类型、非法枚举、缺失集合项及不一致快照，限制 128 KiB、深度 8。分数、最高分、有效 tick 与块身份使用非负十进制字符串。模型对快照进出深复制，检查几何、队列/袋、计时预算和终局一致性；此校验不是从任意输入历史证明盘面可达。不保存真实 pointer ID、按键按住状态、暂停/倒计时阶段、动画进度或后台时间，恢复非终局总是暂停。

开始、锁定、Hold、终局和生命周期边界触发保存；运行期间每 1 秒尝试检查点。`TetrisPage.Save` 同时检查 dirty 与 session revision，无变化的宿主 Save 扇出不会重复写盘；成功保存才推进已存 revision，失败保留内存局和错误提示以便重试。系统强杀可能回到最后一次成功检查点，不能承诺零丢失。Tetris 只写自己的 `tetris-v1.json/.bak/.tmp`，不覆盖其他十三款游戏或公共设置文件。

加载区分无文件、已加载、备份恢复、损坏、不支持版本和 I/O 错误。主档坏时恢复合法备份；主备任一不支持版本或读取失败都保护文件、禁止写入，并提供返回或重读。没有合法备份的损坏状态需明确确认，先将原字节归档再重置。每次写入前及临时文件 flush 后重新校验主档和备份，再原子替换；只有合法主档可以轮换为备份，坏主档不覆盖最后合法备份，合法主档也不能覆盖未来版本备份。存储层确认不支持的版本不开放损坏重置。

## 范围与验证

首版实现范围为单一无尽模式、七袋与双向 SRS、Next 3/Hold/Ghost、基础计分、温和提速、暂停续局、独立最高纪录、共享声音触感、大厅新卡和按钮操作。不纳入进阶计分奖励、联网榜单、对战、道具复活、多皮肤、横屏、棋盘手势和更多模式。

完整旋转状态、双向踢墙表、出生坐标和顶部隐藏区已进入纯 Core；规则数值依据及限制见[Core 说明](../Assets/Scripts/Core/Tetris/README.md)。这不等于取得或复刻完整官方 Guideline。速度、锁定与连按参数仍需真实设备试玩，不以效果图判断手感。

验证按以下层次记录，执行结果集中维护在[本轮验证记录](verification-tetris.md)：

- 规则：七袋边界、旋转表的各状态、墙/地面/堆叠、软降/硬降、1–4 行、跨级得分、顶部失败、Hold、无效操作、锁定上限与低帧分段一致性。
- 输入：快速点击、左右并按、移动同时旋转、多指取消、丢失 UP、换块后的旧输入、暂停与布局变化不补发。
- 存档：真实解析器的缺失/null/错误类型/重复键/未知版本，活动块与计时恢复，损坏备份、写失败和其他游戏文件保持不变。
- UI：常规屏、短屏、长数字、已用 Hold、暂停/结束/保存失败；同一可用尺寸与固定局面对照原型和生产 UGUI，验证真实射线点击。
- Android：独立验证包，Unity 检查与构建串行；记录实际安装的版本和哈希，再验证触控、安全区、后台、音效、触感和帧率。
