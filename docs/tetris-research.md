## 玩法调研

### 基础循环与乐趣

七种四格方块 I、O、T、J、L、S、Z 依次下落。玩家移动和旋转它们，填满横行后消除，上方堆积随之下落；堆积过高导致结束。判断空间、保持平整、避免空洞、为长条保留位置构成持续决策，逐渐加速增加后期压力。[Tetris 官方介绍](https://play.tetris.com/about)

采用现代常见的 **10 列 × 20 行可见棋盘**。顶部生成区另由规则模型管理，不能因为活动方块经过最上排就立即判负。[Tetris Effect 官方站发布的社区入门指南](https://tetriseffect.game/beginners-community-guide/)

核心循环为：生成 → 移动/旋转/下落 → 触地调整 → 锁定 → 同时清除满行 → 更新分数与速度 → 生成下一块。无消行时仍正常进入下一块，不能给空洞自动补齐，也不做连通区域三消。

### 影响手感的规则

| 机制 | 含义 | 本项目建议 |
| --- | --- | --- |
| 七袋随机 | 七种方块各一个组成一袋，洗牌后逐个取出，再开启下一袋 | 采用；缓解长时间等不到某种块的挫败。不是任意连续七块都各不相同 |
| 双向旋转 | 顺时针和逆时针分别转 90° | 均支持，避免只能靠连点三次代替一次逆转 |
| SRS 与踢墙 | 原地旋转受阻时，按旋转状态尝试规定的位置偏移 | 采用成熟的旋转方式，I 与其他块的偏移规则分别定义；禁止临时写成「撞墙就平移一格」 |
| Next | 看后续方块以安排落点 | 显示未来 3 块；3 是本项目的信息密度选择 |
| Hold | 暂存一块，已有暂存块时交换 | 当前活动块落锁前最多使用一次；用完置灰，下块再恢复 |
| Ghost | 预览当前块直接落下的位置 | 默认显示清晰轮廓，与已落定块区分；从同一碰撞结果派生 |
| 软降 | 按住时加速，触地后仍有短暂调整机会 | 独立向下按钮，松开恢复当前等级的自然速度 |
| 硬降 | 立即落到最低合法位置并锁定 | 独立「立即落下」按钮，触发一次，不长按连发 |
| 锁定延迟 | 触地后留出少量移动和旋转时间 | 候选 0.5 秒，并限制可重置次数，避免无限拖延 |

七袋的含义由 [Enhance 官方活动说明](https://www.tetriseffect.game/tournaments-events/tetris-40th-community-showcases/)明确解释。Next 与 Hold 的用途、暂存一块及不可连续重复交换见 [Nintendo 发布的玩法说明](https://www.nintendo.com/jp/topics/article/e8b69d6f-4951-4328-8da9-fb4c42d37fb1)。SRS 的概念见上述 Tetris Effect 社区指南；该页面并非完整官方技术规范，没有给出可直接照抄的完整踢墙表。

### 分数与进阶玩法

官方手机版本的普通消行基础分为：单行 100、双行 300、三行 500、四行 800，再乘当前等级。该版本还有 T-spin、Mini、全清和 Back-to-Back 奖励；例如 T-spin 单/双/三行基础分为 800/1200/1600，符合条件的连续高价值消行可获得额外 50%。这是该作品公开计分规则，并非所有历史版本的统一公式。[手机官方计分说明](https://playstudios.helpshift.com/hc/en/16-tetris-mobile/faq/2437-scoring-in-tetris/?l=en&p=web)

需要分清三个概念：

- **T-spin** 是把 T 形块旋转嵌入特定受限空间，不能仅按「这一块转过」奖励。完整实现还涉及最后有效动作、角点、Mini 和踢墙例外。
- **Combo** 是连续落块都消行，无消行的落块结束连击。
- **Back-to-Back** 连接四行消除等特定高价值消行，中间的无消行落块不等于普通消行，不能简单套用 Combo 状态。

首版建议使用清楚的普通消行分和等级倍率，软降每实际下降一格加 1、硬降每实际下降一格加 2，后两项为本项目拟定奖励。T-spin 技巧在旋转系统中仍可使用，但首版不设额外 T-spin、Mini、Combo、Back-to-Back 或全清计分，帮助页明确说明。这样可以先验证休闲节奏和手机操作；如后续增加进阶计分，应完整定义判定与叠加顺序，并升级规则版本和纪录口径，不能悄悄改变同一排行榜的含义。

### 模式取舍

| 模式 | 玩家目标 | 与本 APP 的匹配 |
| --- | --- | --- |
| 温和加速的无尽模式 | 尽量多消行、提高个人纪录，随时暂停续局 | **首版推荐**；新手容易开始，熟悉后仍有挑战 |
| 40 行竞速 | 尽快消除 40 行，比用时 | 适合熟练玩家，后续再加，纪录独立 |
| 3 分钟冲分 | 固定时间内获取高分 | 短局明确，但会持续施加时间压力，后续再加 |
| 无重力练习 | 主动放块、学习组合 | 改变主要节奏，不纳入首版常驻模式 |

40 行 Sprint、3 分钟 Ultra、150 行 Marathon 和无尽变体在 Tetris Effect 中有对应模式，不能据此认为每个版本都必须采用相同终点。[模式资料](https://tetriseffect.game/beginners-community-guide/)

## 首版规则建议

以下是适合当前选择的候选参数，不是宣称符合官方 Guideline；真实触控和难度还需试玩校准。

| 项目 | 建议 |
| --- | --- |
| 开始等级 | 1 |
| 升级条件 | 每累计消除 10 行升级一次；一次多行照实际行数累加 |
| 自然下落 | 每格 `max(0.2, 1.0 × 0.85^(等级−1))` 秒；约为第 1 级 1 秒、第 3 级 0.72 秒、第 6 级 0.44 秒，第 11 级起触及 0.2 秒下限 |
| 锁定 | 首次触地后 0.5 秒；此后成功移动/旋转最多重置 15 次，第 15 次可以重置、第 16 次不能延长；失败操作不重置，硬降立即锁定 |
| 防拖延 | 重置预算随当前方块保留，离地或到达更低行不补满。首次触地后锁定倒计时在离地时仍推进；允许的有效重置可重新计满 0.5 秒。到期若仍在空中，只记录到期状态，不悬空锁定；下次接地立即锁定，接地到期后不再接收移动或旋转 |
| 加速时机 | 当前落块结算按消行前等级计算，结算后更新等级并用于下一块，避免跨等级一次消行出现两种倍率 |
| 终局 | 生成或 Hold 换入位置无法放置即失败；落锁先处理消行，再检查顶部残留，允许本次消行解除堆顶危险 |
| 顶部规则 | 建议消行后仍有已锁定格留在可见区域上方即结束；隐藏行数量和所有出生坐标与旋转表一起固定为规则常量 |
| 反馈 | 普通锁定轻反馈，消行短促反馈，四行消除稍加强；声音和触感使用公共开关 |
| 新手引导 | 首次准备态给一句动作提示与 Book 入口，不强制完成长教程；开始后收起提示 |

速度、锁定和连按时序应作为同一规则版本管理。不要在设置里同时暴露大量速度滑杆，让新手先配置才能开始。

## 卡片内还是独立游戏页

| 方案 | 优点 | 实际限制 | 结论 |
| --- | --- | --- | --- |
| 大厅卡片内直接玩 | 入口极短，小游戏感觉明显 | 卡高 350 设计单位，还要容纳标题/纪录/按钮；10×20 棋盘很小。滚动、长按移动、暂停的手势归属冲突，离屏仍在下落也不合理 | 卡片只用于展示和进入 |
| 独立页内小棋盘 | 可以套用大标题、大成绩卡和居中小区域 | 若只给棋盘约 600×600 设计空间，正方格棋盘最多约 300×600，宽度空置且侧边信息挤；上方装饰与下方说明占了实际游玩空间 | 可以实现，但不是首选 |
| 独立竖屏完整游戏页 | 棋盘获得主要高度，Hold/Next 与触控有稳定位置，暂停语义清楚 | 需要按长短屏重新分配区域 | **推荐** |

这里的完整游戏页是 APP 内的独立页面，仍保留合集导航和安全区。首版不增加横屏、缩放、棋盘拖动或「普通/专注」切换。10×20 棋盘即使占主要高度也不会占满横向宽度，剩余空间正好放 Hold 和 Next。

### 独立竖屏页

按当前规范设计两个安全内容样本：**388×784 CSS px** 和 **388×688 CSS px**。这两组是浏览器预览尺寸，不包含模拟状态栏、手机外框和手势栏，也不直接等同于 Android dp。

当前原型常规屏棋盘为 **237×474 CSS px**，短屏为 **194×388 CSS px**，均为完整 200 格。主操作按钮两行各高 48 CSS px；Hold 与导航采用各自紧凑样式，需要在 Unity 实现时另外落实真实触控热区，不能从图片推断 dp 合格。

1. 顶部沿用 Home、Book、Settings 的顺序与图形；紧凑显示「俄罗斯方块」。
2. 一行显示本局分数、行数和等级，暂停在该行或相邻的明确位置。最高纪录主要留在大厅及暂停/结算面板，不再常驻第二张大成绩卡。
3. 中央完整 10×20 棋盘，淡色圆角容器 `#EBEEE2` 与适量内边距；左右分别为 Hold 和 Next 3。彩色方块使用低饱和但可辨的色相，轮廓和 Ghost 区分清晰。
4. 棋盘下方集中方向、旋转、软降；「立即落下」占独立一行，与软降分开。Hold 预览框可点击并表现可用/已使用状态。
5. 短屏先压缩留白、缩小棋盘，不改变格子宽高比、不压缩操作热区到不可用。布局公式为 `cell = min(可用棋盘宽 / 10, 可用棋盘高 / 20)`；不足时还需缩减侧栏间距，而不是让棋盘伸出屏幕。

可点击区域应以实际设备密度检查。Android 官方建议触控目标至少 48×48 dp，不能把 48 CSS px 或 48 Unity 单位直接当成达标；相邻热区不得重叠争抢。[Android 触控目标说明](https://support.google.com/accessibility/android/answer/7101858?hl=en)

## 手机输入和页面状态

手机官方版本把横滑用于移动、两侧点按用于双向旋转，下滑/向下拖动分别用于硬降/软降，上滑 Hold。[官方手机操作](https://playstudios.helpshift.com/hc/en/16-tetris-mobile/faq/2953-tetris-controls/?l=en&p=web) 由于软降和硬降共用向下方向，需要较好的手势阈值；考虑本项目的休闲定位，首版建议明确按键，手势作为后续可选方式。

| 输入 | 规则建议 |
| --- | --- |
| 左右 | 按下移动一格，按住后重复；首轮候选延迟 180 ms、重复间隔 60 ms，试玩后调整 |
| 两方向同时按住 | 后按方向优先，释放它后恢复仍按住方向；同一时刻相冲突则不横移，必须由单一输入仲裁器决定 |
| 旋转 | 顺/逆时针各一次；按住不连续旋转 |
| 软降 | 按住加速，候选每格 50 ms；松开或取消立即停止加速 |
| 硬降与 Hold | 一次完整有效操作只提交一次；不通过普通 onClick 再兜底补发 |
| 多指 | 最多两根触点，按动作分别记录 owner，单触点只拥有一种动作。支持横移+软降、横移+旋转/硬降，也支持同时持有左/右再仲裁方向。第三触点介入取消本轮未提交输入，全部松开后再获取；丢失或取消触点不能窃取所有权 |
| 落锁与换块 | 指令绑定活动块身份；硬降或 Hold 改变身份后丢弃旧块剩余离散指令。软降需松开后重新按下才作用于新块；可保留真实横移按住状态，但新块重新等待 180 ms 才连移，不继承旧块的重复计时余额 |
| 弹窗与后台 | 清除全部真实触点、按键及待消费指令；重新获得焦点后不补发旧动作 |

所有输入进入同一命令流。UI 的 raycast 边界与可见操作区一致；不把方向和硬降整个覆盖到棋盘上。

| 状态 | 玩家可见行为 |
| --- | --- |
| 新玩家 | 从卡片进入准备态，明确点击开始后才产生活动局 |
| 进行中 | 分数与棋盘实时更新；暂停始终可达 |
| 主动暂停 / 帮助 / 设置 | 冻结重力、锁定和计时；关闭帮助或设置后仍暂停 |
| 切后台 / 失焦 | 保存完整局面并暂停；回到前台显示继续，不自动下落 |
| 继续 | 点击继续后短倒计时，期间不推进规则；可再次暂停 |
| 返回大厅再进入 | 一键找到同一局，进入暂停续局态，无需重选模式 |
| 游戏结束 | 显示本局分数、行数和最高纪录；再来一局或回大厅 |
| 无存档 | 显示准备态，浏览过程不制造活动局 |
| 主档损坏、备份合法 | 恢复备份并提示玩家，继续前仍暂停 |
| 主备份均损坏 | 保留文件并提示，用户明确重置后先归档再新开 |
| 未来版本或读取失败 | 保护原文件，提供返回/重试；不能伪装成新玩家覆盖进度 |
| 写盘失败 | 局面继续保留在内存，明确显示未保存；成功重试后才清除提示 |

暂停和倒计时属于项目体验选择，不把手机官方未公开的后台恢复行为作为依据。无尽模式没有最终关卡或通关界面，不为对齐其他游戏制造不存在的下一关。

## 工程接入建议

最新 master 已有 Dino 的固定 60 Hz 规则和欢乐球球的固定 120 Hz 推进、输入清理、明确继续及完整动态快照。俄罗斯方块可以参考这些成熟处理方式；不能继续沿用旧基线「项目没有实时循环」的判断。Dino 只存纪录，不能直接拿它的持久化协议承诺完整续局。

| 层 | 俄罗斯方块负责的内容 |
| --- | --- |
| `Core/Tetris` | 唯一棋盘与活动块、七袋/RNG、旋转与碰撞、锁定/消行/分数/等级、固定步推进、深复制快照 |
| `Runtime/Tetris` 的会话和输入 | 准备/运行/暂停/结束、是否已开始、触点所有权、长按重复和命令仲裁 |

采用固定 60 Hz 规则步作为候选，输入时间戳或步序明确。前台低帧率应按有界累积策略处理，后台时长不补跑；浮点显示插值不能改变模型步数。规则结果先提交，消行动画只负责表现；如果保留消行停顿，停顿必须属于模型阶段而不是依赖 Coroutine 最后回调。

宿主需要完整覆盖进入 Tetris、进入其他游戏、回大厅、帮助/设置、后台/失焦、退出、错误状态刷新。大厅使用最新的 `AddLobbyCard(..., cardCount++, ...)` 接入，页脚和内容高度已有自动计算，不手写旧基线卡片坐标。只增加卡片按钮不是完成接入。

构造与进入均采用宿主 `SafeDesignFrame.WidthOnly` 按宽度适配，构造暂时切换后恢复宿主策略；俄罗斯方块自己的 `TetrisLayout` 用实际可用高度计算主体，不修改所有游戏的全局尺寸。若隐藏原宿主底部状态栏，接入现有 `SetHostSaveWarning` 约定，使公共设置保存失败也能显示。

### 保存完整对局

保存内容至少包括：规则版本、已锁定格、活动块类型/方向/坐标、预览队列、七袋剩余顺序与 RNG、Hold 及是否已使用、分数/行数/等级、规则阶段、重力余量、锁定计时与重置次数、有效游戏时长、最高分、是否开始和结果状态。模型校验必须检查几何重叠、合法类型、数组长度、队列/袋约束、计时范围及阶段一致性。

不保存真实 pointer ID、按键按住状态、动画进度、后台经过时间；恢复时清输入并暂停。仅保存棋盘图片会丢失当前块、未来序列和触地时机，不满足续局。

锁定、Hold、终局和生命周期切换时保存；运动期间采用节流的 dirty 检查点，不每帧 flush。系统强杀可能回到最后一次成功检查点，不能承诺所有情况下零丢失。浏览预览不写活动局，不覆盖其他十二款游戏或公共设置文件。主档坏时尝试合法备份；坏主档不能替换最后合法备份。

加载区分无文件、已加载/备份恢复、损坏、不支持的未来版本和 I/O 错误。未知版本与读取错误不能被新局自动覆盖；损坏文件按现有模块做法先保留可诊断副本。保存前重新校验主档和待轮换备份，再决定能否写入；任一处检测到未来版本均应保护该文件，不能以「主档合法」为由覆盖未来版本备份。借鉴 Zuma 的 dirty/revision 门禁去掉无变化重复写盘，不把已有某个页面有 dirty 字段误当成其所有保存入口均已去重。
