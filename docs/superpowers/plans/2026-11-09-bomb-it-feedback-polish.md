# Bomb It feedback and continue-run implementation plan

**Goal:** Address the seven reported usability gaps and add the explicitly selected continue-run checkpoint, with Android delivery for user-operated verification.

**Architecture:** The original SWF owns rules, checkpoint data and its sound switch. The adapter owns presentation, input and pause reasons. The existing native host owns actual audio gating, interaction haptics and durable pending global preferences; Unity remains the global preference owner. Keep the existing isolated worktree and all prior changes. Do not operate a phone, install, publish or merge.

**Tech stack:** Pinned Ruffle and reviewed AS2 patches, HTML/CSS/JS, Android Java, iOS Objective-C++, Unity C# and the existing build entry.

- [x] Verify current behavior from source and screenshots: names/rankings are the only original saves; phase changes shrink/reposition controls; quiet styles remove tool backgrounds; large settings cards overflow; native audio is one-way and haptics absent. Distinguish physical cutout safety from system gesture start regions.
- [x] `sanitizer/bridge/` and its audit/build tools: add checkpoint and sound bridge. Continue saves difficulty, mode, stage, roles, life and total scores at stable run boundaries; current-stage layout regenerates. Preserve original ranking data; validate schema/limits; explicit flush failure prevents a successful exit acknowledgement. Resume through original initialization with correct ordering. Preserve unrelated original actions and offline gates.
- [x] `adapter/controls.js`: fixed geometry across phases, symmetric two-player controls, single-player bomb aligned with movement control and corresponding diameter. Idle stick illustration returns on release; actual origin stays at first contact. Exclude native gesture start zones independently of layout. Emit one valid bomb-press haptic event per DOWN.
- [x] Native Bomb It host/bridge and dedicated C# preferences: initial real sound/haptics configure, bounded settings request/ack, durable revisioned pending update, apply to Unity data and acknowledge only after successful Save. Reconcile on return and cold start. Haptics respect foreground/system settings and need no new Android permission. Other web games retain existing behavior.
- [x] `adapter/host.js`, `index.html`, `style.css`: compact settings with control style plus actual sound/haptics switches, fixed visible close action; backdrop dismissal cancels temporary modal pause only. Restore rounded tool surfaces. Add continue-run summary/entry and accurate original-rule help. Keep viewport invariant across modes/styles and protect original menu/HUD hit areas.
- [x] Computer checks: real Ruffle checkpoint reload/continue, failure flush, original sound synchronization, manual/background/modal pause combinations; control geometry before/after entering battle; settings fit at supported landscape heights; touches on backdrop vs inside; both orientations/safe insets; native Java and iOS syntax; review changed boundaries.
- [x] Build Android through `./scripts/build.sh android --configuration debug`; final exit 0, signature/runtime/actual bundled content passed. APK is 233,724,260 bytes, SHA-256 `2131028efbce0118ad84af94ecf8d09bad7fb58bc8371e5e5ef67768b727a79e`. Provide exact `adb install -r` command for OPPO. No phone interaction or installation performed.

Native feedback contract: `configureFeedback({token,soundEnabled,hapticsEnabled})`; request `feedback-settings` with token/requestId/two booleans; acknowledgement `feedbackSettingsResult` with token/requestId/ok/current preferences. `haptic` accepts token, monotonic pressId and `kind: bomb-press`. Actual audibility remains a separate lifecycle/audio-focus gate.

SWF contract: `xanaduContinue`, `xanaduFlushSave`, `xanaduSetSoundEnabled`; every result uses the existing validated session state, adding continueInfo/saveOk/saveError/soundEnabled/restoring. UI may report persistence only after successful storage result. New games replace the checkpoint only once their first battle initializes.
