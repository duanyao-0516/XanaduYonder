# 欢乐球球原版对齐 Implementation Plan

> **For agentic workers:** Use subagent-driven-development for independent core and scene ownership, then review specification compliance and code quality. No merges or publication.

**Goal:** 按用户确认的原视频修正关卡、弹跳、透视和整套反馈，保留已确认顶部 UI。

**Architecture:** 规则继续由纯 C# 模型负责，SceneView 只表现模型事件；Page 负责死亡反馈等待和生命周期。随机布局和后续续局继续由真实快照/存档链路约束。

**Tech Stack:** Unity 6000.3.27f1, C# 7.3, .NET 10 独立测试，Unity 图形验证，独立 Android 测试包。

### 1. 规则与生成
- [ ] 先用生产代码测试复现弹跳不足、重击无上弹/连续计分、单缺口/固定三层模式。
- [ ] 修改 `HappyBallRules/Game/Generator/Geometry`：v=13.2、g=40；重击命中即时计分、上弹、消耗权限，完整通过时仅推进层索引；维护存档一致性。
- [ ] 生成 1～3 个足够宽的缺口、多段红黑，深度收窄叠加层间变化，支持多目标可达性验证；有界结构化生成与完整入场安全带，不固定每四层节奏。
- [ ] 运行 `scripts/test-happy-ball.sh` 及 persistence 测试，覆盖多种子、多入口、长局、快照恢复、红黑/竖板边界。

### 2. 场景与特效
- [ ] 修改 `HappyBallSceneView/SceneGeometry/Effects` 和必要专用表现文件：透视相机、弹性形变、双向拖尾、柱面/盘面高度阴影。
- [ ] 使用有界对象池生成液滴和不规则颜料；颜料归属层，随转塔、随左右碎块运动。
- [ ] 重击大块变绿并甩出翻落；LayerBroken 的 ScoreDelta 显示一次，LayerPassed 的零分不弹字。
- [ ] 在 `HappyBallUiChecks` 加入连续帧输出与几何/资源界限检查；检查 720×1320 和 720×1582 视口。

### 3. 页面和整体验证
- [ ] Page 添加约 0.33 秒死亡反馈阶段，冻结输入和逻辑但推进表现；后台/弹窗/重开/离页处理一致，存档不延迟依赖动画。
- [ ] 更新玩法文案、现有规格的过期描述；保持标题/单行信息/底部无说明。
- [ ] 运行规则、输入、存档和 Unity UI 回归；查看连续帧并按参考节奏修正，独立审查后再构建隔离测试包。
- [ ] 更新验证记录，分别记录源码审查、自动测试、Unity 画面、构建和真机边界。

### 4. 真机反馈修正：柱面球影与竖板高度
- [ ] 调查柱面影在 Android 上的闪动来源；使用稳定的柱面材质投影或有证据的深度修正，保留软影，不依赖透明贴面碰巧排序。
- [ ] 层距从 1.65 提高到 2.4，构图约显示 4～5 层；竖板由旧 0.29～0.42 提高为随深度递增的约 0.85～1.50；集中几何上限，保证跨层间距/前层完整通过、球底净空、碰撞与存档边界一致。
- [ ] 回归真实旧层距存档的版本化迁移、生成高竖板、顶部弹跳、低位拒绝旋转、高位越过、序列可达和旧存档；输出高竖板和多高度球影连续帧。
- [ ] 在所有修正后的同一源码上重新运行图形与核心受影响检查、构建隔离包，并逐项记录真机验证边界。
