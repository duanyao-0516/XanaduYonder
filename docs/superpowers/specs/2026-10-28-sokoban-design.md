### 已确认并接入的 UI 修订

[可操作原型](../../prototypes/sokoban/README.md)的 `597249b` 为本次 Unity UI 基准。下文规则、页面和存档说明已按该版本更新；早期单页、手动缩放与棋盘滑动移动方案已被本次修订替代。素材和关卡研究保留原始来源与阶段边界。

- 保留导航、标题、单行关卡与计数。移除方向盘中心圆点，左右键保持原位，上/下键各向中间移动半格，分别与撤回/重来两行对齐。
- 移除手动适配、放大、缩小、视口拖动和棋盘滑动移动，只按可用区域自动完整显示地图。棋盘视口使用 15 CSS px 圆角、浅色背景与 12 CSS px 内边距。
- 游戏内选关弹层宽 320 CSS px、内边距 24 CSS px，删除无信息的“进入”。教学列表展示当前进度与实际纪录，普通关以纯数字按钮的边框和底色区分当前局与已完成状态。
- 大厅到推箱子先展示入口页：上方突出“继续上次”，显示当前关卡、真实步数、推动和归位；下方按章节选择全部 108 关。继续操作直接回到已有局面与撤回历史。没有活动尝试时展示教学第一关预览与“开始入门教学”，打开入口本身不会创建活动存档；当前尝试已完成时提供相邻下一关，末关则提供重玩。后台恢复与关闭设置保留原先的入口或游戏视图。
- 教学关保留当前带名称的 64 px 卡片，普通关使用 44 px 高的纯数字按钮。教学与普通关独立编号，普通关显示 1–100；分组改为“第 1–20 关”等实际范围，删除没有内容依据的“仓库一至五”展示名。关卡 ID、地图、顺序和存档身份不变。
- 原型只用内存演示进度并明确标注不保存；Unity 使用真实 `SokobanProfile`、唯一活动尝试和已完成记录。从已有有效步数的未完成尝试切换另一关时继续要求明确确认。

增加入口页的理由是让 108 关的选择与进度有稳定位置。代价是从大厅继续游戏多一次点击，因此“继续上次”必须首屏可见、一键恢复，不再增加确认或逐层选章步骤。

## 1. 当前页面方案

**竖屏入口与游戏两个视图：入口展示真实续局和全部关卡，游戏保留统一导航、标题、单行计数、自动适配棋盘与底部操作。** 显示名「推箱子」，稳定游戏 ID `sokoban`，大厅文案「把每一只箱子，推回它的位置。」。

## 2. 交付范围与首版边界

最初方案阶段交付了独立工作树、素材和关卡源文件、许可与验证材料，以及浏览器 UI 原型。当前已继续接入 Unity 规则、存档、合集路由与本次确认的入口、选关和游戏 UI。浏览器原型仍是独立的内存演示；Unity 的真实存档、音频、触感和宿主生命周期不由该原型替代。

当前首版范围：

- 原创教学 8 关，逐步介绍走动、单箱推动、绕行、目标覆盖、角落风险、先后顺序、撤回与多箱配合；每关必须保存一条验证解法。
- 从 Boxoban 源池选 100 关，分 5 章、每章 20 关，展示为“第 1–20 关”至“第 81–100 关”。机器搜索成本与解法长度不直接标为真人难度；解法回放也不代替人工试玩评价。
- 四向移动、单箱推动、到位反馈、撤回、重来、入口续局、选关、通关面板、下一关、离线续局、已完成记录与个人最佳；棋盘仅自动完整适配。
- 默认开放全部已发布关卡；推荐按顺序游玩但允许跳关，不以卡关阻断内容。选关中展示完成情况，切换到另一关前明确说明仅保留一场进行中的尝试。
- 不加入计时失败、生命、广告、账号、联机、地图编辑器、随机生成、在线下载和运行时自动求解。首版不展示「最优步数」或未经证明的三星阈值。

## 4. 关卡源与配置契约

Boxoban 固定 commit `78011d8c86ad423bfb2e1005012393b4c3c24409`，原始文件 `unfiltered/test/000.txt`，本地名 `Data/Sokoban/boxoban/unfiltered-test-000.txt`。源数据共 1,000 关，每关 10×10、1 人、4 箱、4 目标；源 ID 0–999，不改写源字节。

源文件 SHA-256：`272928a4e7c185fdf84daa523b298750b6ff08703cb0c20d3be7eff93acc5256`。上游 `unfiltered/medium/hard` 是数据集分组，不是本项目的真人难度等级。上游没有逐关附带可回放的解法文件，正式入包必须补齐见证验证。

早期方案中的单关字段示例如下。实际发布目录以 `Assets/Resources/Sokoban/campaign.json` 为准，浏览器原型读取同一资源：

```json
{
  "schemaVersion": 1,
  "levelId": "tutorial-001",
  "contentVersion": "sokoban-campaign-v1",
  "chapter": "tutorial",
  "order": 1,
  "title": "第一只箱子",
  "source": {"collection": "xanadu-original", "sourceId": "tutorial-001"},
  "rows": ["#####", "#@$.#", "#####"],
  "solution": "R"
}
```

符号约定：`#` 墙、空格地面、`.` 目标、`$` 箱、`@` 人、`*` 箱在目标上、`+` 人在目标上。地形与人/箱状态拆开存储，箱移出目标后目标仍存在。数据以左上角 `(0,0)` 为起点，索引 `y * width + x`。保留行内及行尾空格；不对地图执行会改变坐标的 trim。允许原始非矩形 XSB 的未来导入器必须补为显式 Void，再从外部做洪水填充，不能把地图外补空格当可走地板；首版资源保持矩形且有封闭外墙。

正式入包检查：

1. 版本、ID、来源唯一且完整；行数、列数有上限，字符全在白名单；首版教学最大 10 列×14 行，Boxoban 固定 10×10。
2. 恰好一人，箱数等于目标数且非零，人和箱不在墙/外部；可行走格边界闭合。
3. 每关附一条 L/U/R/D 解法，每步通过生产 `SokobanGame` 重放；最后全部箱子到位，步数/推动数与报告一致。外部 Python 验证是前期证据，不能代替生产规则重放。
4. 同一地图的完全重复项去重；保留原作者/源 ID。不修改某一固定 levelId 的地图，任何地图改动更新内容版本或发新 ID。
5. 发布目录包含 manifest、源哈希、规范化地图哈希、解法验证报告。素材与关卡导入结果只在全部通过后替换，失败保留上一份合法输出。

所有 1,000 关留作可扩展源池，首版入包选定的 100 关与 8 关教学。当前 UI 调整只投影显示编号和分组范围，不改变已发布目录的地图、顺序、ID 或内容版本。生产解法重放与人工试玩评价分别记录，不能以可解见证声称已经完成难度调优。

历史预选阶段按源顺序检查前 104 关，生成 100 份解法并独立逐格重放通过；源 ID 21、46、65、78 超出单关预算，记录为 `budget_exceeded`，不据此判定无解。结果位于 `Data/Sokoban/verification/verified-candidates.json`；解法为 15–125 步、4–22 次推动。该记录保留候选池来源和搜索边界，不宣称全局步数最优；正式 108 关的生产验证见[实现验证记录](../../verification-sokoban.md)。

## 5. 规则与交互

- 人每次向上/下/左/右移动一格。邻格是空地则走动；邻格是箱且再下一格为空地则推动一箱。禁止拉箱、斜走、同时推两箱、穿墙或穿越边界。
- 有效走动计一步；有效推动也计一步，并令推动数加一。阻挡不计步、不入历史、不写盘。所有箱子都位于目标时通关；初始地图必须不是已完成局。
- 撤回恢复上一次有效动作前的人、箱、步数、推动数，允许连续撤回；重来恢复原始地图，个人纪录保留。胜利后在结果页选择下一关或重玩，不把已获胜的同一尝试反复计数。
- 箱子进入非目标的静态角落时可提示「可能推不回来了，可撤回」。只提示可确定的静态陷阱，不把简化死锁算法当完整无解判定，不自动判负或重置。
- 游戏处于前台且没有弹层时，可通过四向方向盘、方向键或 WASD 移动。入口页、玩法、选关、设置及后台均禁止移动。棋盘点击、滑动、拖动和双指动作不会移动人物或改变视口；不加入点格寻路与点箱自动推动。
- 方向盘只处理一次按下到正常松开，不做长按连推。同一时刻只有一个操作所有者，只有同一触点在原方向控件正常松开才提交一步。始于棋盘或其他区域的触点不能转交给方向键；第二根手指加入即取消待提交动作，全部手指抬起后才接受新操作。
- 触点取消、丢失松开、视口尺寸变化、切后台、弹窗或离页均取消当前手势与排队方向输入；恢复前台或关闭弹层不会补发旧输入。方向控件的普通点击回调不另行提交移动，避免和按下/松开仲裁重复执行。
- 动画约 80–120 ms，模型先提交、视图后插值。动画期间最多保留一条方向输入，切页清空；后台或撤回立即按最终模型重绘，不从中间精灵位置计算规则。

## 6. UI 与适配

### 入口与游戏视图

入口与游戏共用导航和标题。入口显示简介、真实当前局的小棋盘与继续按钮、完成进度、横向章节标签和关卡网格。教学卡片高 64 CSS px，保留编号、名称与状态；普通关按钮高 44 CSS px，只显示独立的 1–100 编号。参考宽度下教学每行 5 个、普通关每行 6 个，窄屏分别调整为 4 个和 5 个。

游戏视图从上到下排列：

1. 导航栏：左侧 Home 图标返回大厅；中央单行 `XANADU / YONDER` 品牌；右侧 Book 图标打开玩法，Settings 图标打开公共设置。导航图标、颜色、尺寸、安全区和间距对齐现有页面，Home 不承担逐层返回。
2. 标题「推箱子」左对齐，使用 720 宽设计基准下的 49 字号（随现有 CanvasScaler 缩放），左边缘与内容区一致。
3. 单行信息栏：左侧关卡选择入口显示关卡名，右侧同一行展示「步数、推动、归位」。计数不拆到另一行；长关卡名按可用宽度省略，选关页显示全名。关卡入口同时承担切关，不另设一排选关按钮。
4. 棋盘视口：占满信息栏与底部操作区之间的剩余内容空间；背景 `#EBEEE2`、圆角 15 CSS px、内边距 12 CSS px。格子始终正方形，整张地图居中显示，不覆盖导航、计数或操作按钮。
5. 底部操作区高 152 CSS px。左侧撤回、重来各为 166×48 CSS px，分别位于 `(0,24)`、`(0,80)`；右侧方向键为 48×48，上、下、左、右分别位于 `(249,24)`、`(249,80)`、`(197,52)`、`(301,52)`。这些坐标相对操作区，保留中心空白，没有中心圆点、缩放控件或常驻说明。

选关弹层宽 320 CSS px，边框内留 24 CSS px 内边距。顶部横向分组，教学使用带名称及有效状态的列表，普通关使用 5 列数字网格；底部可返回关卡入口。点击当前未完成关继续同一尝试，切换另一个关卡沿用未完成进度确认规则，取消时保留原局面。

Android Back 优先关闭当前弹层；游戏中无弹层时打开选关，再次 Back 只关闭选关。选关的“查看关卡入口”返回入口；入口 Back 返回大厅。顶部 Home 始终直接保存并返回大厅。后台恢复与公共设置关闭保留原先显示的入口或游戏，取消旧输入与动画。普通第 100 关通关结果提供“返回关卡入口”及“重玩本关”；入口主按钮提供“再玩这一关”。

共享设置保存失败与当前游戏保存失败在入口和游戏中均使用持续可见的紧凑状态提示；出现时重新计算可用内容高度，不覆盖操作区。

### 自动完整适配

设 `s = rootWidth / 388`、`padding = 12 * s`，格子大小为 `cellSize = min((boardWidth - 2 * padding) / columns, (boardHeight - 2 * padding) / rows)`，地图在两轴居中。`SokobanViewport` 的兼容投影固定为 `zoom = 1`、`centerX = centerY = 0.5`，不再提供手动缩放、平移或复位操作。

屏幕安全区、可用尺寸或保存提示变化时重算完整适配；继续同一关、重来和切关都使用同一公式。布局变化不修改尝试 ID、人箱位置、计数或撤回历史。教学上限仍为 10 列×14 行，Boxoban 仍为 10×10。

紧凑控件与网格的命中区域按可见矩形设置，原始触摸与 UGUI raycast 共用同一边界，避免扩大区域后抢占相邻控件。CSS px、Unity 设计单位和 Android dp 分别记录，不宣称这些控件在所有设备上均达到 48dp。小屏短屏、长屏、刘海、手势导航与真实多指输入仍需分层验证；单行信息栏需覆盖最高 50,000 步时的可读性。

### 原型查看与验证边界

`docs/prototypes/sokoban/index.html` 为入口、游戏与选关的独立浏览器原型，读取同源生产目录，加载失败时明确退回两张原创示例地图。方向盘和键盘可移动、推动、撤回及重来，棋盘只自动完整显示。原型初始 1 步演示进度、完成集合和个人纪录只存在于当前标签页内存，刷新即重置；Unity 从真实玩家档案恢复，不注入演示进度。

原型检查见[原型 README](../../prototypes/sokoban/README.md)；Unity UGUI 字体、渲染、命中区域、存档和生命周期检查及 Android 构建见[实现验证记录](../../verification-sokoban.md)。浏览器检查与 Unity 自动测试均不代替 Android 真机多指、安全区或交互一致性验收。

## 8. 存档与恢复

独立 `Application.persistentDataPath/sokoban-v1.json`，使用当前 Newtonsoft.Json 13.0.2 的实际严格解析方式，原子临时文件/主档/备份流程沿用项目惯例。保存 `schemaVersion`、`gameId`、内容版本、levelId、attemptId、完整动作序列、当前人/箱、计数、已完成 ID、个人最佳，以及当前关卡的视口倍率与归一化地图中心。

本次尝试从初始地图重放动作序列，校验终态、人箱位置和计数一致；字段缺失/null/错误类型、重复键、未知版本、越界、重复箱、计数不符一律拒绝该槽。地图版本不匹配时清除失效的活动尝试，保留仍能对应的完成纪录并提示重新开始。新版本迁移必须显式设计，不由默认值掩盖。

存档 schema 继续保留视口字段，旧版本的合法放大记录仍可按原编解码契约读取：有限倍率裁剪到 `[1,2]`、中心裁剪到 `[0,1]`，倍率为 1 时中心固定为 0.5。页面恢复完整轨迹后将当前视口归一化为 `1 / 0.5 / 0.5`，后续保存也写入该值；旧放大状态不会导致整局被丢弃或重置尝试 ID、计数、位置及撤回历史。

没有活动尝试时，入口只创建不写入档案的教学第一关预览；即使内容迁移保留了旧选中关，预览也与“开始入门教学”动作保持一致。初始化后的离页、宿主保存、设置及前后台回调均不会把预览变成已开始的游戏，用户继续或选关后才创建真实活动尝试。恢复已有尝试时则保留同一身份与历史。

每次有效动作、撤回、重来、切关和前后台都保存已经提交的模型，不逐帧写盘。一个正式关卡最多保存 50,000 步动作与对应撤回能力；达到上限时阻止继续累积并显示「本次尝试步数已达上限，可撤回或重来」，不截断历史后声称完整续局。文件上限 2 MiB、嵌套深度 12；完整重放只在加载时执行，运行中不每帧重放。

通关集合用 levelId 去重，累计通过关数是唯一已完成关数；重玩不会重复加一。个人最佳保存两个真实元组：最少步数纪录 `(moves, pushes)` 与最少推动纪录 `(pushes, moves)`，分别按字典序比较；不能把两次成绩独立最小值拼成不存在的成绩。通关结果与纪录一起捕获并保存；选择下一关时先保留已完成结果，再创建并保存下一次尝试。下一关按目录顺序定位，独立的教学/普通显示编号不参与存档身份或顺序计算。

读取先主档后合法备份；两者都坏时保留坏档用于诊断，提示新开。写入失败保留有效旧档、允许当前内存继续游玩并持续提示「尚未保存」，重试成功再清除。设置弹窗、后台、返回、视口尺寸变化和资源释放有成对的输入取消及动画停止，不在销毁后回调更新页面。
