## 1. 推荐方案

**默认竖屏游戏页面，棋盘占满内容宽度；另提供可随时切换的专注模式。** 显示名「推箱子」，稳定游戏 ID `sokoban`，大厅文案「把每一只箱子，推回它的位置。」。

| 形式 | 体验与限制 | 结论 |
| --- | --- | --- |
| 页面内大棋盘 | 保留标题、关卡、步数和撤回；符合现有合集；近方形地图已充分利用手机宽度 | 默认 |
| 应用内专注模式 | 压缩页头和说明，增加棋盘纵向空间；仍保留退出、撤回、方向键和保存错误 | 可选；高地图受益最大 |
| 页面中固定小窗口 | 留白多，箱子、目标与角色偏小；控制区和窗口容易争抢触摸 | 不采用 |

这里的「专注」指当前游戏页面内的布局变化，不是另起 Activity、相机、WebView 或 Android 系统强制全屏。首版不切横屏、不改变全应用系统栏策略。标准与专注共享同一对局，切换绝不重开。

现有 `UiFactory` 基准为 720×1320；`MinesweeperPage.Layout.cs` 中普通与专注棋盘宽度均为 648，只改变高度。因此对于 10×10 关卡，隐藏标题通常不能继续放大格子。原型同时显示近方形与高地图，避免只用一张图得出「全屏更大」的误判。宽地图同样不会因增加高度变大，首版通过关卡规格控制解决。

## 2. 本轮交付与正式首版边界

本轮交付独立工作树、实际可用的素材/关卡源文件、来源与许可、内容验证材料、完整方案及可操作的简单 UI 原型。浏览器演示用于观察布局、移动、推动与撤回，不是 Unity 实现，也不写正式游戏存档。

建议正式首版内容：

- 原创教学 8 关，逐步介绍走动、单箱推动、绕行、目标覆盖、角落风险、先后顺序、撤回与多箱配合；每关必须保存一条验证解法。
- 从 Boxoban 源池选 100 关，分 5 章、每章 20 关；上线顺序由可解证明和人工试玩共同确定。机器搜索成本与解法长度只辅助编排，不直接叫「简单/困难」。
- 四向移动、单箱推动、到位反馈、撤回、重来、选关、通关面板、下一关、离线续局、已完成记录与个人最佳。
- 默认开放全部已发布关卡；推荐按顺序游玩但允许跳关，不以卡关阻断内容。选关中展示完成情况，切换到另一关前明确说明仅保留一场进行中的尝试。
- 不加入计时失败、生命、广告、账号、联机、地图编辑器、随机生成、在线下载和运行时自动求解。首版不展示「最优步数」或未经证明的三星阈值。

## 4. 关卡源与配置契约

Boxoban 固定 commit `78011d8c86ad423bfb2e1005012393b4c3c24409`，原始文件 `unfiltered/test/000.txt`，本地名 `Data/Sokoban/boxoban/unfiltered-test-000.txt`。源数据共 1,000 关，每关 10×10、1 人、4 箱、4 目标；源 ID 0–999，不改写源字节。

源文件 SHA-256：`272928a4e7c185fdf84daa523b298750b6ff08703cb0c20d3be7eff93acc5256`。上游 `unfiltered/medium/hard` 是数据集分组，不是本项目的真人难度等级。上游没有逐关附带可回放的解法文件，正式入包必须补齐见证验证。

导入后的每关数据定义如下（字段与示例表示正式格式，当前原型不依赖此生产格式）：

```json
{
  "schemaVersion": 1,
  "levelId": "tutorial-001",
  "contentVersion": "sokoban-campaign-v1",
  "chapter": "tutorial",
  "order": 1,
  "title": "第一只箱子",
  "source": {"collection": "xanadu-original", "sourceId": "tutorial-001"},
  "rows": ["#####", "#@$.#", "#####"],
  "solution": "R"
}
```

符号约定：`#` 墙、空格地面、`.` 目标、`$` 箱、`@` 人、`*` 箱在目标上、`+` 人在目标上。地形与人/箱状态拆开存储，箱移出目标后目标仍存在。数据以左上角 `(0,0)` 为起点，索引 `y * width + x`。保留行内及行尾空格；不对地图执行会改变坐标的 trim。允许原始非矩形 XSB 的未来导入器必须补为显式 Void，再从外部做洪水填充，不能把地图外补空格当可走地板；首版资源保持矩形且有封闭外墙。

正式入包检查：

1. 版本、ID、来源唯一且完整；行数、列数有上限，字符全在白名单；首版教学最大 10 列×14 行，Boxoban 固定 10×10。
2. 恰好一人，箱数等于目标数且非零，人和箱不在墙/外部；可行走格边界闭合。
3. 每关附一条 L/U/R/D 解法，每步通过生产 `SokobanGame` 重放；最后全部箱子到位，步数/推动数与报告一致。外部 Python 验证是前期证据，不能代替生产规则重放。
4. 同一地图的完全重复项去重；保留原作者/源 ID。不修改某一固定 levelId 的地图，任何地图改动更新内容版本或发新 ID。
5. 发布目录包含 manifest、源哈希、规范化地图哈希、解法验证报告。素材与关卡导入结果只在全部通过后替换，失败保留上一份合法输出。

所有 1,000 关留作可扩展源池，首版只入包选定的 100 关与 8 关教学。5 章排序在人工试玩之后冻结；本轮验证见证不能作为已经完成教学编写或难度调优的证明。

本轮已按源顺序检查前 104 关，生成 100 份解法并独立逐格重放通过；源 ID 21、46、65、78 超出单关预算，记录为 `budget_exceeded`，不据此判定无解。结果位于 `Data/Sokoban/verification/verified-candidates.json`；解法为 15–125 步、4–22 次推动。该候选池证明可解，不宣称全局步数最优，也尚未完成正式关卡编排。

## 5. 规则与交互

- 人每次向上/下/左/右移动一格。邻格是空地则走动；邻格是箱且再下一格为空地则推动一箱。禁止拉箱、斜走、同时推两箱、穿墙或穿越边界。
- 有效走动计一步；有效推动也计一步，并令推动数加一。阻挡不计步、不入历史、不写盘。所有箱子都位于目标时通关；初始地图必须不是已完成局。
- 撤回恢复上一次有效动作前的人、箱、步数、推动数，允许连续撤回；重来恢复原始地图，个人纪录保留。胜利后在结果页选择下一关或重玩，不把已获胜的同一尝试反复计数。
- 箱子进入非目标的静态角落时可提示「可能推不回来了，可撤回」。只提示可确定的静态陷阱，不把简化死锁算法当完整无解判定，不自动判负或重置。
- 默认四向键盘/方向盘；棋盘内一次滑动最多提交一步。编辑器方向键/WASD可用；不在本期加入点格寻路与点箱自动推动。
- 方向盘首版只处理一次按下到正常松开，不做长按连推。滑动和方向盘拥有各自开始触点，但同一时刻只有一个操作所有者；多指、取消、切后台、弹窗、离页与切布局均取消尚未提交的输入。
- 动画约 80–120 ms，模型先提交、视图后插值。动画期间最多保留一条方向输入，切页清空；后台或撤回立即按最终模型重绘，不从中间精灵位置计算规则。

## 6. UI 与适配

### 标准页

沿用现有导航：返回 / 玩法 / 设置。标题「推箱子」，次行「第 1 章 · 01 / 20」；计数行显示「步数、推动、到位」。棋盘占内容宽度（720 基准内约 648），格子保持正方形并整体居中。下方为撤回、重来、选关与专注入口；最下方是四向方向盘和简短操作说明。

### 专注页

缩小标题区域，顶部仅保留退出、关卡和必要计数，棋盘向上/下扩展；底部仍保留撤回、重来和方向盘。共享设置保存失败与当前游戏保存失败都必须可见，不能因为隐藏宿主页脚而丢失错误。Android 返回顺序：先关弹层，再退出专注，再回选关，最后回大厅。

### 尺寸策略

`cellSize = min(availableBoardWidth / columns, availableBoardHeight / rows)`，整体等比缩放，不裁地图、不覆盖操作按钮。普通页推荐 10×10；10×14 高地图可以看出专注模式的实际收益。首版不需要棋盘平移/双指缩放，因此不会把移动人物的滑动与拖动视口冲突在一起。

触控目标按真实物理尺寸至少 48dp，不把 88 个设计单位直接等同 48dp。须覆盖小屏短屏、20:9 长屏、刘海和手势导航安全区；竖屏手机的操作层优先保住触控大小，压缩说明和装饰留白。若后续引入超过内容规格的大地图，应单独设计缩放/总览或横屏，不把它悄悄塞进小格子。

### 原型查看

`docs/prototypes/sokoban/index.html` 为本地简单 UI。桌面比较两种手机布局，窄屏切换；原创演示地图用于可视对照，移动/撤回仅在当前页面内生效。原型细节可能不等同最终 UGUI 字体测量、Android dp 或触摸分发；正式接入后仍按本节规范验收。

## 8. 存档与恢复

独立 `Application.persistentDataPath/sokoban-v1.json`，使用当前 Newtonsoft.Json 13.0.2 的实际严格解析方式，原子临时文件/主档/备份流程沿用项目惯例。保存 `schemaVersion`、`gameId`、内容版本、levelId、attemptId、完整动作序列、当前人/箱、计数、已完成 ID、个人最佳与布局偏好。

本次尝试从初始地图重放动作序列，校验终态、人箱位置和计数一致；字段缺失/null/错误类型、重复键、未知版本、越界、重复箱、计数不符一律拒绝该槽。地图版本不匹配时不把旧坐标强塞给新地图，保留仍能对应的完成纪录并提示该关重新开始。新版本迁移必须显式设计，不由默认值掩盖。

每次有效动作、撤回、重来、切关和前后台都保存已经提交的模型。一个正式关卡最多保存 50,000 步动作与对应撤回能力；达到上限时阻止继续累积并显示「本次尝试步数已达上限，可撤回或重来」，不截断历史后声称完整续局。文件上限 2 MiB、嵌套深度 12；完整重放只在加载时执行，运行中不每帧重放。

通关集合用 levelId 去重，累计通过关数是唯一已完成关数；重玩不会重复加一。个人最佳保存两个真实元组：最少步数纪录 `(moves, pushes)` 与最少推动纪录 `(pushes, moves)`，分别按字典序比较；不能把两次成绩独立最小值拼成不存在的成绩。结果与纪录、下一关选择在同一次存档事务内保存。

读取先主档后合法备份；两者都坏时保留坏档用于诊断，提示新开。写入失败保留有效旧档、允许当前内存继续游玩并持续提示「尚未保存」，重试成功再清除。设置弹窗、后台、返回、布局切换和资源释放有成对的输入取消及动画停止，不在销毁后回调更新页面。
