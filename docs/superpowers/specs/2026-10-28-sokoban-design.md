## 1. 推荐方案

**单一竖屏游戏页面：统一导航和标题，关卡与计数合为一行，剩余空间交给可缩放棋盘，底部集中操作。** 显示名「推箱子」，稳定游戏 ID `sokoban`，大厅文案「把每一只箱子，推回它的位置。」。

页头、品牌、标题字号和对齐方式与已有游戏一致。进入关卡时默认等比适配，完整显示地图；需要看清大地图时，可在适配尺寸的 100%–200% 范围放大，再拖动查看。缩放和平移只改变视口，保持同一对局与计数。页面保持竖屏，沿用全应用系统栏与安全区策略。

现有 `UiFactory` 基准为 720×1320，棋盘视口占满可用内容宽度，随页面剩余高度伸缩。近方形、细长和较宽地图均用同一套适配公式；大地图通过缩放和有边界的平移查看，避免用固定小窗口或裁掉地图内容来适配。原型保留 8×8 与 8×13 两张原创演示地图，用于观察地图比例、视口和操作区的关系。

## 2. 本轮交付与正式首版边界

本轮交付独立工作树、实际可用的素材/关卡源文件、来源与许可、内容验证材料、完整方案及可操作的简单 UI 原型。浏览器演示用于观察统一布局、移动、推动、撤回、按钮缩放和 pointer 拖动，不是 Unity 实现，也不写正式游戏存档。双指缩放纳入正式实现方案，当前原型未实现或验收该手势。

建议正式首版内容：

- 原创教学 8 关，逐步介绍走动、单箱推动、绕行、目标覆盖、角落风险、先后顺序、撤回与多箱配合；每关必须保存一条验证解法。
- 从 Boxoban 源池选 100 关，分 5 章、每章 20 关；上线顺序由可解证明和人工试玩共同确定。机器搜索成本与解法长度只辅助编排，不直接叫「简单/困难」。
- 四向移动、单箱推动、到位反馈、撤回、重来、选关、通关面板、下一关、离线续局、已完成记录与个人最佳；棋盘支持适配、100%–200% 缩放及放大后的拖动查看。
- 默认开放全部已发布关卡；推荐按顺序游玩但允许跳关，不以卡关阻断内容。选关中展示完成情况，切换到另一关前明确说明仅保留一场进行中的尝试。
- 不加入计时失败、生命、广告、账号、联机、地图编辑器、随机生成、在线下载和运行时自动求解。首版不展示「最优步数」或未经证明的三星阈值。

## 4. 关卡源与配置契约

Boxoban 固定 commit `78011d8c86ad423bfb2e1005012393b4c3c24409`，原始文件 `unfiltered/test/000.txt`，本地名 `Data/Sokoban/boxoban/unfiltered-test-000.txt`。源数据共 1,000 关，每关 10×10、1 人、4 箱、4 目标；源 ID 0–999，不改写源字节。

源文件 SHA-256：`272928a4e7c185fdf84daa523b298750b6ff08703cb0c20d3be7eff93acc5256`。上游 `unfiltered/medium/hard` 是数据集分组，不是本项目的真人难度等级。上游没有逐关附带可回放的解法文件，正式入包必须补齐见证验证。

导入后的每关数据定义如下（字段与示例表示正式格式，当前原型不依赖此生产格式）：

```json
{
  "schemaVersion": 1,
  "levelId": "tutorial-001",
  "contentVersion": "sokoban-campaign-v1",
  "chapter": "tutorial",
  "order": 1,
  "title": "第一只箱子",
  "source": {"collection": "xanadu-original", "sourceId": "tutorial-001"},
  "rows": ["#####", "#@$.#", "#####"],
  "solution": "R"
}
```

符号约定：`#` 墙、空格地面、`.` 目标、`$` 箱、`@` 人、`*` 箱在目标上、`+` 人在目标上。地形与人/箱状态拆开存储，箱移出目标后目标仍存在。数据以左上角 `(0,0)` 为起点，索引 `y * width + x`。保留行内及行尾空格；不对地图执行会改变坐标的 trim。允许原始非矩形 XSB 的未来导入器必须补为显式 Void，再从外部做洪水填充，不能把地图外补空格当可走地板；首版资源保持矩形且有封闭外墙。

正式入包检查：

1. 版本、ID、来源唯一且完整；行数、列数有上限，字符全在白名单；首版教学最大 10 列×14 行，Boxoban 固定 10×10。
2. 恰好一人，箱数等于目标数且非零，人和箱不在墙/外部；可行走格边界闭合。
3. 每关附一条 L/U/R/D 解法，每步通过生产 `SokobanGame` 重放；最后全部箱子到位，步数/推动数与报告一致。外部 Python 验证是前期证据，不能代替生产规则重放。
4. 同一地图的完全重复项去重；保留原作者/源 ID。不修改某一固定 levelId 的地图，任何地图改动更新内容版本或发新 ID。
5. 发布目录包含 manifest、源哈希、规范化地图哈希、解法验证报告。素材与关卡导入结果只在全部通过后替换，失败保留上一份合法输出。

所有 1,000 关留作可扩展源池，首版只入包选定的 100 关与 8 关教学。5 章排序在人工试玩之后冻结；本轮验证见证不能作为已经完成教学编写或难度调优的证明。

本轮已按源顺序检查前 104 关，生成 100 份解法并独立逐格重放通过；源 ID 21、46、65、78 超出单关预算，记录为 `budget_exceeded`，不据此判定无解。结果位于 `Data/Sokoban/verification/verified-candidates.json`；解法为 15–125 步、4–22 次推动。该候选池证明可解，不宣称全局步数最优，也尚未完成正式关卡编排。

## 5. 规则与交互

- 人每次向上/下/左/右移动一格。邻格是空地则走动；邻格是箱且再下一格为空地则推动一箱。禁止拉箱、斜走、同时推两箱、穿墙或穿越边界。
- 有效走动计一步；有效推动也计一步，并令推动数加一。阻挡不计步、不入历史、不写盘。所有箱子都位于目标时通关；初始地图必须不是已完成局。
- 撤回恢复上一次有效动作前的人、箱、步数、推动数，允许连续撤回；重来恢复原始地图，个人纪录保留。胜利后在结果页选择下一关或重玩，不把已获胜的同一尝试反复计数。
- 箱子进入非目标的静态角落时可提示「可能推不回来了，可撤回」。只提示可确定的静态陷阱，不把简化死锁算法当完整无解判定，不自动判负或重置。
- 四向方向盘与编辑器方向键/WASD始终可用。在适配倍率 100% 时，棋盘内一次单指滑动最多提交一步；倍率大于 100% 时，棋盘内单指拖动只平移视口，人物通过方向盘或键盘移动。不在本期加入点格寻路与点箱自动推动。
- 方向盘首版只处理一次按下到正常松开，不做长按连推。同一时刻只有一个操作所有者；触点起始于棋盘或控件后，不跨区域转交。第二根手指在棋盘内加入时，取消尚未提交的人物滑动，交给视口双指缩放；该手势结束后须所有手指抬起，才可接收新的人物移动。第三根手指、取消、切后台、弹窗或离页均取消当前手势。
- 每次棋盘手势按开始时的倍率决定单指滑动或平移，不能在同一触摸途中变成人物移动。缩放按钮介入、适配按钮、视口尺寸变化或双指缩放开始时，取消未提交的滑动与排队方向输入；平移、缩放和手指抬起均不产生额外走动。
- 动画约 80–120 ms，模型先提交、视图后插值。动画期间最多保留一条方向输入，切页清空；后台或撤回立即按最终模型重绘，不从中间精灵位置计算规则。

## 6. UI 与适配

### 单一页面结构

从上到下按现有游戏的视觉规范排列：

1. 导航栏：左侧 Home 图标返回大厅；中央单行 `XANADU / YONDER` 品牌；右侧 Book 图标打开玩法，Settings 图标打开公共设置。导航图标、颜色、尺寸、安全区和间距对齐现有页面，Home 不承担逐层返回。
2. 标题「推箱子」左对齐，使用 720 宽设计基准下的 49 字号（随现有 CanvasScaler 缩放），左边缘与内容区一致。
3. 单行信息栏：左侧关卡选择入口显示关卡名，右侧同一行展示「步数、推动、归位」。计数不拆到另一行；长关卡名按可用宽度省略，选关页显示全名。关卡入口同时承担切关，不另设一排选关按钮。
4. 棋盘视口：占满信息栏与底部操作区之间的剩余内容空间，格子始终正方形；地图缩放与平移均限制在该视口内，不覆盖导航、计数或操作按钮。
5. 底部单一操作区：左侧集中撤回、重来，及下排 `− / 适配 / ＋` 缩放控制；右侧集中上、下、左、右方向盘。操作区不再放常驻说明文字，玩法说明由顶栏 Book 入口承载。

共享设置保存失败与当前游戏保存失败必须持续可见，采用不遮挡操作区的紧凑状态提示；出现时重新计算可用棋盘高度。Android 返回顺序：先关闭玩法、设置、结果等弹层，再回选关，最后回大厅。顶部 Home 直接保存当前已提交状态并返回大厅，取消当前输入及动画。

### 适配、缩放与拖动

适配基准格子大小为 `fitCellSize = min(availableBoardWidth / columns, availableBoardHeight / rows)`。默认 `zoom = 1`，显示完整地图并居中；实际格子大小为 `cellSize = fitCellSize * zoom`，`zoom` 限制在 `[1, 2]`。百分比相对于当前视口的适配尺寸，不是图片原始像素或设备像素比。

`− / ＋` 每次调整 25 个百分点，达到边界时禁用对应按钮；「适配」恢复 100% 并居中。按钮缩放以当前视口中心对应的地图位置为锚点。正式版本支持双指连续缩放，以两指中点对应的地图位置为锚点，并对缩放过程和结束状态执行边界裁剪。双指缩放不触发角色移动或箱子推动。

倍率大于 100% 时，棋盘内单指拖动只平移；视口中地图的边缘不能拖过允许边界而露出额外空白。若某一轴的地图显示尺寸小于视口，该轴保持居中；超出视口的轴允许平移，直到地图边缘与视口边缘相接。恢复 100% 时重新居中并清除多余偏移。视口缩放与平移不增加步数、不写入规则动作历史、不影响撤回内容。

屏幕安全区或可用尺寸变化时重算适配基准，保留相对倍率与归一化地图中心，再裁剪至新的合法范围；不使用旧设备像素偏移恢复视口。切到另一关或重来时回到适配居中；继续同一关时恢复其已保存合法视口。首版教学上限仍为 10 列×14 行，Boxoban 仍为 10×10，缩放能力不会自动扩大可发布关卡规格。

触控目标按真实物理尺寸至少 48dp，不把设计单位直接等同 dp。须覆盖小屏短屏、20:9 长屏、刘海和手势导航安全区；优先保证导航与底部操作区的触控大小，压缩装饰留白，棋盘按剩余面积适配。单行信息栏通过关卡名省略和固定计数字段适配窄屏；正式需验证最高 50,000 步时仍可读、不溢出。

### 原型查看与验证边界

`docs/prototypes/sokoban/index.html` 为单一页面的浏览器 UI 原型，包含 8×8 和 8×13 原创演示地图。可在页面内移动、推动、撤回、重来，使用按钮缩放，并在放大后通过 pointer 拖动查看；这些交互只在当前页面内生效。双指缩放属于上述正式方案，当前原型未实现或验收，不能用桌面 pointer 拖动验证替代。

UGUI 字体测量、Android dp、真实多指输入及安全区仍需在 Unity 和 Android 上另行验收，浏览器原型不能代替这些检查。原型具体已完成检查以同目录 README 为准。

## 8. 存档与恢复

独立 `Application.persistentDataPath/sokoban-v1.json`，使用当前 Newtonsoft.Json 13.0.2 的实际严格解析方式，原子临时文件/主档/备份流程沿用项目惯例。保存 `schemaVersion`、`gameId`、内容版本、levelId、attemptId、完整动作序列、当前人/箱、计数、已完成 ID、个人最佳，以及当前关卡的视口倍率与归一化地图中心。

本次尝试从初始地图重放动作序列，校验终态、人箱位置和计数一致；字段缺失/null/错误类型、重复键、未知版本、越界、重复箱、计数不符一律拒绝该槽。地图版本不匹配时不把旧坐标强塞给新地图，保留仍能对应的完成纪录并提示该关重新开始。新版本迁移必须显式设计，不由默认值掩盖。视口字段同样校验字段与数值类型，合法有限数值在恢复时将倍率裁剪到 `[1, 2]`、归一化中心裁剪到 `[0, 1]`，再按当前地图和视口大小裁剪平移边界；100% 时强制居中。视口调整不得改变恢复后的对局、步数或撤回历史。

每次有效动作、撤回、重来、切关和前后台都保存已经提交的模型。视口拖动/双指缩放在手势结束时保存，按钮缩放或适配在操作提交后保存；不逐帧写盘。一个正式关卡最多保存 50,000 步动作与对应撤回能力；达到上限时阻止继续累积并显示「本次尝试步数已达上限，可撤回或重来」，不截断历史后声称完整续局。文件上限 2 MiB、嵌套深度 12；完整重放只在加载时执行，运行中不每帧重放。

通关集合用 levelId 去重，累计通过关数是唯一已完成关数；重玩不会重复加一。个人最佳保存两个真实元组：最少步数纪录 `(moves, pushes)` 与最少推动纪录 `(pushes, moves)`，分别按字典序比较；不能把两次成绩独立最小值拼成不存在的成绩。结果与纪录、下一关选择在同一次存档事务内保存。

读取先主档后合法备份；两者都坏时保留坏档用于诊断，提示新开。写入失败保留有效旧档、允许当前内存继续游玩并持续提示「尚未保存」，重试成功再清除。设置弹窗、后台、返回、视口尺寸变化和资源释放有成对的输入取消及动画停止，不在销毁后回调更新页面。
