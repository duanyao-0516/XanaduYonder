# 07 黄金矿工：首版玩法与数值方案

状态：首版实现采用的规则规格。开发准备基线为 `ca50db0`（v0.4.0），实施前已合并真实远端 master `b793fe8`；实际实现与验收证据见[验证记录](../../verification-gold-miner.md)。本稿的数值为本项目明确的首版规则。

## 1. 范围与入口

- 大厅增加一张编号 **07 黄金矿工** 卡片，保持既有卡片高度和纵向滚动；卡片进入竖屏模式选择页，不增加两张重复游戏卡。
- **单人探矿**：竖屏，一名矿工；点击非控件区域出钩。
- **双人合作**：横屏全屏，共享矿场、余额、关卡目标和时间；左半屏控制 P1，右半屏控制 P2，两人可同时出钩。橙色 P1、青色 P2，各自炸药数量与本关贡献分别显示。
- 每种模式是一场独立的 **10 关挑战**；各保留一场未结束挑战和历史最好成绩。第 10 关成功后完成挑战，不进入无尽或额外商店。
- 首版包含金块、石块、钻石、神秘袋、移动小动物及携钻动物、五种商店道具、暂停、说明、重试、返回和完整续局。不开设对战、联机、广告复活、充值或另一套独立货币。

## 2. 参考与本项目的取舍

经典参考入口：[GameRival Gold Miner](https://www.albinoblacksheep.com/games/goldminer)、[Two Player Gold Miner](https://www.twoplayergames.org/game/two-player-gold-miner)。后者明确列出双方独立出钩和炸药操作。参考其摆钩、抓取、按重量回收、关卡目标与商店的循环，代码重新实现。

本项目确定采用累计余额过关、关间消费、双人合作与手机触控。10 关长度、以下全部金额/速度/概率、同关重试及确定性生成都是 **Xanadu 首版设计值**，不是对原版精确参数的声明。与纯随机无限关卡相比，有限挑战便于验证难度和完整通关；与固定一张矿图相比，种子变体保留重复游玩的变化。

## 3. 对局循环与时间

`模式选择 → 关卡准备 → 游戏中 → 等待在途钩子结束 → 成功/失败`。

- 新挑战：余额 0，每位玩家炸药 1 根，进入第 1 关准备页。按“开始”后才消耗时间；旋转、加载、说明、准备页均不计时。
- 每关 **60 秒，3,600 个 1/60 秒模拟步**。显示时间为剩余秒数向上取整，最后 10 秒提示变色；5、4、3、2、1 秒各提示一次。
- 提前达到目标仍可继续采矿，时间结束才结算；已无可采集实体且所有钩子闲置时可提前结算。
- 剩余时间到 0：不再接收新出钩；已发射的钩子继续伸出、可能命中并回收，带载回收时仍能使用炸药；动物继续移动，空闲钩子停止摆动。等所有在途动作结束后，比较最终余额与目标。
- 本步的合法入账先于本步的最终结算；每关只结算一次。收获仅在负载到达钩子原点时入账，命中或爆炸不提前加钱。
- 1–9 关成功：显示本关收益、余额和目标，合作再显示双方贡献；点击进入商店。商店完成后进入下一关准备页。
- 第 10 关成功：记录通关一次，显示挑战完成和双方贡献，提供“再玩一局”“返回大厅”。失败提供“重试本关”“返回大厅”，不回退另一模式。
- “重试本关”恢复本关开始前的完整检查点：同一矿图、余额、炸药、增益和 60 秒；本次失败收益全部撤回，商店之前的交易不撤回，也不重新抽取矿图。暂停中的“重试本关”需确认。模式选择中的“重新开始挑战”才清空该模式当前挑战并产生新种子，历史纪录保留。

## 4. 摆钩、抓取和物件

### 4.1 模拟坐标与速度

所有距离使用逻辑单位，与屏幕像素分离；坐标原点在矿场左上，Y 向下。单人矿场 `6 × 7.2`，钩轴 `(3, 0)`；合作矿场 `12 × 5.2`，两轴为 `(3, 0)`、`(9, 0)`。显示时等比缩放，宽高差由背景和布局吸收，不改变规则空间。

| 项目 | 当前规则 v2 值与语义 |
| --- | --- |
| 摆动 | 以垂直向下为 0°，在 −80°～80°往返，60°/秒；初始 P1 为 −35°向右、P2 为 35°向左 |
| 空闲长度 / 钩尖半径 | 0.2 / 0.09；绳索不参与碰撞 |
| 伸出速度 | 7.2 单位/秒，发射后角度固定 |
| 空钩回收 | 5 单位/秒，接触矿场边界立即转为空钩回收 |
| 带载回收 | `2.4 / max(重量, 0.5)` 单位/秒；生效中的力量药水再乘 1.5 |
| 碰撞 | 钩尖扫掠圆与物件圆的首次接触；钩之间不碰撞，回收负载不抓其他物件 |

2026-10-28 根据实机试玩反馈，回收规则升级为 v2：空钩从 8 降到 5、带载基速从 6 降到 2.4。重量、半径、目标、价格与 60 秒规则不变；全部 240 张矿图须用新规则重新生成成功见证。旧 v1 存档的无损升级契约见技术文档 §6.1。

合作左右半屏只限定**输入归属**，不限制钩子到达哪一半矿场。两个钩子争抢同一物件按同一步内更早接触时间获胜；完全相同则 P1 优先。失败的钩子继续检测其剩余路径上的下一件未被认领物件，不扣分、不停止另一名玩家。

### 5.2 离线生成与运行时选图

每模式每关提供 **12 张矿图变体，三种图案各 4 张**，共 240 张。矿图在开发机离线生成并验证，随包交付；手机只按种子选图和抽袋子，不运行路线搜索。这样首帧准备耗时与手机性能不会改变同一种子的结果。

1. 使用非零 `uint` 种子和 xorshift32（左移 13、右移 17、左移 5）；新挑战用系统随机产生种子，保存生成后的状态。布局、袋子使用独立随机状态，按固定顺序从主种子调用两次 xorshift32 派生两个非零状态；商店固定价不消耗随机数。取整数使用 `NextUInt() % exclusiveMaximum`，该轻微偏差是本规则版本的一部分。
2. 单人建立 6 列×5 行、合作 10 列×5 行格点；X 为 `(列+0.5)×宽/列数`，Y 为 `1.2 + 行×(高−1.8)/4`。格点不直接显示。
3. 离线按三类图案分别生成：均匀交错、重矿集中左侧、重矿集中右侧。先用 Fisher–Yates 打乱可用格点；均匀图案再按列奇偶分组、保持组内洗牌次序交错取点；集中图案为大石/大金按 X 稳定排序取靠对应侧的格点，同 X 保留洗牌次序，其他类型按剩余格点的原洗牌次序取点。不在分区后再次洗牌覆盖图案。
4. 按大石、大金、中金、小石、小金、钻石、袋子顺序分配静态物件，实体 ID 按此顺序递增。格点 X/Y 抖动范围为 ±0.04；边缘内缩至少半径＋0.04，任意静态物件距离至少半径和＋0.08。依固定排序依次尝试格点；与已放重矿冲突的点暂时跳过，仍保留给较小物件使用。遍历剩余格点仍放不下时重新生成候选，不降低数量或半径。这也避免合作矿场 0.85 的行距强行挤入相邻重矿。
5. 动物按 ID 分布在 Y=`1.8 + i×(高−2.4)/max(1,动物数−1)` 的水平轨道，初始 X 在半径边界内随机，方向交替左右；初始位置不能与已放置物件重叠，最多尝试 32 个 X。动物轨道允许运行中经过静态物件。
6. 每个候选先查边界、重叠和角度可达性，再用**真实 Core 模拟**回放规划器给出的出钩时刻，确认存在在限时内取得足够收入的路线。不能用“矿物总金额大于目标”代替此检查。
7. 每张离线变体最多尝试 32 个候选；全部失败则该图构建失败，需要修正布局生成或补制同模式/关卡/图案的参考图，并通过相同验证。不能将未经证明的图作为回退带入安装包，也不能悄悄删掉难关。
8. 240 张最终图逐张附上真实 Core 成功输入见证；验证时袋子按 100、无增益、无炸药。每张以 mode/level/pattern/variant 构成稳定 ID，目录有版本和 SHA-256。
9. 运行时加载当前模式/关卡目录，按稳定 ID 排序，排除上一关图案后在剩余 8 张中用布局随机流选一张；第 1 关在全部 12 张中选。选定后才按生效增益用袋子流为袋子各抽一次金额，写入包含完整实体、图 ID 和目录版本/哈希的检查点；续局、重试不再读取目录重建状态。
10. 目录缺失、损坏、数量或版本不符时停留准备页，显示资源错误和“重试/返回”，不扣时间、不消耗种子、不覆写上一份合法存档；不依赖下载修复或临时随机矿图。

离线规划器采用按当前状态枚举“等到下一个可命中对象的角度后发射”的动作、保留最优 128 个状态的有界 beam search；合作动作允许仅 P1、仅 P2 或两者同时发射，动作排序固定为等待 tick、P1 目标 ID、P2 目标 ID。最多展开 20,000 个状态；超过预算视为候选未通过，而不是证明不可解。验收以实际模拟的成功输入见证为准，搜索启发式不参与玩家对局规则。

候选的保底要求：第 1 关取得对应模式目标；第 2–10 关取得 `本关目标−上关目标＋上一个商店可花费金额上限`，按无增益、无炸药、袋子保底 100 计算。合作商店上限取全部商品总价，单人也使用同一上限。这覆盖以恰好达标余额过关后购物的最紧情形；不承诺随意瞄准也能过关。

### 5.3 难度校准门槛

240 张图逐一通过成功见证；另以每模式×每关至少 100 个运行时种子验证选图、图案去重和抽袋重放。试玩目标为首关多数首次体验者一两次能过，后半程需要选择钻石和避石；这属于尚待测量的体验目标，不伪造通过率。发布前记录每关真人尝试数、过关数、剩余时间和卡住原因。若需要调整数值，同步规则版本/表格/见证，不暗改存档中的规则含义。

## 6. 商店与五种道具

商店只在第 1–9 关之后出现，使用采矿所得的同一余额。每店固定展示全部五类商品；价格以本关编号 L 计算，不随机，不用刷新刷价。合作的四种增益共享，炸药购买时明确选择给 P1 或 P2。购买在按下确认后原子扣款/发货，连续点击不能重复购买已经售完的库存。

| 道具 | 价格（L 为刚完成的关卡） | 每店库存 | 效果、期限与上限 |
| --- | ---: | ---: | --- |
| 炸药 | `60 + 10×L` | 合计 3 根 | 指定玩家＋1；每玩家最多 9 根，跨关保留。仅带载回收可用，立刻销毁当前负载并转为空钩回收，不伤周围矿物；无负载或库存 0 不消耗 |
| 力量药水 | `120 + 20×L` | 1 份 | 下一关带载回收速度×1.5；合作两人都生效，不叠加，不加快摆动/伸出 |
| 幸运四叶草 | `80 + 10×L` | 1 份 | 下一关袋子概率改为 20/40/40；不改变地图和已生成袋子 |
| 石头收藏书 | `50 + 10×L` | 1 份 | 下一关两种石块金额×3，重量不变 |
| 钻石油 | `150 + 20×L` | 1 份 | 下一关钻石部分金额×1.5，携钻动物的 30 不翻倍 |

上一店全购费用上限为 `580 + 90×L`；余额不足的按钮禁用并提示差额。允许不买任何东西进入下一关。购买后“下一关还需赚取”的数值立即更新。

四种增益在离店创建下一关检查点时从“待生效”转为“本关生效”，本关成功结束时清除；失败重试从检查点恢复同一增益，不重复扣款。不得带回上一关重新获利，也不得在第 10 关后购物。原有未使用炸药不因换关消失。

## 7. 界面状态与记录

- 模式选择始终竖屏，显示各自“开始/继续”、当前关卡和历史最高通关关卡。进入合作后的准备、游戏、商店、暂停、结算均保持横屏，返回模式选择/大厅恢复竖屏。
- 游戏中主要展示余额、目标、时间、暂停、炸药；合作增加本关 P1/P2 收益。收益包括被该玩家收回的袋子、动物和增益加成，购物不扣贡献。
- 单人记录与合作记录分别保存：最高已通过关卡、最佳挑战累计毛收入、完整通关次数。重试本关不累计失败尝试收入；新的最佳毛收入只在关卡成功提交时更新，10 关完成只增加一次通关次数。
- “返回大厅”保留进度。存档失败明确提示，不能一边显示“已保存”一边丢弃内存局；购买、重试、新挑战、换关等事务失败时留在原状态，详见技术契约。
- 暂停/后台恢复/冷启动续局总是先显示“继续”，不会在用户尚未准备时倒计时。手指在恢复之前已按住时，必须抬起再重新按下才触发出钩。
