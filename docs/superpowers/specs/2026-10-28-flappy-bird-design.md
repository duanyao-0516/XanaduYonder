## 2. 经典玩法与体验目标

调研对象是 Dong Nguyen 的 2013 年原作，原作者页面保留发布日期与截图。[DOTGEARS 原作页](https://dotgears.com/games/flappybird)

核心体验是单手、低学习成本、节奏判断：点击让鸟向上，间歇下落，预判下一组管道缺口。作者采访强调可在屏幕任意位置点按和适合短暂通勤；挑战来自简单动作的掌握。[作者采访](https://davidkushner.com/article/the-flight-of-the-birdman/)

经典计分为每通过一对管道加 1 分，碰管或地面结束，以最高分为目标。[同期实玩记录](https://www.macworld.com/article/667180/flappy-bird-review.html)

未找到原作者公布的重力、上冲速度、管距、碰撞盒及顶部边界参数。以下数值与边界处理是本项目设计，不能声称是原作精确复刻。后来的品牌新作、教程、克隆仓库不作为原版参数依据。

### 首版规则

| 内容 | 设计 |
| --- | --- |
| 动作 | 游戏区一次按下触发一次拍翼；长按不自动连发，松开不另触发 |
| 飞行 | 鸟固定水平位置；受重力下落，每次拍翼覆盖为固定上冲速度 |
| 障碍 | 成对上下障碍向左移动；固定速度、宽度和缺口大小，缺口中心变化 |
| 计分 | 鸟的碰撞主体完全越过障碍对后加 1，每对仅一次 |
| 失败 | 碰障碍或地面立即冻结规则结果；坠落/粒子只是表现，不再加分 |
| 顶部 | 本项目选择软限制：鸟主体不能越过顶部，向上的速度归零；顶部本身不致死，顶部障碍仍正常碰撞 |
| 连续挑战 | 无关卡、无终点、无倍率；首版不自动加速，不加入皮肤经济、复活道具或联网榜单 |
| 记录 | 独立本地最高分；同进程切后台可暂停续玩，主动退出或进程重启从新局开始 |

第一组障碍给足起飞准备时间。缺口中心限定在地面以上有效高度的 `0.30H..0.70H`，缺口高 `0.29H`，因此最短上下障碍仍有 `0.155H`；相邻中心变化不超过 `0.20H`。合法区间必须包含完整鸟碰撞体与安全余量，不能只检查中心。

首版把候选中心离散为 `0.30/0.40/0.50/0.60/0.70H`，从满足相邻差约束的集合取样。实现时用生产物理验证允许的连接及连续路径，将通过验证的连接作为生成白名单；不能只证明每一对各自可过，却无法把动作连接起来。无合法随机候选时沿用上一中心，重复同高的退路也必须先通过验证，不能用夹紧非法值代替。参数或碰撞体变化后重新验收，未通过的配置不启用。可达只表示存在合法操作路径，不保证玩家任意误操作后的状态仍可挽救；有限随机样本不能替代生成契约。

### 状态与误触处理

`Ready → Playing → Dying → Result → Ready`；`Playing → Paused → Countdown → Playing`。

- 大厅进入后停在 Ready，入口点击不能穿透；场地下一次按下同时开始并拍翼。
- 同一时刻仅一个主触点，一次按下只提交一次。第二根手指不额外拍翼；鼠标模拟和触摸不能重复提交。
- 返回、暂停、帮助、设置各自消费事件；它们不能同时触发拍翼。
- 撞击先锁定终局，再做表现；碰撞与得分同一模拟步必须按事件发生时刻排序，碰撞时刻及之后不得计分。
- 结算显示本局/最高，约 0.35 秒后开放“再来一次”；重开进入 Ready，该按钮点击不直接起飞。
- 后台、失焦、帮助、设置、宿主尺寸变化冻结模拟并清空输入；按中断前状态恢复：Ready 回 Ready，Result 保持 Result；Dying 已提交终局，动画取消也进入 Result。只有 Playing 被中断后回 Paused，明确继续后倒数三秒；倒数再次中断回 Paused，下次重新完整倒数，期间输入不缓存为拍翼。
- 进行中离开大厅需明确结束本局；返回键先处理当前弹层，再处理暂停/退出。声音和触感沿用公共设置。

## 3. 小区域还是全屏

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 大厅卡片内直接玩 | 少一次进入 | 与列表滚动竞争；手指遮挡比例大；暂停和结果难以安放 | 不选 |
| 独立页中的 Dino 式窄跑道 | 沿用现有结构，导航空间充足 | Flappy 需要上下躲避；固定竖向世界塞进横向窗会变得很小 | 不选 |
| 独立竖屏页，大场地保留轻量外壳 | 看清上下缺口，单手点击，仍具有合集调性 | 要明确场地比例、安全区和短屏适配 | **推荐** |

“独立页”指进入专门的游戏页面；场地四周仍有合集留白与圆角，导航可见。首版不加额外的全屏开关、方向选择或第二种模式。它与 Dino 都是独立游戏页，但场地形状、操作区和信息密度不同。

### 布局建议

1. 大厅：沿用 `608×350` 卡片与 24 间距，标题、简介、最高分和开始按钮；右侧用橙鸟与云构成小预览。卡片不是活动对局，不推进规则、不写存档。
2. 顶栏：Home 返回大厅；Book 玩法；Settings 公共设置。使用现有图标和按钮状态，不让不同动作都显示 Home。
3. 紧凑标题与一行信息：Flappy Bird；本局、最高、暂停。数值无需占据 Dino 的大面积独立分数区。
4. 飞行场地：占剩余主要高度，整块可点击；首次提示置于场内，开始后消失。没有底部“跳跃”大按钮，也没有常驻规则段落。
5. 暂停/结算：覆盖场地但保留背景上下文，主要按钮突出。保存失败提示保持可见，不挤压飞行世界或让页面静默显示成功。

以 **388×784 CSS px 的安全内容**作为原型主视图，与推箱子对照口径一致，不绘制虚假的系统栏。逻辑场地暂定 `360×600`（3:5，含地面），等比 contain 到导航以下剩余区域。长屏增加周围留白，不能增加前方障碍视野；短屏缩放整块世界，不裁掉地面或上下障碍。开发时对照同一可用尺寸转换至 Unity，CSS px、设计单位、屏幕像素和 dp 分开计算。

主题取自 `UiFactory`：`Paper #F6F4EC`、`Ink #173D35`、`Accent #276653`、`Muted #718179`。场内可以有橙色角色和淡蓝天空，公共按钮、标题和弹窗仍遵循合集风格。

## 5. 初始手感参数

这些是调参起点，不是原作参数，也未经真机调优。令 W 为固定世界宽度、H 为地面以上有效高度，向上为正。

| 参数 | 初始建议 |
| --- | --- |
| 鸟的位置 | x=0.28W，起始 y=0.55H |
| 重力 | 3.5H/s²，向下 |
| 拍翼后速度 | +0.95H/s，覆盖旧速度 |
| 下落上限 | 1.4H/s |
| 障碍速度/宽度 | 0.38W/s；0.16W |
| 缺口高度/相邻中心差上限 | 0.29H；0.20H |
| 障碍间隔 | 1.6s；首对约开局 2s 后到达鸟位置 |
| 碰撞 | 根据可见身体选固定椭圆/简化体，排除透明留白和装饰翼尖；不因扑翼动画改变判定 |

单次拍翼约 0.27s 到顶、上升 0.13H、约 0.54s 返回原高度。先校准重力和上冲，再调整障碍节奏；不能同时乱调所有参数。固定模拟步长与渲染解耦，输入只消费一次；超过约 100ms 的异常帧间隔采用暂停恢复，避免后台补跑导致立刻死亡。

## 6. 与现有 Dino 的复用边界

| 可以借鉴 | 不直接复制 |
| --- | --- |
| `UiFactory` 的主题、字体、按钮、图标 | Dino 竖屏 `656×320` 跑道和大底部双按钮 |
| AppController 的进入、离页、公共设置和前后台连接 | 横竖屏选择、两种方向纪录 |
| 暂停、清空触点、三秒恢复倒数、异常帧处理 | Jump/Duck 双动作所有权、落地长按续跳 |
| 独立存档、严格解析、合法备份与原子替换 | Dino 速度曲线、障碍规则、碰撞体和节日逻辑 |
| 固定输入回放、页面截图、设备验证方法 | 把历史测试通过视作新游戏已验证 |

计划的最窄职责：`Core/FlappyBird` 管理规则与随机障碍；独立 session 管理 Ready/Playing/Paused/Result 及输入门禁；Runtime 页面管理 UGUI、表现和音效；SaveCodec/Store 管理边界解析与磁盘。AppController 只连接卡片、路由、公共设置及生命周期，不扩成所有游戏的规则基类，也不为本需求重构其他玩法。

独立 `flappy-bird-v1.json` 只保存版本、稳定 gameId 与非负最高分，使用真实 Newtonsoft 解析并严格校验缺失/null/错误类型/未知版本/范围/重复键/大小。新纪录在有效得分后保存，终局再保证落盘；失败继续允许玩，提示未保存并保留旧备份。公共声音和触感不复制一份。恢复前台使用同进程内存状态，进程重启不制造“继续游戏”入口。

保存失败时“最高”显示内存最高分，并明确标“未保存”；已保存值独立保留，不能拿内存值假称落盘成功。提示放在固定预留区域，不在失败时改变世界比例；提供重试动作，同时在下一次新纪录、终局及离页时重试。离页后将待保存纪录保留在模块的内存 profile，大厅卡继续显示未保存状态；成功后清除提示。进程在写盘成功前结束会丢失这部分新纪录，退出提示应说明这一点。示例用内存最高 37 / 已保存 36 展示此状态。

## 7. UI 示例与验收

[打开 UI 示例](../../prototypes/flappy-bird/index.html)；[浏览说明与素材记录](../../prototypes/flappy-bird/README.md)。示例使用真实候选图集，演示大厅卡片、准备、飞行、暂停、帮助/设置、结算和保存失败，数据明确标为演示。它用于评审布局、素材与状态，不是可玩 Unity 构建，不能用预览点击模拟代替实际游戏输入验证。

正式实现时至少覆盖：

- 单击、长按、多指、取消、入口/弹窗/重开穿透；首次按下只起飞一次。
- 30/60/90/120Hz 渲染下同输入轨迹一致，长帧不补发动作，碰撞不穿透，穿管只加一次。
- 同步检查终局/计分顺序，保存与结算重复调用幂等。
- 源图透明边界、鸟/管道碰撞体、上下端帽、地面接缝和判定线一致。
- 388×784 原型对照、320 窄屏、短屏、长屏、平板安全区；世界比例固定，最长纪录不挤掉暂停。
- 帮助、设置、锁屏、Home、通知、失焦及返回；离页后不模拟、不留音频/订阅。
- 真解析器坏档、备份恢复、磁盘写入失败与其他游戏文件字节隔离。
- 合并时重新拉远端 master，核对卡片顺序、路由、构造、离页、保存及回归清单。

## 2026-10-28 OPPO 验证后参数更新

用户反馈初始下落加速度/速度偏快，过障碍时来不及反应。实现改为重力 2.2H/s²、拍翼 0.80H/s、最大下落 0.95H/s、管速 0.30W/s、缺口 0.32H；间隔 2.2 秒、首管完整通过 3.2 秒。场地、画面、碰撞轮廓、存档协议不变。全部 13 条同高/相邻连接使用重新生成的生产物理证书，连续入口区间证明未放宽。实测边界与后续反馈见 [验证记录](../../verification-flappy-bird.md)。上方参数表保留为设计阶段的初始建议，不代表最终手感参数。
