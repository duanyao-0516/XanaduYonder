# 成语接龙：玩法、词库与接入方案

原始设计日期：2026-10-26；数据、选词和提示规则按 2026-10-30 更新。旧设备和自动化结果见[历史验证记录](../../verification-idiom.md)，不证明新规则已完成设备验收。个人学习与四槽位保存的当前实现以[选词设计](../../idiom-selection.md)为准；本文保留初始技术接入背景。

玩法与各页面 UI 的简明开发口径见[成语接龙：玩法与页面说明](../../idiom-game.md)。本文保留详细规则、数据结构和技术接入说明。

已确认需求：独立成语接龙小游戏；APP 在左、玩家在右的对话界面；同字和同音两种模式；左右按钮选择机器开局/人先开始；本局双方不可重复；提示跨局免费无限，每名人类玩家每局最多三组，第3组后可继续，用完后可认输；详情弹窗可加入生词本，游戏页可进入生词本二级页；两套成语数据在本机统一清洗，核心内容为成语、拼音、包含典故的释义。

以下规则细节与实现选择承接已确认需求。初次调研基线为 `4289660`；词库清洗的当前产物和验证结果见[数据说明](../../idiom-data.md)。

## 1. 推荐方向与范围

定位为“离线接龙 + 随手学成语”。APP 根据本地词库接龙，回复和释义可追溯到真实词条，安装完成后的首次使用即可断网游玩。

| 方案 | 优点 | 取舍 |
| --- | --- | --- |
| **采用：两套数据按来源保留，本地规则接龙** | 保留双方资料与来源，生成一份统一词库，适合接龙和生词本 | 需要明确字段映射、读音解析与来源完整性检查，详细资料按需加载 |
| 新华词库单独作为主库 | 数据较小，结构简单 | 四字词较少，故事、用法等信息较少 |
| 在线大模型对话 | 可生成更自由的交流内容 | 增加联网、费用和生成错误问题，不符合本项目首版目标 |

首版包含双模式、开局方选择、完整对局、三次提示后的鼓励小结、详情弹窗、生词本、独立存档、大厅入口和 Android 真机验收。朗读、全局词典搜索、联网排行、真人匹配和多种 AI 难度不纳入首版。

## 2. 玩法与判定

### 2.1 两种模式

首次进入默认“同字接龙”，上方可切换“同音接龙”。两种模式分别保留当前对局和最佳接龙条数；切换模式恢复该模式的对局，不把进行中的链条换一套规则重新解释。

| 项目 | 同字接龙 | 同音接龙 |
| --- | --- | --- |
| 相接条件 | 上条末字与下条首字完全相同 | 上条末音节与下条首音节相同，忽略声调 |
| 示例 | 一心一意 → 意味深长 | 一心一意（yì）→ 一帆风顺（yī） |
| 多音字 | 按字匹配 | 按各来源可解析的完整读音对匹配，每回合仅沿匹配到的音对继续 |
| 当前目标提示 | 请接“意”字开头的成语 | 请接读音“yi”的成语，声调不限 |

同音不合并 `ü/u`、平翘舌、前后鼻音或 `n/l`。例如“长驱直入”的 `cháng` 与“长幼有序”的 `zhǎng` 不相同。拼音原文保留声调用于展示，匹配使用单独生成的规范键。

同字目录保留全部 45,776 个四汉字词，同音使用其中至少有一对可解析读音的词。来源释义或读音差异不删词；没有可解析读音的同音提交明确报错，不猜补。首版接受四个完整汉字的词条；输入仅去除首尾空白，不静默去除内部标点、纠正错字或转换简繁体。词库未收录时显示“本地词库暂未收录”，不武断宣称该词不是成语。

### 2.2 一局的流程

1. 新局先显示并排两按钮：左侧“机器开局”，右侧“人先开始”。这时不产生历史、不随机选词；选择后固定本局开局方，恢复已有对局不再询问。
2. 机器开局：APP 按普通/到期复习优先与其他合法词探索策略选择首词，显示左侧气泡。人先开始：输入区提示“输入一个你想到的四字成语”，首词校验四字、收录与未用，同音还须有可解析读音；不要求首尾衔接；即使首词让 APP 无词可接，也按真实规则接受。
3. 玩家点击“发送”。除玩家开局首词外，依次检查完整四字、词库存在、双方本局均未用过、符合当前接字或接音。有效输入显示在右侧，计一个玩家完成的成语，APP 随后回复。
4. 每次提交词条后，先检查是否用尽整个可玩词库；若是则显示“词库挑战完成”。否则，APP 无词可接或玩家无词可接均进入本轮小结，说明“这一轮接到这里”；APP 无词可接时可补充“这个词把我难住了”。不展示“失败/机器获胜”。
5. 每名人类玩家最多使用三组新提示，第3组仍可填入并提交，对局继续；主按钮在额度用完后变为“认输”。当前人认输或主动结束进入小结；新一局重新选择开局方。
6. 主动结束和有进度时重新开局均要求确认。切换模式、查看生词本和返回大厅自动保存，不结束对局。

**去重是规则层约束**：本局双方接受的全部词条组成一个已用集合，玩家输入、APP 回复和提示候选都查询它。有效提交后才占用词条；仅查看提示、填写草稿、查看释义、加入生词本不占用。恢复时从完整历史重建，跨页面或重启不能绕过。新一局才清空该局集合；两个模式不同对局各自去重。若清洗阶段建立了经审核的别名映射，也按同一规范词条 ID 去重。

没有倒计时、体力或输入错误次数限制。错误输入留在输入框中，就地给出具体原因，不进入历史、不计数、不消耗提示或随机状态。

显示“本轮完成 N 个成语 / 最佳 N 个”，N 只计算玩家有效提交，**包括人先开始时的第一词**。机器开局词和回复、仅展示未发送的提示候选不计数；通过前两次提示提交的合法词同样计数。不设置会让用户感到受罚的提示扣分或失败排行。

### 2.3 免费提示、认输与小结

- 提示没有账户、付费或跨局配额。人机用户每局最多三组，本地双人左右各自三组；新局归零。
- 一次新提示针对当前待输入回合生成最多三个合法候选。前两项优先普通词，第三项优先生词且有 5% 机会探索其他合法词；空位先从普通/生词合并池补足，再从其他合法词补足。点选只填输入框，仍需用户发送。
- 当前回合已有提示、看释义、页面重绘和恢复都不重复计次或抽样。提示与回合状态一次性保存，快速连点不重复提交；全库无候选或生成失败不计次。
- 第三组与前两组同样可用，对局保持进行中。用完后主按钮变为“认输”，当前人可继续自行输入或主动认输；本地双人每方各自判断额度。恢复允许双方合计六次历史提示及第3组之后的继续输入。
- 认输产生 `Surrendered = 7`；旧 `HintLimit` 仅保留只读历史兼容，不再由新提示产生终局。机器只有全库没有合法回复才无词可接，轮到的人没有全库合法接法时自动提示结算；优先池为空不结束。
- 小结保留完成数量、双人分方计数和结束原因，提供“再来一局”“生词本”“回看本轮”。回看不恢复输入，退出恢复不重复计数。仅真实刷新纪录才显示“新纪录”。

### 2.4 APP 回复策略

- 所有符合本局去重和字/音规则的词始终有正选择概率。普通词及到期生词为优先范围，其他合法词（包括冷却生词）为探索范围。
- 两范围都有候选时 95% 选优先、5% 选探索；一类为空时另一类获100%。优先内部普通与到期复习都非空时按80%/20%，只有一池就使用该池。
- 池内按正权重随机，普通后继数只提供 1.0–1.3 的轻微倍率；零后继不排除合法词。稳定排序与保存随机状态保证恢复不重新抽样。
- 1,534 词的 Common 表为人工编辑范围，不是词频。全部候选、公式、冷却和提示随机状态详见[选词设计](../../idiom-selection.md)。不保证永远可接，不编造词语。

## 3. 页面与操作

沿用现有米白背景与绿色配色，APP 气泡靠左、玩家气泡靠右。气泡以成语大字和较小拼音为主，颜色及左右位置共同区分双方。

```text
┌──────────────────────────────────┐
│ ‹ 大厅   成语接龙  [生词本]  ⋯    │
│       同字接龙  |  同音接龙       │
│ 请接“入”开头       本轮完成 1 个  │
├──────────────────────────────────┤
│ APP                              │
│ ┌ 一心一意 ⓘ ┐                  │
│ └ yī xīn yī yì┘                  │
│                    ┌ 意味深长 ⓘ ┐│
│                    └ yì wèi shēn cháng│
│ ┌ 长驱直入 ⓘ ┐                  │
│ └ cháng qū zhí rù                │
│             对话区域滚动          │
├──────────────────────────────────┤
│ 请接“入”字开头的成语             │
│ [提示0/3] [ 输入成语……   ] [发送]│
└──────────────────────────────────┘
```

顶部与输入区的接龙提示来自同一规则状态。新局未开始时，对话区显示“谁来开个头？”及左右并排的 `[机器开局] [人先开始]`。标题、模式区与底部输入固定，对话区填满剩余空间；不会把整页缩成位于屏幕中部的小区域。玩法说明明确“第 3 次提示后回顾本轮”，不让结算突如其来。

- 中央对话可滚动；接近底部时新消息自动跟随，正在看历史时保留位置并显示“新回复”入口。
- 使用气泡复用或虚拟列表，长局不会为所有历史同时保留 GameObject。按下后发生滚动拖拽，不触发详情点击。
- APP 回复是本地计算。可用约 150–250 ms 的轻量出现动画，但动画不作为规则层的输入锁；后续有效操作可以结束当前表现并基于已提交状态继续。重复点击同一次发送只提交一回合。
- 默认依靠明确的“发送”按钮。输入法的选字、回车、失焦和 `onEndEdit` 均不直接发送；拼音组合尚未提交时提示先确认汉字。
- 不在输入过程中把字符上限设成 4，否则会截断拼音组合。提交时才校验四字；草稿设置合理的独立长度上限，防止超长粘贴。
- 新一局、主动结束和玩法说明放在页面菜单，避免挤占聊天区域。终局保留完整历史和查看释义能力。

### 3.1 释义弹窗

点击双方任意有效成语气泡，复用公共 modal 容器，显示居中对话框。宽度不超过安全区的约 90%，高度不超过约 75%；标题与关闭按钮固定，正文独立滚动。

显示成语及各来源原拼音，正文逐来源展示原拼音、词义、典故、出处和例句；不裁定来源正误，不选主释义。长典故可展开，缺失时不显示空栏目，也不把出处自动改写成完整故事。近反义词和语法用法不展示。底部主按钮“加入生词本”，加入成功后变为“已加入”；同时提供“复制成语”和关闭入口，并以轻量文字展示资料来源。来自聊天、提示、小结、生词本列表的词条都复用同一详情。

打开详情收起键盘并保留草稿、对话位置；关闭后恢复原位置，不自动弹出键盘。蒙层阻止底层发送与点选。正文按纯文本渲染，关闭 RichText 解析，不把外部数据当作标记或操作指令。

### 3.2 生词本二级页

游戏页右上方提供小尺寸“生词本”按钮，开局前、进行中和结束后都能进入。生词本跨对局、跨模式共用，列表按最近加入排序，每项显示成语、拼音与一行释义摘要。点击条目打开同一详情弹窗；已加入的条目显示“已加入”，另提供明确的“移出生词本”动作，不让重复点击加入按钮意外移除。

同一词条只保存一份；重开不清空生词本。空列表提示“点开成语，加入想记住的词”。首版提供列表查看、详情、加入和移除，不加入背诵计划、熟练度评分或全库搜索。进入只结束视觉动画并保存对局，返回恢复原模式、草稿、聊天位置和终局状态。

### 3.3 Android 中文输入与返回键

现有安全区布局不能代替键盘避让。Unity 6000.3 的 `TouchScreenKeyboard.area` 在 Android 返回零矩形，不能据此估算键盘高度。[Unity 官方说明](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/TouchScreenKeyboard-area.html)

- Android 11+ 使用系统 IME insets；Android 8–10 使用可见窗口区域兼容方案，转换到实际 Canvas 坐标。
- 区分窗口已缩放和键盘覆盖，避免重复上移。输入栏贴在可见键盘上边沿，对话区相应缩短；关闭后恢复安全区布局。
- 浮动键盘可能没有底部 inset，不能以高度为零推断键盘已关闭。
- 区分“输入法抢焦但 APP 仍在前台”和真正进入后台。Android 弹出键盘会触发 Unity 的失焦回调；现有 shell 以 `focused` 阻止输入，不能直接照搬到文字输入页。依据平台前台/暂停状态与 IME 状态处理：输入法抢焦保留编辑和发送能力，真正 Home/暂停仍停止表现并保存，不能仅凭键盘可见就忽略所有失焦。[Unity 生命周期说明](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/MonoBehaviour.OnApplicationFocus.html)
- 返回键顺序：关闭当前弹窗 → 收起输入法 → 生词本返回游戏 → 游戏返回大厅 → 大厅退出确认。若 Android 已消费返回键用于隐藏输入法，不再向下派发一次页面退出；详情从哪里打开，就回到哪里。
- 保留 UGUI 和现有输入系统。新增窄范围 Android 键盘桥接，不迁移整个 APP 的 UI 框架。

需要真实中文输入法验证九宫格/全键盘、候选选字、长拼音、粘贴、回车和快速连续输入；ADB 的文本注入不能替代这部分验收。[Android IME Insets](https://developer.android.com/reference/android/view/WindowInsets.Type)

## 4. 词库调研结论

本次已下载指定版本的原始 JSON 进行统计，结果不是照抄 README。

| 指标 | 京墨独立数据仓 | chinese-xinhua |
| --- | ---: | ---: |
| 实际记录数 / 唯一词条数 | 49,639 | 30,895 |
| 唯一四汉字词条 | 45,776 | 29,502 |
| 四字且释义非空 | 45,772 | 29,502 |
| 上述条目中基础四音节语法通过 | 45,764 | 29,492 |
| 原始文件总大小，十进制 MB | 26.60 | 10.32 |
| 四字且有释义的紧凑 JSON，gzip MB | 7.60 | 3.41 |

以上为初次调研的语法统计，不等于逐条校对。当前目录保留全部45,776个四汉字词；拼音异常、字体诊断及旧排除项仅留审计，无法解析的读音不生成同音边。

新华 README 标注 31,648 条，但固定版本 JSON 实测为 30,895。两库共有 30,858 个词条，按同名合并后共 **49,676** 个词条。新华独有的 37 条中没有完整四汉字词条，仍进入本机整理资料库并标记质量问题；统一库导出一个游戏子集，不重复打包两份数据。

两个源的原始字段都保留在开发快照里，但产品只使用本节规定的统一字段。京墨的结构化 `story` 共有 **3,961** 条，是短典故梗概，约覆盖合并资料库的 **7.97%**，并非每个成语都有完整故事；四字条目中有 3,548 条带此字段。不能以出处替代故事，也不自动编故事补齐。

本轮额外核对发现：同名拼音规范化后仍有 **398** 条带调差异，其中四字词有 **353** 条；这些是待核对差异，不表示某一仓库必然错误。释义规范化完全一致的有 17,213 条，诊断时忽略标点后相同的有 28,184 条；其余差异不能简单拼接或凭字符串长度决定。京墨还存在词义/读音错配样本，故不能“整条记录无条件主库优先”。

### 4.2 当前统一字段规范

稳定词 ID 与来源资料分离。每个同名词的全部来源记录均独立保留，不用来源优先级或字符串长度决定主释义。

| 内容 | 来源与职责 |
| --- | --- |
| `id / word` | 规范正文与稳定词 ID，不模糊合词、不自动改字 |
| `sourceVariants[]` | 每条源记录独立的 `sourceKey / sourceLabel / sourceRecordId`、原拼音、词义、典故、出处和例句 |
| `gameReadings[]` | 各来源可机械解析的四音节读音及成对首尾音，不猜补读音 |
| `senses[] / quality.reasons` | 原有差异诊断，仅用于审计，不决定展示答案或四字准入 |
| `gameSenseId` / 详情 `SenseId` | 稳定内容身份；单义可沿用旧 ID，多来源使用资料集合 ID，不代表主释义 |
| `sourceRecords / versions` | 原始文件、记录行号/ID、固定版本及规则摘要 |

详情按 `Sources` 展示每条来源：`SourceKey, SourceLabel, SourceRecordId, Pinyin, Meaning, Stories, Origins, Examples`。来源原文中的占位、差异和格式仍可查，不把另一源改写为标准答案。缺字段不补造文字；类型异常继续记入审计。`source/derivation` 归出处，`story` 归典故，`quote/example` 归例句；不替换例句中的符号或扩写故事。

无可解析音对的四字词在同字模式可用，同音提交给明确提示。解析可以接受无调原文，但不补调；匹配去声调并保留 ü/u 和其他音节区别。每回合只沿匹配到的音对继续，不能从一种读音取首音、另一种读音取尾音。

### 4.3 全量本机整理与导出

1. 五个景墨分片、新华完整文件及许可固定 commit/SHA256，保留原始快照，离线可重跑。
2. 规范正文采用 NFC 与首尾去空白；全部80,534条源记录可追溯，归并为49,676个唯一词。每条源资料独立保存，不因同源重复、标点近似或跨源一致而丢失来源记录。
3. 全部45,776个四汉字词进入目录，非四汉字3,900词留在统一库。释义/读音冲突、缺字段、字体诊断和显式旧排除原因不再删四字词。审计记录与游戏目录可以重叠。
4. 所有来源可解析四音节生成成对首尾键；不能解析的原拼音仍展示。`pinyinDisplay` 按稳定来源顺序连接不同原拼音，不合成标准读音。
5. 移动目录9列为 `[id,word,pinyinDisplay,firstKey,lastKey,definitionId,chunk,common,[[first,last],...]]`。实际同音使用第9列；无读音时单键为空、音对为空。
6. 详情每片最多256词，共179片，逐来源保留完整资料。生词本保存带来源的全文快照；超出已有长度/文件上限时报错并回滚，不截断。
7. 固定排序、gzip时间戳和校验和保证可复现。验证来源守恒、唯一身份、完整详情引用、所有读音对、无读音同字路径及重复导出；字体和设备显示单独验收。

清洗规则、目录版本和重跑命令见[数据说明](../../idiom-data.md)。来源或规则变化使用新的忽略目录，本次为 `artifacts/idiom-cleaned-preserved`。旧42,851词目录及其设备验证是历史基线，不代替新资源验证。目录版本不兼容仍保护原存档，不自动迁移、清空或绕过校验。

## 5. 状态、存档与异常

### 5.1 规则层拥有完整回合

`IdiomGame` 是本局状态唯一来源，纯 C# 且不引用 Unity。UI 不能自己追加有效历史或决定胜负。

一次有效提交的流程为：校验玩家输入 → 确定 APP 回复或终局 → 一次性提交完整回合与记录 → 尝试原子写盘 → 展示双方气泡。回复不依赖定时器才进入存档；出现动画只是已提交状态的表现。机器首词由独立的开局动作提交；玩家首词仍沿用提交链路，只免除首尾匹配。提示是独立状态动作，三次都只记录候选与次数，不结束对局、不额外产生玩家或 APP 消息；认输是独立终局动作。

离开页面、切换模式、打开弹窗、暂停或真正的应用失焦时立即结束尚未完成的表现，按模型重绘；仅 IME 抢焦时不清空编辑或锁住发送。恢复时不会重复追加 APP 回复、重抽随机数或重复增加最佳记录。计算、保存、呈现通过回合编号去重，旧页面的详情异步结果通过请求标识失效。

### 5.2 当前持久化契约

当前保存入口为 `Application.persistentDataPath/idiom-learning-v1.json`，`schemaVersion=1`、`gameId=idiom-learning`；四组对局、个人学习资料和生词本原子保存，文件上限64 MiB。旧 `idiom-v1.json` 与 `idiom-notebook-v1.json` 不迁移、不覆盖。详细字段与所有权见[选词设计的保存章节](../../idiom-selection.md#状态所有权与保存)。

历史、先手、当前方、字/音规则、随机状态、草稿、提示事件和结束原因都严格校验。提示每名人类玩家最多三次，双人最多六条历史提示；第三次之后允许继续消息。恢复按各提示发生时的历史验证合法性，不能用最终已用集合误判后来提交过的提示词。新局不产生 `HintLimit`；`Surrendered=7` 记录当前人认输。

同音恢复从完整历史逐步重建可用尾音对，不能只看最后一个词的所有读音。目录版本不兼容时保护原文件，不自动迁移或改判链条。主档损坏可尝试合法备份；版本不兼容或无可用备份时阻止自动写入，等待已有归档重建流程。归档失败保留原文件并报告。

使用临时文件刷盘、原子替换和备份。普通对局保存失败保留旧合法文件和内存进度，显示具体错误；词库未就绪或旧档受保护时，草稿、失焦和离开回调不能用空状态覆盖原档。其他小游戏存档不受影响。

### 5.3 生词本资料快照

每项保存稳定词ID、资料内容身份ID、原拼音、加入时间、目录版本与带来源的完整资料文本；同词仅一项，不随新局清除。快照包括所有来源的词义、典故、出处和例句，列表摘要不得覆盖保存全文。

加入、移除、记住采用已有事务保存；写失败时回滚生词本及共享学习资料，不假报成功。保持现有文本长度和文件上限，超限明确报错，不能截断或静默丢来源。当前身份与版本兼容时显示当前完整详情，否则受现有版本和坏档保护约束，不自动删除旧资料。

### 5.4 异常界面

- 目录索引缺失或校验失败：显示模块加载失败和重试入口，其他小游戏仍可进入。
- 某条详情分片读取失败：保留已验证的成语与拼音，显示“详情暂不可用”和重试，不破坏对局。
- 错误输入：就地提示“请输入四字成语 / 本地未收录 / 本局已经用过 / 需要接某字或某音”，保留草稿。
- 可选字段缺失：省略对应小节。字体覆盖在导入阶段校验；真机补验罕见字显示。

开发排期以全量清洗冲突报告和中文 IME 验证结果为依据。清洗完成要求全量记录有明确去向、自动检查通过、各来源原文及差异可追溯，冲突不删四字词；不将其表述为四万余条成语已经逐条人工考据。

必须通过的验收：

- 两种模式 × 两种开局的四组路径均可有效接龙、错误重试、提示、结算、重开；玩家首词计数正确；恢复不会重新选择开局方。
- 玩家、APP 与提示统一检查双方已用集合；草稿、看释义、加入生词本不占用；新局重置，切页与重启不重置。
- 每人三次新提示均可继续，第三组仍可提交；用完后主按钮为认输。本地双人各三次、恢复最多六条提示历史，认输与无词可接分开校验；连点、失败和重复查看不多计。
- 多音字按来源成对读音处理，不跨对组合，声调忽略但 `ü/u` 和平翘舌不混淆；无效输入不改变历史、计数或随机状态。
- 全部四汉字词保留，各来源原文可追溯；无解析音同字可用、同音明确提示；配对读音不交叉，APP和提示只给出本模式合法词。
- 双方新旧气泡、提示、小结、生词本条目都能看详情；释义包含有来源的典故，缺故事不编造；长内容可滚动，滚动聊天不误开弹窗。
- 生词本加入幂等、跨局跨模式保留、可移除；写失败不假报成功；二级页返回保留对局与滚动位置，词库变化不静默删除收藏。
- 真实中文输入法候选确认不会误发送；键盘不遮挡输入栏；键盘保持打开时仍可发送；键盘打开后按 Home 仍正常暂停保存；返回键不把一次收键盘变成退出游戏。
- 快速连点、动画中切换、详情加载中退出、Home/失焦/杀进程恢复均不产生重复回复、遗漏回合或重复计数。
- 主档损坏、备份恢复、写入失败、词库版本变化均走明确错误路径；词库未就绪/坏档待处理时的退出不能覆盖原档，诊断归档失败不清除原文件；其他小游戏存档不受影响。
