# 成语发送时的键盘过渡建议

状态：最初按用户要求仅调查；用户随后明确批准实施，并要求增加发送后是否收键盘及是否显示拼音两个开关。当前实施入口见[实施计划](../plans/2026-10-30-idiom-keyboard-and-bubbles.md)，最新页面行为见[玩法文档](../../idiom-game.md)。以下保留问题分析及方案依据。

## 已确认的代码路径

1. UGUI 在发送按钮的 pointer down 时取消 InputField 的焦点，原生键盘开始关闭；pointer up 才触发发送。人机 Submit 不主动 HideKeyboard 也会经历失焦，双人还会显式 HideKeyboard。
2. `IdiomPage.Layout` 在按住时冻结布局以保障点击。松手后直接更新 footer 位置与聊天 viewport 高度，没有位置过渡。
3. `IdiomVirtualList.Tick` 随高度变化重新调整滚动偏移。现有 0.18 秒淡入只作用于最后一条消息，不作用于整个游戏区或输入栏；没有发现发送时整页隐藏或重建的路径。
4. Java bridge 返回缓存测量值并异步调度新测量，C# 再结合当前 Screen.height 和 SafeDesignFrame 换算；过渡期间是否混用不同帧的数据需要真机时序记录确认。同步存档耗时也尚未测量，不能直接认定为闪动根因。

## 建议方案

优先记录一次真机发送时的焦点、IME 可见性/高度、屏幕和安全区尺寸、footer 位置、聊天滚动偏移以及保存耗时，确认是几何跳变、滚动锚点变化还是主线程停顿。

- 人机连续输入可选择发送时保留键盘与输入焦点，直接避免一次收起/重开；必须在 pointer down 的焦点交接阶段处理，不能等 click 后再激活输入框。双人交接、返回、切页、手动收键盘仍保持明确的关闭路径。
- 若保留“发送后收起”，先让窗口/安全区/IME 尺寸作为一致的布局快照应用，并确保一次关闭只触发一轮布局收敛。
- 在稳定几何后，让聊天 viewport 与输入栏同步跟随系统键盘过渡；拿不到连续进度时，再尝试约 180–220 ms 的缓出位置过渡。标题不参与移动。消息列表处于底部时保持贴底，看历史时保持当前消息及其屏幕偏移，避免每一帧强行滚到底。

不建议直接给整个 Canvas 加淡入、缩放或整体位移动画。先明确焦点和布局时序，才有条件把动画做顺。后续验证应覆盖人机/双人、两种接龙规则、有效/无效发送、快速连点、提示选词、手动关闭、候选字确认、短屏及后台恢复。
