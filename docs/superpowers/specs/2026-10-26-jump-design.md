# 第二款游戏：跳一跳

用户要求完整接入第二款游戏，并明确视觉采用原版微信跳一跳的方案。实现采用真实三维物体、斜俯视正交镜头、按住压缩蓄力、松手翻转跳跃和落台后镜头跟随；由 Unity 原生渲染，独立编写代码与几何素材。延续合集的米白、墨绿和暖色点缀。

## 完整游玩范围

- 大厅同时提供 2048 与跳一跳入口，显示各自最高分；两款游戏可各自继续。
- 当前平台与下个目标平台交替沿世界 X/Z 方向延伸，随机距离与尺寸，难度逐渐增加但所有平台均可达。
- 按住游戏区域蓄力，松手跳跃，时间映射到距离；短跳仍在原平台时可以继续，落空结束。中心落点连续奖励 2、4、6…；普通落台 +1 并清空连续中心次数。
- 角色蓄力压缩、起跳翻转、抛物线、落地回弹、坠落、平台阴影和镜头平滑推进。角色脚底与可站立平台表面严格一致。
- 分数、最高分、玩法说明、确认重开、失败重开、返回大厅；共用声音和触感设置。声音包含蓄力、起跳、落地与失败反馈。
- 暂停/失焦/打开弹窗取消尚未提交的蓄力；已经松手的跳跃先提交唯一模型结果，动画可安全结束，恢复不会重复计分。退出页面禁用相机并取消输入。

## 边界与职责

- `Core/Jump`：纯 C# 状态与随机生成；坐标每次成功落台重新归零，避免长局精度退化。快照包含确定性随机状态、平台、玩家落点、分数、步数、连击和结束状态。
- `Runtime/Jump/JumpPage`：游戏生命周期、存档、分数和弹窗请求；`JumpSceneView`：独立相机、三维素材、表现；`ChargeGesture`：单手指输入所有权及取消。
- `AppController`：公共导航、弹窗、设置与页面路由。2048 规则与旧 JSON 不改动。
- 跳跃存档使用独立 `jump-v1.json` 和备份，沿用原子写入及损坏恢复策略。严格校验实际 JSON token、版本、数值有限性、范围及跨字段不变量；坏档不影响 2048。
- 不增加账号、联网、广告、榜单、微信 SDK 或外部资源。已有发布版 v0.1.0 的数据保持可读；版本更新为 0.2.0/versionCode 2。
