# 贪吃蛇玩法与界面设计草案

日期：2026-10-28。范围：XanaduYonder 的 Unity / Android 离线小游戏。用户已选择「经典无限挑战＋障碍闯关」，本文保留设计阶段的调研、完整规则方案、关卡配置草案，以及遵循推箱子截图样式的经典与障碍关卡独立 UI 示例。

实现状态（同日更新）：用户确认后已接入 Unity，等级下拉按补充要求参考数独；运行截图、独立 Android 验证包及尚未完成的真机验证见[实现与验证](../../snake/verification-implementation.md)。正文中的设计阶段范围和待调优说明保留作原始依据。

## 1. 建议方案

采用单一竖屏页面棋盘，以用户提供的推箱子截图为界面基准，固定使用 APP 纸色与墨绿。棋盘始终完整可见，固定 20 列 × 24 行；不同设备只做安全区内等比适配，不改变地图、速度、蛇长或食物。经典默认四边穿越，可在新局选择围墙；闯关的边界由关卡定义。经典没有食物数量目标，但填满棋盘仍然胜利结算。

首版包含两个模式、三档经典速度、12 个原创静态障碍关卡、独立续局、本地纪录、帮助、暂停与满盘结算。暂不引入移动障碍、随机落墙、炸弹、传送门、道具、联网排行和每日任务。这些机制会同时增加输入、可解性与难度问题，适合核心手感完成后再评估。

## 2. 调研结论与来源界限

Snake 不是一个拥有统一关卡表的单一游戏。公开作品里同时存在撞墙版本、穿墙版本、无障碍追分和带迷宫的闯关模式；因此这里明确选定本项目规则，不以「经典」两个字省略边界契约。

[Visnalize 的 Brick 1100 Snake II 文档](https://visnalize.com/brick1100/games/snake)描述了自动前进、不能倒退、四边穿越、自身与迷宫墙碰撞、经典和 Campaign 等模式。这是现代复刻作品的开发者文档，不是 Nokia 原版规格。本项目参考其玩法分类，不复制其素材、地图、积分公式或商业机制。

[Snake '97 开发者指南](https://snake97.com/guides/snake-2/)也介绍穿边回到对面、迷宫和限时奖励；说明「边界可穿越」与「地图内部存在障碍」可以同时成立。限时奖励本轮不采纳。

素材的下载、许可证、实际文件、缺件和替代方式见[素材调研台账](../../snake/assets-research.md)。没有找到可直接作为本项目发行内容、授权和适配都已核清的完整 Snake 关卡库。Kenney Tiny Dungeon 的 Tiled 示例地图是地牢素材示例，不等于贪吃蛇已验证关卡。因此本轮提供原创关卡配置，明确标为待试玩调优的草案。

## 3. 玩法规则

### 3.1 共用规则

| 项目 | 首版约定 |
| --- | --- |
| 坐标 | 左上角 `(0,0)`，x 向右，y 向下；范围 x=0..19、y=0..23 |
| 开局 | 长度 4；头到尾依次 `(6,20),(5,20),(4,20),(3,20)`，向右 |
| 运动 | 自动按固定逻辑 tick 前进一格，渲染插值只影响画面 |
| 转向 | 上下左右，禁止直接反向；每 tick 最多消费一次转向 |
| 食物 | 同时 1 个，吃到后增长 1 格、食物计数加 1、得分加 10 |
| 失败 | 撞自身、内部障碍、solid 边界；没有复活或扣血 |
| 暂停 | 暂停、设置、帮助、返回、失焦、后台都停止逻辑并清空待处理输入 |
| 恢复 | 对局恢复后停在暂停态；用户点继续，显示 3 秒倒计时后才重新前进 |
| 结算 | 终局只记账一次，终局后输入和计时均停止 |

吃食物后的增长立即生效。非增长步允许走入「这一 tick 正好离开的尾格」；增长步尾格不会离开，仍算自身碰撞。输入队列长度最多 2，方向相对队列末尾（空队列时相对当前方向）检查，丢弃同向重复和反向请求，避免同帧两次转向造成原地掉头。

### 3.2 四边穿越

`boundary = wrap` 时，右边 `(19,y)` 向右进入 `(0,y)`，左边反之；下边 `(x,23)` 向下进入 `(x,0)`，上边反之。可实现为 `(nextX + width) % width` 和 `(nextY + height) % height`。

穿越只处理棋盘外边缘，不允许穿过内部障碍。坐标归一化后仍检查障碍和蛇身，包括对面出口正好被蛇占据的情况。画面在边缘分别绘制消失段和出现段，不能把头从右边横穿整个棋盘插值到左边。

`boundary = solid` 时，越界立即失败；围墙是边界规则，不在 480 个格子中扣除外围一圈。地图中的障碍才占格子。底部左侧的「四边相通」控件显示开/关，棋盘边缘出口标识表示 wrap，实线边框表示 solid；「碰墙结束」的解释放在玩法说明中，不作为底部常驻提示。颜色不是唯一提示。

经典的边界只能在新局配置时选择。已有对局点击「四边相通」开关时，先暂停，再确认按目标边界新开一局；确认前不得改变当前对局的边界，取消后保留原局与原边界并停在暂停态。闯关的同位控件只读显示本关开/关状态，不能修改关卡规则。穿墙／围墙、三档速度各自记录最高分，避免规则不同的成绩混记。

### 3.3 满盘胜利与结算顺序

`playableCellCount = width * height - distinctObstacleCount`。所有非障碍格必须静态连通；蛇长达到 `playableCellCount` 即为满盘，不要求占据障碍格。经典空地图为 480 格，初始 4 格，因此吃到第 476 个食物后胜利，基础得分 4,760 分。

每个逻辑 tick 按以下顺序处理：

1. 消费最多一个合法方向，计算下一格并处理 wrap/solid。
2. 判断是否吃食物，按本步尾格是否离开检查自身碰撞，再检查障碍；碰撞则失败并返回。
3. 提交移动和可能的增长，更新食物计数、分数与占用集合。
4. 若蛇长等于可行走格数，进入 `WonFullBoard`，清除食物，结算并立即返回。
5. 否则，闯关达到 `targetFood` 则进入 `WonTarget`，结算并返回。
6. 仅当本步吃食物且仍在进行时，从未被蛇/障碍占据的格子列表中等概率选择下一个食物。

禁止用「反复随机直到抽到空格」生成食物。枚举剩余格子再选索引；剩余为 0 时不调用随机接口。若未满盘却找不到候选，是数据或规则错误，停止并保留可恢复存档，不能冒报胜利。食物可出现在蛇身暂时围住的空区：这是路径规划挑战，不能把临时不可达误当作满盘。

满盘和吃食目标同 tick 达成时，满盘优先；纪录、通关奖励、页面弹层均只触发一次。终局按钮为「再来一局／返回大厅」；障碍关卡获胜后另有「下一关」，第 12 关显示「本章已完成／重玩关卡」。经典不在满盘后继续计时、无限加速或自动扩图。

满盘界面展示「满盘通关」、覆盖率 100%、蛇长 / 可行走格、食物数、得分、用时、边界和难度。没有时间奖励或额外分数，最高分到上限后以更短有效游戏用时作为满盘纪录，暂停和倒计时不计时。

### 3.4 经典无限挑战

| 难度 | 开始 tick | 每吃 5 个食物 | 最快 tick |
| --- | ---: | ---: | ---: |
| 轻松 | 240 ms | 减少 5 ms | 160 ms |
| 标准 | 200 ms | 减少 5 ms | 100 ms |
| 挑战 | 160 ms | 减少 5 ms | 80 ms |

公式 `max(minTickMs, initialTickMs - floor(foodEaten / 5) * 5)`；调速从下一 tick 生效。所有模式每个食物都为 10 分，不以倍数掩盖速度差异；纪录按规则分组。以上数值是待真机校准的首版参数，不宣称已经验证好玩。

经典没有内部障碍，以转向、穿边和自身避让建立基础体验。想挑战地形则进入障碍闯关，避免经典里突然出现新规则。

### 3.5 障碍闯关

12 关分四章，每章 3 关，逐步引入边界、孤岛、隔断和回廊。关卡内速度固定，首关 220 ms，末关 140 ms，食物目标由 8 递增到 30；每关独立开局，不把上一关的长蛇带入新地图。进入前展示完整地图、目标、边界和速度，首关即解锁，完成上一关解锁下一关，可重玩已解锁关。

首版只采用静态、始终可见的障碍。地图不会在蛇头前突然长出墙，不设置只能用道具逃脱的局面。障碍让路线和转弯成为挑战，不额外增加惩罚。地图采用至少两格宽的通道设计；几何校验只能排除静态错误，不能证明任意食物序列、任意蛇长和任意走法都可解。

完整逐格坐标见 [levels-v1.draft.json](../../snake/levels-v1.draft.json)，关卡表与校验说明见 [levels-notes.md](../../snake/levels-notes.md)。这份数据足以驱动地图预览和后续加载器，不是从商业游戏导出的关卡，也尚未被生产运行时加载。

## 4. 单一页面棋盘与独立模式示例

页面遵循用户提供的推箱子截图，经典与障碍关卡各提供一个独立 UI 示例，两者使用相同的页面结构，另保留独立的经典满盘结算示例。页面沿用项目竖屏设置，在安全区内展示完整 20×24 棋盘，不侵入刘海或系统手势区。棋盘不提供平移、缩放或显示模式切换；设备宽高变化时等比适配，逻辑网格不变。

| 区域 | 统一布局与行为 |
| --- | --- |
| 顶部导航 | 左侧 home 图标返回大厅，中间居中显示 `XANADU / YONDER`，右侧依次为玩法书本和设置图标；游戏标题不挤在导航同一行 |
| 标题与进度 | 下一行左对齐显示「贪吃蛇」，随后展示当前模式及必要的得分、速度或关卡目标；经典和闯关各自呈现对应信息 |
| 棋盘 | 参考 608×729.6 设计单位，20×24 格完整可见，置于页面中部 |
| 底部左侧 | 放置「暂停」「重来」及「四边相通」开/关控件；经典按新局配置或暂停确认后新开局生效，闯关在同一位置只读显示关卡固定状态 |
| 底部右侧 | 方向十字键参考推箱子截图排列：上、左、右、下围绕中心留白，四个方向为独立触控目标 |
| 玩法说明 | 通过右上书本查看转向、边界和碰撞规则；底部不放操作提示或「不能掉头」等常驻文字 |

以 720×1320 设计基准排版：导航约 y=34..92，标题单独位于下一行并与棋盘左边缘对齐，模式和进度位于标题下方；棋盘参考 x=56/y=240/w=608/h=729.6，底部操作约 y=1000..1240。短屏先减少装饰留白，再以 `min(可用宽/20, 可用高/24)` 计算格边长，保留左右操作区和完整棋盘；控制按钮物理触控范围目标至少 48 dp（需要真机换算验证，不能把设计单位直接当 dp）。

固定沿用 `UiFactory` 的纸色 `#F6F4EC`、墨绿 `#173D35`、强调绿 `#276653`，使用已有 Noto Sans CJK 字体。APP 示例的背景、文字和控件颜色不随聊天界面或系统的明暗主题改变。地格采用米色 `#E9DFC5` / `#ECE3CD`，障碍采用青灰色 `#819C9E` 及墙块纹理，呼应推箱子截图。蛇头有眼睛和朝向，食物为暖红圆果，蛇身与障碍不靠颜色区分。形状、坐标和命中范围一致；圆角/阴影不改变格子碰撞规则。

界面状态：新局配置、进行、暂停、设置/帮助、选关、目标通关、满盘通关、撞墙/撞身失败、存档异常提示。重来或切换经典边界均需在暂停后确认新局，确认前保留当前对局；暂停层显示规则摘要，恢复倒计时，不能点穿到棋盘。经典示例展示本局分数与边界配置，障碍示例展示关卡名称、食物目标及固定边界。目标通关与满盘结算沿用各模式的规则。每个示例仅在产品画面外标注「UI 示例」，产品内部不添加调研或实现状态解释；正文交付明确说明示例不是可玩游戏，不包含实际游戏循环或真实存档。

## 5. 操控与生命周期

默认使用底部右侧方向十字键（按下即请求一次转向，按住不重复提交）；棋盘与明确划定的非按钮操控区域也支持手势，键盘方向键 / WASD 用于编辑器验证。手势超过阈值即提交，移动中可重新建立锚点识别下一次拐弯，不要求抬手才转向；短点按不转向。禁止直接掉头仍是逻辑规则，玩法书本内说明，不在底部常驻显示。现有 2048 `SwipeGesture.End` 在抬手才提交，不能原样用于 Snake。

手势只接管从游戏操控区开始的首个有效手指，禁止 UI 按钮手势漏入棋盘；cancel、第二指干扰、失焦、退出、重新布局时清空手势和方向队列。按钮与滑动进入同一带序号输入通道；同帧按照采样时间和序号排序，避免两套组件直接改方向。使用非增长步的尾格释放规则检查连续转弯。

逻辑计时不依赖渲染帧率。前台累计时间达到 tick 才推进，正常帧不丢 tick。若帧间隔大于 250 ms 或将积压超过 2 tick，则自动暂停并重置累计器，提示用户继续，避免卡顿后补跑数格导致无法操作的死亡。后台不补跑；返回后不会突然加速。该策略仍需低端 Android 设备验证。

## 6. Unity 接入与数据边界

| 模块 | 责任 |
| --- | --- |
| `Core/Snake` | 纯 C# 的格子模型、移动/碰撞/增长/满盘、规则配置、事件和只读快照；不引用 Unity |
| `SnakeSession` | tick、输入队列、暂停恢复、单次终局、有效游戏计时 |
| `SnakeProfile` | 经典六种规则组合的独立续局和纪录、闯关一份活动续局、解锁与关卡纪录 |
| `Runtime/Snake/SnakePage` | 页面、帮助/暂停/结算、宿主回调、声音/触感开关 |
| `SnakeBoardView` | 20×24 格、蛇/食物/障碍、边缘穿越分段显示；不判断输赢 |
| `SnakeInput` | Unity 触摸/按钮/键盘适配，首指所有权和取消处理 |
| `SnakeSaveCodec` / `SnakeSaveStore` | 严格 JSON 验证、原子写入与备份恢复；独立 `snake-v1.json` |
| `Resources/Snake` | 经审核的地图配置、选用音效、最终自绘/授权图形及许可证 |

`AppController` 仅增加 Snake 入口、独立 page、进入/离开/暂停/设置回调、纪录摘要；沿用游戏卡高度 350、间距 24 和大厅滚动。游戏的最终序号在集成时按当时 master 排序，不在并行开发中预占。已有七款游戏的存档和规则不改。单一页面布局复用 `UiFactory` / `SafeDesignFrame` 和现有导航图标，Snake 负责棋盘与底部左右操作区的适配，不依赖扫雷的缩放/总览逻辑。

存档字段包括 schemaVersion、rulesVersion、levelPackVersion、活动模式、经典边界/难度、关卡 ID、头到尾有序坐标、方向、食物、已吃数、分数、逻辑 tick 数、有效用时、随机状态、状态、sessionId、单次结算标识和纪录。蛇必须连续（wrap 邻接要考虑对边）、坐标唯一、没有障碍重叠，food 可空仅允许终局；进行局食物必须为空格。严格验证缺字段、null、错误类型、越界、重复和未知枚举，不以 C# 默认值替代输入校验。

恢复时重新验证 `length=initialLength+foodEaten`、分数、容量与终局一致性；`WonFullBoard` 要求 length 等于容量。存档 `levelPackVersion` 取配置顶层 `packVersion`，当前为 `snake-levels-v1-draft-20261028`；障碍、速度、目标或边界等关卡内容变化均必须更新此版本，`schemaVersion` 只用于数据结构。地图更新不得静默换掉进行局的障碍；版本不兼容时提示该局无法继续，保留旧文件和有效纪录，新开一局使用新版本。开始/吃食/终局/主动暂停/离开/后台保存，前台移动时每 2 秒定期 checkpoint；在写入成功且调度正常的前提下，突发进程终止最多丢最近 2 秒，正常离开保存最近完成的逻辑 tick。活动手指、插值帧和方向队列不写盘；恢复时重置时间累计器和队列。写盘失败要可见提示，不能显示「已保存」。

## 7. 素材落地范围

最终推荐用本项目原创几何绘制蛇头、直身、转角、尾巴、果实、墙块和边缘出口，保证在 20×24 小格中清晰，避免为素材更换引擎或主题。网上找到的 Snake Sprites 2D 可作为圆节蛇备选，其实际组件是否覆盖转弯和尾巴以台账为准。保留实际来源、作者、许可证和 SHA-256；网页允许免费下载不自动等于可再分发。

完整美术需求是：头四向（可旋转）、身体直段两向、弯段四向、尾四向、眼睛/失败眼、1 种食物、障碍、底格、wrap 出口与 solid 边框、吃食/撞击/通关的简单反馈。home、设置、暂停、重来和玩法书本复用项目已有图标体系。首版声音只需转向反馈可选、吃食、按钮、失败、通关、倒计时，沿用全局声音/触感开关；不要求背景音乐。

## 8. 后续开发顺序与验收

1. 实现纯 C# 规则和独立测试：wrap 四方向、solid、增长/尾格、满盘、食物生成、输入队列、计分和三档速度。
2. 定稿关卡载入与校验：固定内容版本，执行几何检查，再对每关多种随机种子做模拟与人工试玩，调整速度/目标。不能把静态连通冒充动态可解性证明。
3. 接入 Unity 单一页面棋盘、统一导航、底部左侧操作与右侧方向十字键、暂停/倒计时和两个模式，核对固定配色、真实格子边界与穿边动画。
4. 接入独立存档、幂等终局和大厅入口，增加损坏恢复与后台/强杀测试。
5. 验证通过后选择素材/声音、完善触感与动效，形成 Android 独立验证包（建议包名后缀 `.snaketest`），再按项目流程集成。

| 验收场景 | 必须看到的结果 |
| --- | --- |
| wrap 四方向 | 同一行/列从对边进入，不跨屏插值；不忽略落点碰撞 |
| solid 四方向 | 越界失败，仍为 480 格容量；不会把外框误作占格墙 |
| 快速右→上→左 | 连续两个 tick 转向，每 tick 最多一次，不能同 tick 反向 |
| 非增长进尾格 / 增长撞尾格 | 前者合法、后者失败 |
| 最后一个食物 | 增长到满盘后立即胜利，不调用随机、不多走一步 |
| 障碍满盘 | 分母为 480 减去障碍数量，无重复扣格 |
| 满盘与目标同 tick | 只结算一次，展示满盘成功 |
| 经典各边界/难度 | 六组纪录/续局互不覆盖，进行局不能改规则 |
| 经典四边相通开关 | 新局配置生效；已有对局先暂停、确认后按目标边界新开局，取消保留原局与原边界 |
| 障碍四边相通状态 | 底部左侧同位只读显示本关开/关，点击不改变关卡边界 |
| 选关 | 正确显示目标、地图、速度、边界和解锁状态 |
| 经典与障碍独立 UI 示例 | 均有统一 home/品牌/书本/设置导航，标题下一行左对齐，底部左操作、右方向十字键，无底部常驻玩法提示 |
| 聊天与系统明暗主题 | APP 示例始终保持纸色 `#F6F4EC` 与墨绿 `#173D35`，控件颜色不随外层主题切换 |
| 短屏/长屏/刘海/全面屏 | 整盘可见，按钮不遮盘，触控目标与视觉一致 |
| 暂停/失焦/后台/设置 | 停止 tick，清空输入；恢复先倒计时，不补跑 |
| 卡顿 | 自动暂停，无积压连续死亡，无重复提交动作 |
| 存档缺失/损坏/null/类型错 | 严格拒绝无效局，备份恢复和用户提示符合约定 |
| 满盘结算后强杀并恢复 | 不重复记胜场、分数或解锁 |
| 其他七款游戏 | 大厅、设置和原存档回归通过 |

本轮没有 Unity 编译、APK 安装或 Android 触摸验证；网页示意和静态配置检查不能替代这些验收。交付前的实际检查结果记录在 [本轮验证](../../snake/verification-design.md)。
