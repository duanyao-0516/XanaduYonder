# 旸了个旸

显示名称为「旸了个旸」，稳定游戏标识为 `sheep`。这是合集内的离线叠牌三消游戏：点击没有被盖住的牌，将其放入 7 格卡槽，集齐三个相同图案自动消除。

## 玩法

1. 第一关有 18 张牌、3 种图案，每种 6 张，用于熟悉取牌和消除。
2. 第一关清空后进入第二关：144 张牌、16 种图案，每种 9 张。棋盘包含多层主区域、浅层保留牌以及左右两个盲堆；盲堆只显示顶牌图案和剩余数量。
3. 只要一张牌的卡面与更高层尚存的牌重叠，就不能选择；移走上方牌会立即解锁下方牌。仅边缘接触不构成遮挡。
4. 相同图案自动在卡槽中排在一起。每次取牌先结算三消，再判断是否满 7 张失败；第七张若能组成三张消除，就能继续。
5. 棋盘、卡槽和移出区全部清空才算过关。第二关成功后累计通关增加一次；返回大厅或恢复这个终局不会重复增加。

“重开本关”保留当前关卡编号，重新生成棋盘并恢复本关工具次数，累计通关不变。第二关成功后的“再闯一轮”回到第一关。

| 工具 | 效果与限制 |
| --- | --- |
| 移出 | 每关一次，将卡槽前三张移到移出区；不足三张时移出全部。移出的牌没有被消除，可逐张点回卡槽。 |
| 撤回 | 每关一次，将最近一次、仍未被消除的取牌放回准确来源位置；若来源为移出区，也恢复原来的顺序。最近一手已经三消时不可撤回。 |
| 洗牌 | 每关一次，只打乱棋盘上剩余图案，保留每种图案数量、卡槽、移出区和布局。至少有两张棋盘牌且尚未失败时可用。 |
| 免费复活 | 满槽失败后每关一次，将卡槽前三张移到移出区，和移出工具分开计次。 |

移出区最多容纳 6 张。满槽后，尚未用完且满足条件的移出或撤回同样可以解困。使用工具后清除上一手撤回记录。无效取牌或无效工具操作不改变对局，也不消耗随机状态。

所有工具均免费，无广告、分享门槛、登录、排行榜或联网请求。

## 规则参考与本项目的适配

- [2022 年现场报道](https://finance.sina.cn/2022-09-24/detail-imqmmtha8537675.d.html)记载经典玩法的 7 格槽、同图案三消、教学关到复杂叠层关的结构。
- [2022 年官方攻略转述](https://finance.sina.cn/2022-09-15/detail-imqqsmrn9110556.d.html)介绍移出前三张、撤回、洗牌及复活机会。
- [开发商发布的通用攻略](https://game.xiaomi.com/viewpoint/1647049200_1745293797306_13)介绍主攻深层区、浅层保留区、盲堆和复活的作用。该页面位于较新产品社区，本项目只参考通用消除规则，不引入星球功能。

具体牌数、三个布局变体、道具免费、移出区六张全部可见、最近一手已三消时不能撤回，以及使用工具清除撤回记录，是本项目明确采用的离线规则。不声称这些未公开的实现边界与原版完全相同，也没有复制第三方游戏源码。

## 可解生成

`SheepLevelGenerator` 首先生成符合实际遮挡关系的取牌顺序，再沿此顺序分配交错的三张图案组。路径上最多同时存在三个未完成的图案组，三消结算后卡槽最多占六格，构造出一条可以通关的取牌路径。相同关卡和种子生成相同布局、牌面与路径；新开局使用新的非零种子。

生成器返回棋盘和解法，测试使用实际 `SheepGame.Pick` 逐步重放，验证遮挡、卡槽和最终清空状态。运行时不再执行通用搜索求解。初始局有解不表示玩家任意取牌顺序都能成功；洗牌保留剩余图案的数量，**不保证任意局面洗牌后都有解**。

## 模块与生命周期

- `Core/Sheep` 不依赖 Unity，拥有位置状态、遮挡、三消、胜负、工具和确定性随机状态。`SheepGame` 的导入/导出使用快照深拷贝。
- `SheepPage` 管理关卡、独立存档、计数、工具按钮、帮助和结果。合法操作立即提交规则和保存，动画只表现已提交结果；快速下一次取牌会结束上一段表现，按新状态继续。
- `SheepBoardView` 使用独立牌底与图案渲染棋盘、卡槽、移出区和短动画，不负责判断能否三消或获胜。
- `AppController` 管理入口、设置和共用声音/触感。离页、设置模态层、应用暂停或失焦会结束动画并重绘已提交的状态；各游戏的对局相互独立。

## 独立存档

文件位于 `Application.persistentDataPath/sheep-v1.json`，带 `.bak` 和 `.tmp`，不读取或改写 2048、跳一跳的文件。

| 范围 | 字段及约束 |
| --- | --- |
| 根对象 | 固定字段 `schemaVersion=1`、`gameId="sheep"`、`game`、`completedRuns`、`winRecorded`。 |
| 累计通关 | `completedRuns` 为非负 64 位十进制字符串；达到 `long.MaxValue` 后饱和。`winRecorded` 为布尔值，仅在已清空的第二关为 true，且累计值至少为 1。 |
| 几何 | `level` 为 1 或 2，`layoutId` 为 0、1 或 2；坐标根据二者派生，不从磁盘接受任意几何。 |
| 图案与位置 | `kinds` 与 `locations` 长度分别为 18 或 144；第一关图案 0..2 各 6 张，第二关图案 0..15 各 9 张。位置枚举为 0 棋盘、1 卡槽、2 移出区、3 已消除。 |
| 槽顺序 | `tray` 最多 7 个牌 ID，`reserve` 最多 6 个牌 ID；必须与位置数组一一对应，不能有重复、漏项或越界 ID。已消除的每种图案数量必须为 3 的倍数，卡槽不保留已凑齐的三张。 |
| 随机与工具 | `randomState` 是非零 uint；`removeUsed`、`undoUsed`、`shuffleUsed`、`reviveUsed` 是布尔值，并检查移出区与工具状态一致性。 |
| 撤回来源 | `lastPickedId`、`lastSource`、`lastReserveIndex` 保存最近未消除取牌及原位置；没有记录时三个值均为 -1。 |

读取严格拒绝字段缺失、null、额外字段、重复键、错误 token 类型、未知版本、越界数组或不一致的游戏状态；限制为 128 KiB、JSON 深度 8，并严格检查 UTF-8。胜负由牌位置与卡槽推导，不接受独立的胜负字段。

保存前先校验模型，再写入并 flush 临时文件、原子替换正式文件；只有合法主档能更新备份。读取失败时尝试备份，均不可用则开启新局并提示。写入失败时保留已有文件、提示未保存且允许继续游玩，之后写入成功清除该错误。挑战关通关会先更新计数与 `winRecorded` 再写盘，恢复该终局时不会重复计数。
