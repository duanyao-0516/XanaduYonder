# 弹窗、设置与菜单控件

同一个入口只回答一个问题。合集采用以下三种布局，保留现有纸色、墨绿和游戏原画。按钮标题写清执行的动作。用户有可能丢失当前进度时，确认前说明受影响的数据并提供取消入口。[Apple HIG 的提醒设计](https://developer.apple.com/design/human-interface-guidelines/alerts)

| 玩家需求 | 布局与返回 |
| --- | --- |
| 确认重开、退出，或者处理一次错误 | 居中对话框，突出一个主要动作。取消或继续当前对局放在旁边。标题已说清的确认只显示标题和动作。需要说明后果时，卡片随正文增高；长说明可滚动，操作区保持可见。 |
| 选择展示方式或修改偏好 | 每个设置入口只打开一张贴底面板。设置在原位生效；仅用于完成一次选择的独立选择器可以选完即关闭。 |
| 调整多类设置、查看长说明或资料 | 用不可点击的标题区分任务，所有设置和说明都在同一面板的一条纵向滚动区域中。需确认的操作在原行显示确认与取消。草稿模式提供一次保存和取消。独立资料由玩法自己的入口打开。 |

例如，大厅的声音和触感都能点一下即时生效，适合放在底部面板。设备触感和系统音量说明紧跟在设置项之后，读完可直接点「完成」。[Material 底部面板](https://developer.android.com/develop/ui/compose/components/bottom-sheets)

阻断操作的确认框、设置与底部面板使用中性黑蒙层，标准色为 `rgba(0, 0, 0, 0.40)`。蒙层铺满所属画布，同一时刻只显示一层。全屏说明页使用实色背景。黄金矿工的位置教学用 16% 不透明度，便于看清提示所指的真实矿物。

每个弹窗都能点蒙层关闭。设置一次回到打开它的游戏或大厅，确认框走取消，结算回看原局或返回可重新打开结算的页面。存档或加载错误保留原始数据及重试入口。iOS 网页宿主收起错误详情后保留「查看错误详情」入口。按下和抬起都要命中蒙层才关闭。从正文、开关或滚动区拖到蒙层时保留面板。

## 关闭、触摸与键盘焦点

大厅设置的更改即时生效。点蒙层、点「完成」或按系统返回，面板在 200 毫秒内向下移出，蒙层同步淡出。展示方式和各玩法设置沿用这个退场动作。动画播放期间，蒙层继续拦截输入；连续点按只能完成一次关闭。点面板内标题或留白会留在当前页。

触屏按钮只在按下时给反馈，松手恢复原底色。开关靠滑块位置和轨道颜色显示当前值，互斥选项保留选中标记。键盘和手柄在操作时显示焦点，保证用户看得到下一次确认会执行哪个动作。

大厅退出使用「退出应用？」与「取消」「退出」。点蒙层或按系统返回等同于取消。正文为空时，标题下直接排操作行。需要说明进度损失的重开操作继续描述实际后果。[退出确认截图](screenshots/dialogs/lobby-exit-android.png)

军棋、象棋、国际象棋、跳棋使用同一套分组。打开即可调整「落子与显示」，下滑依次看到「声音与触感」「对局管理」「继续其他对局」和「本局棋谱」。分组标题没有箭头，也没有点击动作。点一次蒙层即可回到棋盘。[国际象棋设置首屏](screenshots/dialogs/chess-settings-android.png) · [同一面板滚动后的棋谱](screenshots/dialogs/chess-settings-record-android.png)

## 圆角与屏幕边缘

| 元素 | Unity 720 宽设计坐标中的半径 | 网页菜单的半径 |
| --- | --- | --- |
| 贴底面板 | 上方两角 40，下方两角 0 | 上方两角 20 CSS px，下方两角 0 |
| 居中对话框 | 四角 32 | 四角 16 CSS px |
| 设置项、菜单按钮 | 四角 16 | 四角 8 CSS px |
| 开关轨道 | 高度的一半，滑块为正圆 | 胶囊形，滑块为正圆 |

以手机 360 逻辑宽为基准，贴底面板、居中框和普通控件的圆角半径分别为 20、16、8。Unity 数值随画布缩放，使用局部坐标的组件应换算到同一设计比例。面板底色从所属画布的左边缘铺到右边缘，并延伸到底边。两个下角顺着设备外轮廓收口。标题、选项和底部按钮放在独立的安全内容区。系统手势区或导航栏占用的高度只计一次，沉浸模式仍为底部留出间距。横屏时按可用安全区居中内容，避开侧边挖孔。[共用圆角](../Assets/Scripts/Runtime/Navigation/DialogCorners.cs) · [底部面板布局](../Assets/Scripts/Runtime/Navigation/DialogSheetLayout.cs)

## 字号与间距

以 360 逻辑单位的屏幕短边换算，Unity 弹窗标题上限为 15，正文和操作文字为 13，补充说明为 12。分组标题使用加粗正文，与面板标题按字重和上下间距区分。标题与面板边缘至少留 20，宽段正文两侧至少留 16。常规行按 720 宽画布设置，行间距 12，分组标题前再留一份间距。原作使用其他画布尺寸时按比例换算。文字缩小后保留独立触区，长标签折行，长面板可以纵向滚到末项。[字号换算](../Assets/Scripts/Runtime/Navigation/DialogTypography.cs) · [分组排版](../Assets/Scripts/Runtime/Navigation/DialogSheetSections.cs)

小米 17（1220 × 2656，520 dpi）竖屏实测，以文字着墨像素高度为准。「对局设置」从 80 px 调整为国际象棋 46 px、军棋 47 px；两款的「单击落子」均为 34 px。分组与标题的首个文字像素距左边缘约 70 px。

## 控件约定

真机验收分别观察面板两侧的内容留白、短标签与开关的距离，以及末项和底部手势区的间距。[大厅设置截图](screenshots/dialogs/lobby-settings.png) · [战斗画面上的暂停确认](screenshots/dialogs/web-resume.png)

- **开关**用于开或关的布尔设置。共用声音、触感并排放在两个等宽格子中，格内的短标签与轨道作为一组居中，标签排版框与轨道之间最多留一个汉字宽度。点标签、轨道或格子留白都只切换本项。长标签和独立偏好使用整行开关。圆点位置和轨道颜色共同表示状态。应用设置沿用原有读写、写入失败处理和禁用条件。[Material 开关](https://developer.android.com/develop/ui/compose/components/switch)
- **互斥选项**用于方向布局、模式或主题。一组选项只有一个选中值。主题和带预览的选项在当前分组中换行排列。
- **分组标题**使用静态文字。普通操作采用浅色按钮，继续或确认等主要操作采用实色按钮。重开进行中的 2048 会说明清空当前棋盘的后果并显示独立的确认色。
- **输入边界**由玩法拥有。棋盘落子、射击、拍翼、方向盘、摇杆、按住蓄力、拖动物件和左右手热区继续由原来的输入组件处理。

## 维护入口

Unity 菜单使用 [DialogUi](../Assets/Scripts/Runtime/Navigation/DialogUi.cs)、[开关](../Assets/Scripts/Runtime/Navigation/DialogSwitch.cs)和[互斥选项](../Assets/Scripts/Runtime/Navigation/DialogChoices.cs)。[弹窗焦点管理](../Assets/Scripts/Runtime/Navigation/DialogFocusScope.cs)负责拦截底层按钮的键盘与手柄输入。[宿主弹窗](../Assets/Scripts/Runtime/App/AppController.Dialogs.cs)负责共用设置、提示、遮罩与返回。游戏内暂停、回看、重试和待保存的草稿由各玩法持有。网页管理界面使用[共用弹窗样式](../ThirdParty/WebGameUI/dialogs.css)，沿用原有 WebView 或 WKWebView 的暂停和存档协议。

| 入口 | 检查的实际操作 |
| --- | --- |
| 大厅、2048、多个玩法共用的声音与触感 | 分别点击声音、触感的文字和轨道，确认另一项保持原值。在同一面板读到说明末段，分别验证完成、系统返回和蒙层。2048 写盘失败的处理与重试走原宿主路径。 |
| 军棋、象棋、国际象棋、跳棋 | 打开设置后滚动到落子与显示、声音与触感和对局管理，并验证同一面板持续存在。棋谱、复盘、教程和存档异常仍可从相应入口到达。 |
| 旸了个旸、成语接龙、飞花令、抓大鹅 | 验证同一设置面板的草稿、保存与取消。草稿和诗词输入法由各自页面管理。抓大鹅的数量显示、主题与共用声音均在同一面板内直接调整。 |
| 数独、扫雷、五子棋、推箱子、数字华容道、连连看 | 验证规则、难度和重开确认，分别检查继续游戏、保存失败与查看最终棋盘等本款提供的动作。 |
| 贪吃蛇、俄罗斯方块、飞机大战、Flappy Bird、欢乐球球、合成大西瓜、跳一跳 | 检查暂停与继续、结算与回看，以及从规则返回。方向盘、旋转换边、投放和跳跃通过原输入路径验收。 |
| 黄金矿工、Dino、Zuma | 横屏管理面板、帮助及声音设置单独验收，恢复时回到原暂停层。 |
| Q 版泡泡堂、只有一道门、赵云与阿斗、割绳子 | 验证第一方宿主提供的设置、错误与退出界面。原引擎画布、随包美术及输入语义由原作负责。 |

每次改动交付前运行 `python3 scripts/check-dialog-styles.py`。这个入口在新的目录执行 Unity 后台套件及四款网页游戏的浏览器检查，生成逐游戏、逐窗口、逐分辨率的截图。四款棋分别在两种屏幕尺寸滚动到显示、反馈、管理、存档、棋谱五个位置，保留实际可见控件的截图。打开 Unity 输出中的 `index.html` 逐页核对，检查清单中的缺图、异常布局和关闭后的状态。新建弹窗时，把能实际打开它的场景和验收项一起加入对应玩法检查。

网页验收使用已准备好的离线资源、Chromium 和 Node 的 Playwright 模块。iOS 原生错误弹窗通过 `--simulator <已启动的模拟器 UDID>` 加入同一轮，覆盖四款网页游戏的加载和保存分支。Android 原生错误弹窗通过 `--android-serial <独立模拟器序列号> --apk <正式包路径>` 加入，在错误发生后检查真实的系统弹窗、卡片外触点和返回路径。

Android 真机覆盖安装后检查大厅、四款棋、退出确认和退场动画，记录机型、方向、导航模式及本轮实际触点。平台资源和封装另由 `python3 scripts/test.py --group platform` 校验。

真机验收时，从大厅分别打开设置和展示方式，在圆角屏上观察两侧、两个下角及手势条附近的交界。底色应连续覆盖两侧和底边，标题、轨道、按钮文字和点击范围应完整可用。点底部按钮的边缘，再分别检查手势导航、三键导航及支持的横屏入口。直接观察屏幕的物理圆角，保存全屏截图，并记录机型、方向与导航模式。
